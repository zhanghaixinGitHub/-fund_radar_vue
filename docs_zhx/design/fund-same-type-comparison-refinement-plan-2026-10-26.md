后端筛选、比较端点计算和接口已按本方案实施；基金目录、采集任务、历史评级与预测保持原范围。现有宽泛样本不会自动被认定为通过细分核验，必须满足资料门槛。

## 3. 本次页面调整

“混合型”使用本次比较响应的 `fundType`，复用项目已有中文类型映射，不根据基金名称猜测。切换基金后说明随响应更新，不能把混合型写死。

- 已知大类：显示实际中文类别和“按基金大类划分”。

- 比较范围不是当前已识别范围：显示“本次同类：比较范围暂不可用”，不猜测新的分组含义。
- 加载或请求失败：继续使用原来的加载、错误说明，不显示上一只基金的分类。
- 基金不在范围内或净值不足：保留实际类别说明，同时明确当前不能比较，不伪装成有可比结果。

旧版响应下方简述“仅比较已收录且截至同一天的基金，按近一月单位净值变化从高到低排列，不含分红和买卖费用”。不把旧响应没有表达的细分条件写进其说明。

当前细分接口由后端返回真实的分组名称和一句简述，例如：

上述仅为版式示例，不代表当前 002112 或任何现有样本已经属于该组。名称应覆盖会影响本组准入的主要条件；较长条件可在紧邻的一句业务说明中补充，不做新的参数选择器。

继续保留统一的统计截止日、必要的实际区间说明、样本数量和单位净值变化口径。用户不需要选择分类算法或自行调整分组参数。

## 4. 推荐的细分规则

### 4.1 分组依据与规则顺序

先保留合同中的正式基金类别，再根据投资市场、主动或被动管理方式、资产配置约束和明确投资主题细分。分组规则与必要阈值必须在计算比较结果前固定，不按哪种分组会让目标基金表现更好来调整。

分类依据优先采用有效基金合同、更新后的招募说明书和明确的官方变更公告。已授权数据源的分类字段需要核对其定义和版本；定期报告中的多期持仓用于辅助确认实际投资特征及发现偏离。

参考[证监会《证券投资基金评价业务管理暂行办法》](https://www.csrc.gov.cn/csrc/c106256/c1653866/content.shtml)第十一、十二条所列的投资方向、投资范围、投资方法、业绩比较基准及风险收益特征。本方案下述细分是拟议的应用分组方法，不冒称官方统一细分类别或官方评级。

不得仅根据名称中的“成长”“价值”“灵活配置”等词、单季前十大持仓、最近涨跌相关性或现有评级总分确认同类。资料没有说明是否存在主题限制时，应记为未知，不能默认成全市场投资。

### 4.2 各类基金的比较条件

| 对象 | 建议必须核实的条件 | 不直接混入同一细分组的情况 |
| --- | --- | --- |
| 主动股票基金 | 正式类别相同；主要投资市场、合同股票配置约束、全市场或明确行业主题相符 | 行业主题不同，或主要投资市场明显不同 |
| 混合基金 | 正式类别相同；有依据的偏股、平衡、偏债或灵活配置细类；合同股票配置区间、投资市场和主题条件相符 | 只因都叫混合型，就把明显不同的股债配置或行业主题放一起 |
| 普通指数基金 | 跟踪指数身份一致、投资市场和汇率处理可比 | 仅因指数名称近似或都属于股票指数而混合 |
| 指数增强基金 | 跟踪同一指数、增强策略类别可比 | 与普通被动跟踪产品混合 |
| 债券基金 | 有依据的纯债、含权益或可转债细类，以及期限、信用风险约束相符 | 短债与风险结构不同的可转债产品混合 |
| 境外投资基金 | 在各自正式类别内，再核实目标市场、资产类别、计价币种和汇率对冲方式 | 仅因都属于 QDII 就把不同国家、股票、债券或商品放一起 |
| 货币、基金中基金等其他类别 | 使用适合该类别的专门分类和比较指标 | 为了复用单位净值涨跌列表而套用股票、混合基金规则 |

首期优先选择已有可靠资料覆盖的类别。货币基金等不适合当前单位净值变化指标的类别，必须保留“当前指标不适用”的边界，不机械开启细分比较。

仓位、期限、信用风险等分档不临时编造通用数值。本轮采用原文明确的资产配置区间、主题限制和参照标的，不新增未经验证的数值分档；缺少可核实依据时，该细类保持未就绪。不能把分类不明的一批基金放在“未知”组后，当成一组严格同类。

### 4.3 002112 的处理

已核实该基金归档招募说明书与概要中的类别、股票配置范围、可投资市场、投资主题约束和业绩比较基准。本轮按境内灵活配置混合、股票范围 0%—95%、无固定行业最低配比、人民币和同 C 类份额分组。多期持仓只能补充当前投资特征，不把单期高股票仓位直接改写成永久偏股类别。

## 5. 资料、产品和日期边界

### 5.1 复用现有证据，先核实覆盖

- `FundProfile` 已有业绩基准、原始投资类型、原始基金类别等资料字段，但字段存在不等于值完整、定义清楚或已核验。
- `fund_rating_classification` 已具备产品标识、类别、币种、有效起止日、来源引用、核验时间和撤回标记，可作为复用候选。只有证据、有效期和字段语义都满足本比较规则时才能使用；有评级记录不自动证明所有细分条件齐备，没有评级总分也不应单独阻断已经核实的分类。
- `fund_master_id`、基金名称相似或代码相近不能单独证明两个份额属于同一产品。产品关系需要来源资料佐证。
- 上市交易市场、代码后缀等字段不能直接代替底层资产的投资市场。
- 本次已按当前 49 个启用份额逐项审计，37 个分类就绪，12 个保留明确缺口；不能由代码中的表结构推定数据齐全。

分类记录应能追溯到来源文件、关键依据、适用日期和规则版本。规则变更或资料更正保存新版本；不得覆盖旧比较使用过的分类事实。分类有效期未覆盖整个比较窗口时，严格比较应排除该样本并记录原因。

### 5.2 A/C 等份额去重

以经证实的独立产品为单位形成比较样本。同一产品只占一个位置：

1. 目标产品保留用户正在查看的实际份额，其他同产品份额不再作为竞争样本。
2. 其他产品优先选与目标同份额类别且满足资料要求的份额；若仍有多个，按预先固定的代码顺序选择，不按收益挑选。
3. 首期没有可比份额或产品归属无法核实时，不自动拿另一收费类别替代，也不假定为新的独立产品；保留缺口。后续如需放宽，另行定义费用差异说明和代表份额规则。
4. 净值始终使用所展示份额自身的连续记录，不拼接 A/C 历史，不取各份额的最好收益。

去重后样本可能少于当前份额数，这是预期结果。后端明确区分列表行数、份额数与独立产品数，前端不能仅替换“只基金”的文字就把旧数量宣称为产品数量。

### 5.3 比较日期与指标

实施前不同基金可能回退到不同基准日。当前细分比较已要求共同起点和共同终点：

- 以目标基金截止日为终点，以其核实过的近一月基准日为共同起点，候选必须具有同一天的两端净值。
- 基准日回退需符合适用披露日历；缺数或日历无法确认时，不把更早的任意记录称为相同一月区间。
- 各基金两端必须同来源、正数、有限；币种和汇率处理须满足同组口径。
- 页面仍显示单位净值变化，不把累计净值端点比值、未经核实的复权字段或其他份额收益替代成总回报。
- 如未来采用含分红的总回报，另行定义计算、来源和验证规则，不在本次顺带切换。

区间收紧已实施，页面显示真实的共同起止日。境内沪深资产复用已核实日历；没有其他市场完整日历时，只接受精确 30 天的原值端点，不猜测回退日期。缺数不会被伪装为休市。

## 6. 接口与存储实现

### 6.1 继续沿用现有读取链路

浏览器仍通过 Java 的 `GET /api/v1/funds/{fundCode}/same-type-comparison` 读取，Java 保留 `FUND_READ` 授权，再访问 Python 内部服务。前端不传自定义同类名单，也不承担最终分类和产品去重。

本轮三端契约已补充以下信息：

| 拟议信息 | 用途 |
| --- | --- |
| `comparisonGroup`：业务名称、简述、宽分类或已核实细分类别 | 前端准确说明本次同类；不能从基金名称拼出细类 |
| `comparisonStartDate` 与原 `asOfDate` | 说明真正使用的共同统计区间 |
| `sampleUnit` 与可核实的独立产品数量 | 区分份额对照和产品去重后的比较 |
| 分类不足、资料冲突或无其他可比产品的业务原因 | 前端显示简短中文，避免误报成功或空白页 |

保留既有 `fundType`、`scope`、日期、状态和列表字段的兼容语义。`comparableCount` 始终对应返回行数；只有经核实去重后才能附带产品数量和相应单位。新旧模式必须有明确区分，不悄悄切换同一说明下的样本含义。

分类规则版本、来源证据、每项排除原因及输入摘要保存在后端可追溯记录中，日常页面不展示技术代码或证据处理流程。当前接口中已有的位置字段不新增前端展示，不据此增加全市场名次。

### 6.2 分类事实与计算方式

已复用归档原件及身份依据，采用版本化的 `app/data/fund_peer_classifications_v1.json` 独立保存比较分类及证据引用；只读原件校验和逐份额回算由专用审计命令完成。本次没有新增表、数据库字段或迁移脚本，也没有回写原评级分类。

类别和产品关系批量读取，继续复用批量净值查询，避免按基金逐条查库。请求只读本地已核实资料，打开页面不触发外部抓取、分类重算或同步；本方案不自动增加数据源、成本或定时任务。

## 7. 分类不足和样本不足的显示

| 场景 | 页面处理 |
| --- | --- |
| 兼容旧版大类响应 | 明确显示“按基金大类划分”，不称已核实细类 |
| 严格细分类别缺资料或有冲突 | 显示“分类资料不足，暂无法进行细分同类比较” |
| 类别已核实，但只有目标基金满足条件 | 可保留目标数据，同时显示“暂无其他可比基金”；不呈现领先名次 |
| 有候选，但共同日期或数据口径不足 | 说明“同一统计区间的数据不足”，不补零或换用其他区间 |
| 细分样本少 | 显示真实数量；不自动退回更宽类别凑数 |

如果未来提供宽分类参考，必须与严格细分对照明确区分，用户可以知道当前采用哪一种；首期严格比较不做静默放宽。当前数据读取失败与分类资料不足仍是不同状态。

验收重点：

1. 混合型、股票型、指数型等页面显示各自真实大类；未知、缺失分类和未知比较范围不会被伪装为已核实类别。

3. 同正式类别但投资约束明显不同的基金按固定规则排除；同主题文字不等于已核实同类。
4. 同一产品 A/C 不重复；用户查看的实际份额保留，不能因为收益较差就换成其他份额。
5. 所有返回产品满足实际共同起止日、来源和币种等条件；缺失或无效数据保持未知。
6. 分类和产品关系证据过期、被撤回或在窗口中变更时，不继续沿用旧结论，也不覆盖旧快照。
7. 排列仍为变化幅度降序，同值时按代码升序；去重数量与返回列表、页面单位相符。
8. 页面保持基金名称及代码、变化幅度、清楚的同类范围、统计日期和必要口径说明；不新增技术选择或运行状态卡片。
