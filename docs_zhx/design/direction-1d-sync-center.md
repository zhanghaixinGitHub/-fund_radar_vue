## 调用与权限

- 浏览器经 Java `POST /api/v1/sync-jobs/direction-1d-predictions` 创建预测任务，`GET /api/v1/sync-jobs/direction-1d-predictions/latest` 恢复状态，分别需要 `SYNC_JOB_START`、`SYNC_JOB_READ`。
- Java 转发 Python 同路径的 `/internal/v1/funds/sync-jobs/...`，复用同步队列和内部服务令牌。
- Python 经 Java `/internal/v1/direction-1d/sync/window` 冻结目标日，`/fund-codes?after=...` 分页取得去重关注代码，再 POST `/{code}`。Java 回调要求服务令牌并拒绝浏览器来源；请求不能指定用户或模型阈值。
- 关注范围和个人关系均由 Java 决定，Python 不读个人账本数据库，也不接收账号与持仓金额。Java 复用一日预测生成、原文校验、归档和个人关联链路。
- 单只基金每个目标日复用公共留档；不同账号关注同一基金只计一只。目标日中途变化时停止该基金本期生成并给出原因，不跨期混算。

## 串行次序和状态

一键同步全部：标普500 → 基金资料与市场数据更新 → 净值增量 → 历史指标计算 → 全部关注基金预测 → 模拟费率。任一阶段失败会继续处理其余阶段，并保留批次部分完成状态。

预测任务类型为 `DIRECTION_1D_PREDICTIONS`，共用任务响应：`fetchedCount` 是检查基金数，`createdCount` 是新生成数，`updatedCount` 是本期已有数，`skippedCount` 是未生成数；页面使用对应中文标签，不显示成更新净值条数。`requestedNavDate` 在结束时为实际冻结的预测目标日，执行中进度文字也标明目标日。

全部已生成（含本期已有）为 `SUCCEEDED`；部分未生成是 `PARTIAL_SUCCESS`；全部未生成是 `FAILED`，页面说明业务原因。空关注范围正常结束，检查数为0。缺数据、类型不支持、超出时间窗口都不能展示成“全部预测成功”。保存结果不确定时不自动重发 POST，重试仍通过原有留档去重。

同步任务状态沿用当前进程内队列，Python 重启后最近任务可为空；预测原文和个人历史仍持久化保留。运行自动预测不会伪装成某次管理员手动同步记录。
