# 关注与站内提醒设置

## 行为约定

- 关注一只基金时，在同一事务内创建 `EVENT` 与 `SIGNAL_CHANGE` 两类默认开启的接收设置；已有关注在 V27 升级时只补缺项。
- 已有规则主键、启停选择、阈值及时间不被默认值覆盖。关闭一类不影响另一类，也不影响关注。取消关注停止接收，再次关注保留之前的选择。
- 规则和消息历史不因取消关注而删除；提醒设置列表只展示本人当前关注的基金。已有风险规则可继续单独启停，默认不创建风险阈值。
- 详情页以两个独立条目解释用途，按钮操作直接保存；失败保持原值，切换基金后的迟到响应不更新新页面。
- 站内提醒的规则列表提供“全部 / 已开启 / 已关闭”接收状态筛选，每页 10 条。切换筛选回到第一页；启停成功后重新读取当前筛选及总数，末页空了回到最后一个有效页。慢请求不能覆盖后选的筛选。
- 规则页只保留页面标题，移除“本人设置”和重复标题、前往关注按钮，以一句“我的关注 → 基金详情 → 我的提醒”说明设置路径。

## 接口与生成边界

原 `GET/PUT /api/v1/alert-rules` 保留响应格式。新增只读 `GET /api/v1/alert-rules/availability`，沿用 `ALERT_RULE_SELF_READ` 权限，返回公告检查是否实际加载、覆盖基金及方向/风险提醒能力。用户接收开关与发送能力分开展示。

新增 `GET /api/v1/alert-rules/page`，沿用本人提醒读取权限：可选 `enabled=true/false`，省略为全部；`page` 从 1 开始，`pageSize` 默认 10、范围 1–100。响应为 `{items,page,pageSize,totalCount,totalPages}`；空结果页码 1、总页数 0。服务端按当前用户及仍关注的基金过滤，用同一只读快照查询总数与条目，按更新时间及主键倒序分页；越界页回到末页。前后端需一起更新，新接口由 Java 重启加载。

当前公告检查仅覆盖 002112；走势与风险自动提醒仍未接通，本次不声称已可发送。界面如实说明不可用状态，保留接收选择。没有在本次启动自动采集、训练、提醒调度或外部通知。

启用规则要求本人已关注。关闭已有规则不依赖外部基金资料服务。公告检查与写入处于同一事务，对本次使用的关注和规则加共享锁；关闭/取消关注操作完成后不再按旧状态产生新消息。

## 数据库升级

Java `V27__default_watchlist_alert_rules.sql` 在关注插入或归属变更时补齐两类订阅，同时回填旧关注。`ON CONFLICT DO NOTHING` 保留手动选择，默认创建写审计，业务失败回滚时订阅和审计一起回滚。发布应先加载 Java 与 V27，再使用新的前端设置页；读取缺项时前端不会伪装成已开启。

本次交付未应用业务库迁移或重启共享服务，避免影响同时进行的预测解释工作。Java 下一次正常启动将执行 V27；消息生成能力仍按真实可用状态展示。
