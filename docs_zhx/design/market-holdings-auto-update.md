## 调度与执行边界

Codex 在合并后的主任务聊天定时唤醒。正常先执行纯资料一键同步，其中持仓阶段调用共享检查入口，不再另跑一次独立命令。综合服务不可用且本轮未执行持仓入口时，才可调用下述独立命令完成持仓部分。基金雷达的 Vue、Java、FastAPI 生命周期不注册持仓定时器。执行仍需本机、Codex、原有数据库与公开来源可用；数据库不可达时报告失败，不把未检查写成成功。

工作目录为 `C:\pythonProject\workSpace06`，使用本项目 `.venv\Scripts\python.exe`：

```powershell
$env:PYTHONIOENCODING='utf-8'
.venv\Scripts\python.exe -m app.commands.check_market_holdings --output .local-runs/market-holdings-auto/latest-result.json
```

默认不传 `--force`。北京时间 1—3 月、4 月、7—8 月、10 月按保守披露窗口每天检查；其他月份以周一为周界每周检查一次。错过周一可以在本周后续唤醒补查；同一天/周已完成检查时命令返回 `NOT_DUE`。`--force` 仅供明确的现场验证、失败重试使用，不用于日常绕过去重。

一键同步同样遵守此周期。未到检查周期时，只有本周期已结束、日期有效的逐基金回执可以复用；保留原检查时间和失败状态，未覆盖的新增基金继续待补。不能把运行中或失败结果当作成功，也不把沿用资料称为本次重新下载。持仓未到期不影响其他资料更新和准入检查继续。

## 范围、来源与历史

每轮从现有数据库读取 `TUSHARE_PRO_FUND` 的全部有效市场份额，不使用关注列表或固定代码清单。目录完整翻页并核对基金身份、公告编号和日期。完成既有报告身份基线后，按公告身份及目录元数据指纹识别新报告/修订；相同目录版本已收录时不下载正文。旧报告期的新更正版仍按新公告收录。来源未给出修订信号的原地正文变化不能仅靠目录检查发现。

原文按内容摘要归档，报告、基金断点、运行回执均持久化。解析失败复用已经校验的正文；空正文保留失败回执并允许下次重试。HTTP 限速、请求上限与连续失败熔断保护来源；异常不删除已存数据。市场目录异常或达到运行保护上限时明确失败，不能缩成关注列表后声称全量成功。

所有页面持仓发布入口合并已有报告。同报告期的季报与中报/年报、更正前后的不同原件分别保留；解析扩展保留旧快照版本。同一原件解析覆盖变窄时不降低已有覆盖，内容不变时不重新发布。季报只列本期披露的部分持仓；6/12 月公开补充表可能已包含后发中报/年报全仓，必须限制在原季报明确列出的证券内。联接基金直接持有的目标基金单列，不当作穿透证券。未知或未核齐的部分保留缺口，不冒充零值或完整持仓。

## 留存与验收

`data/fund-materials/market-maintenance/state.json` 保存检查日与最近状态，`funds/` 保存每只基金的公告断点，`sources/` 保存原文，`runs/` 保存逐轮回执。网页持仓仍从 `data/fund-materials/<基金代码>.json` 读取。与原有手工资料维护共用数据库业务锁，冲突时不推进检查日。

验收以实际运行结果为准：动态市场覆盖、重复检查正文下载数为零、解析失败能继续其他基金、修订后保留旧报告、维护前已有报告 ID 全部仍在。运行成功、部分成功和未到检查日分别记录，不能用进程退出码替代业务结果。仅在收录变化、失败状态变化或需要用户处理时通知；未变化的成功检查保持安静。

本任务只更新披露持仓，不启动网页服务、不改变评级/预测准入、不训练或执行交易。
