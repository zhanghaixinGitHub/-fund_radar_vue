# 我的持仓：模拟买入、定投与卖出设计与实现

> 日期：2026-09-10
> 状态：已实现本地版本；下方“实现与验收”记录具体落点和验证边界。
> 目标：使用真实基金净值和模拟交易金额，记录买入、加仓、定投、卖出及盈亏。所有金额均属于模拟记录。

## 1. 产品决策

把“我的持仓”升级为可持续记账的模拟持仓模块。用户填写投入金额，系统按照明确的模拟交易规则计算份额，再随真实净值更新市值和收益。

推荐默认方案：

- 首次买入以“我的关注”为主要入口；基金详情、持仓页的“添加基金”也可以进入同一个买入窗口。
- 已持有基金主要从持仓列表或持仓详情加仓、卖出、设置定投。
- 无持仓时也能设置定投，第一笔定投确认后自动建立持仓。
- 所有入口共用一个买入流程；首次买入与加仓共用一套后台账务。
- 第一版每人一个模拟组合，人民币计价。每笔买入视为一次模拟资金投入，卖出款和现金分红视为转出到组合外，分别记入流水；因此无需先充值或设置钱包余额。
- 如果以后需要模拟“剩余现金够不够买”，再增加现金账户，并独立定义充值、提现、可用和冻结余额。
- 收益跟随净值涨跌。“自动定投”增加投入，“自动更新收益”反映盈亏，两者分别计算。
- 交易计算使用确定性规则；模型建议不直接生成交易、改变定投金额或修改账本。

本次用户已明确授权实现模拟买入、加仓、定投和卖出，范围扩展到模拟账本。没有接入支付宝、银行卡、支付或真实交易。

## 3. 入口与页面

### 3.1 入口规则

| 位置 | 没有该基金持仓 | 已有该基金持仓 |
| --- | --- | --- |
| 我的关注列表、关注详情 | 模拟买入、设置定投 | 加仓、查看持仓、管理定投 |
| 基金市场详情 | 模拟买入、设置定投 | 加仓、查看持仓 |
| 我的持仓 | 添加基金：从关注选择或搜索基金 | 每行提供加仓、卖出、定投 |
| 我的定投 | 新建计划；无需先手动买一笔 | 查看、修改、暂停、恢复或终止计划 |

无待确认订单且无份额才显示“首次买入”；只有待确认买单时显示“买入确认中”，仍可另行追加，不能把待确认订单当成可卖份额。

买入不自动加入关注，不自动占用关注积分。取消关注不删除持仓、不停止定投、不影响卖出和历史查询。

持仓详情应有独立接口，提供该用户自己的账目与必要净值资料；持仓关系不自动解锁目前受关注权益约束的完整资料和研究内容。

### 3.2 我的持仓页面

顶部固定显示“模拟持仓”，提供“添加基金”。页面内设三个标签：持仓、定投计划、交易记录。

持仓页顶部：

- 持仓市值：已按有效交易日期计入的份额估值。
- 最近收益：标明净值日期；数据齐全且同日时才使用“今日/昨日收益”。
- 持有收益：当前剩余份额的浮动盈亏。
- 累计收益：包含已卖出部分及分红的全部盈亏。
- 待确认买入和卖出进度单独显示，避免把待确认金额与持仓市值重复汇总。

列表展示基金名称及份额类别、持仓市值、份额、成本、持有收益/收益率、最近收益、净值日期、定投状态，以及加仓/卖出/定投操作。手机端使用每只基金一张卡片，保留金额、收益、日期和主要操作。

持仓详情展示当前份额、可卖/冻结份额、剩余成本、已实现收益、分红、该基金交易记录和定投计划。全部卖出后进入“历史持仓”，再次买入可以重新持有，历史记录持续保留。

第一版优先提供金额收益曲线，累计收益率、年化收益率待现金流口径明确后再扩展，不能直接用累计盈亏除以当前剩余成本表示整个投资过程的回报率。

## 4. 模拟交易规则

### 4.1 首期支持范围

优先支持人民币、日频单位净值的普通场外开放式基金，例如符合条件的股票、混合、债券和指数联接基金。按实际产品属性核验，不能只根据名称中是否含有“指数”或“ETF”判断。

货币基金、QDII、场内 ETF/LOF 交易、FOF、封闭期/持有期/定期开放产品等需要独立规则，后续扩展。产品需要的数据和规则不齐全时展示具体原因。

净值价格与公布日期、开放日、暂停申赎及限额资料各有职责。现有净值数据不等于拥有全部交易规则。如果某项规则没有可靠来源，必须标为模拟假设；不能把缺失状态直接解释成该基金在真实渠道可以买卖。

### 4.2 买入及确认

买入窗口提供：基金、买入金额、提交时间、预计净值归属日、费用口径、预计确认条件。提交后展示订单号和交易进度。

建议统一采用以下普通场外基金模拟规则：

- 时区为上海；基金开放日 15:00 前提交，归属当日 T；15:00 及之后、非开放日提交，归属下一开放日。
- 使用 T 日正式单位净值确认；提交时显示的最新历史净值只能作为参考。
- 模拟份额确认最早在 T 的下一开放日，且必须已取得 T 日有效净值。这里的确认时点是产品模拟约定，实际渠道按各基金规则可能不同。
- 净值缺失时保持待确认并重试；不能改用其他日期的净值成交，也不能由估算净值或模型预测确认份额。
- 买入确认后从有效成交净值开始参与后续净值变化，不能享受买入之前已经发生的涨幅。展示系统处理时间与成交/确认归属日期。
- 撤单仅允许在归属交易日截止前、订单尚可撤销时进行；已确认单用更正记录处理，不直接删除。

计算：确认份额 = 净投入金额 ÷ 成交单位净值。费用包含在买入总投入中，剩余成本保留相应费用。

每个基金份额类别单独记账，A 类与 C 类不合并成同一持仓。

### 4.3 卖出

卖出窗口按份额输入，提供 1/4、1/2、全部快捷选择，同时展示估算金额。最终金额依赖成交日净值，不能承诺按当前展示金额成交。

- 可卖份额 = 已达到可卖条件的份额 − 已被待确认卖单冻结的份额。
- 首期模拟规则约定买入确认后可卖，真实渠道的可卖时点可能不同。
- 提交卖单立即冻结选中的可卖份额，净值确认后减少持仓并生成卖出收入记录；可撤销订单取消时释放冻结。
- 冻结不等于已经成交：卖出成交日前仍参与应有的净值变化，成交后不能继续算这部分收益。
- 卖出净收入 = 卖出份额 × 成交净值 − 卖出费用。
- 按先进先出消耗买入批次，计算该笔卖出的成本和已实现盈亏；剩余成本也按同一批次规则扣减。保留每批买入日期，为将来按持有期限计算费用提供基础。
- 本版本卖出确认后记模拟转出收入，不另建银行卡到账流程。

全部卖出窗口默认勾选“同时暂停这只基金的定投”，用户可取消。若仍有待确认买单，明确提示它们可能使持仓再次增加；暂停定投不自动撤销已生成买单，撤单按原规则逐笔处理。

### 4.4 费用及分红

首期缺少完整真实渠道费率时，可采用明确的“未计申赎手续费”模拟口径，不能静默填零后标成与支付宝收益一致。可配置的费率规则须保存版本及来源，在订单中固定当时采用的费用，修改配置不回写历史费用。

后续接入真实申购费时区分价内/价外、固定金额/比例、渠道折扣；赎回费按对应批次及持有期计算，不能给所有基金套同一个费率。净值中已体现的管理、托管等费用不再重复扣减。

现金分红应进入首期收益闭环：按正式权益登记与分红记录确定享有份额、每份红利及金额。除息后计入应收分红，派息时将应收转为已收到的模拟转出收入，仅确认一次收益。必须核对来源 `cashDividend`、`baseUnit` 的单位口径，不能仅凭字段名称假定是“每份”或“每十份”。

首期默认现金分红，红利再投资后续扩展。分红、拆分/折算资料缺失或无法核对时，受影响收益标为待核对，并阻止依赖未知份额状态的结算；不得直接把除息造成的净值下降报告成完整投资损失。成交和市值均使用单位净值，不能用累计净值替代并同时重复计入分红。

## 5. 定投

每个用户每只基金首期允许一个有效计划，填写每期金额、每日/每周/每月、开始日期，以及可选结束日期或期数。每日明确为“每个基金开放日”。创建时明确展示第一期预计执行日期，不额外悄悄买入一次。

推荐统一执行时间为开放日上午 10:00。每周/月计划遇非开放日顺延；每月指定日期不存在时取当月最后一天，再按开放日规则处理。每日计划不累积周末扣款；同一计划多期顺延至同一天时，首期默认最多执行一期，其他期记录合并跳过原因，防止长假后意外累计投入。

计划状态：执行中、已暂停、已结束。支持修改金额/周期、暂停、恢复、终止；修改从下一尚未生成订单的期次生效，已生成订单保留原金额和规则版本。

执行链路：计划到期 → 建立本期执行记录 → 生成普通模拟买单 → 等待对应净值及确认条件 → 更新份额与流水。买单标明来源为手动或定投，并关联计划与期次。

异常处理：

- 同一计划同一期次只生成一笔订单；重复触发、超时重试和服务重启均不重复投入。
- 无有效净值：已有订单保持待确认，不为同一期新建订单。
- 已知暂停申购或模拟限额不满足：记录本期未执行及原因，不无限累积等待恢复后集中买入。
- 服务停机导致当期买单从未在截止前创建：记录为错过执行，恢复后从下一期继续，不使用事后已知的历史净值自动补买。
- 已在截止前持久化的订单只是延迟结算：仍按原交易日期处理，和“漏执行”区分。
- 浏览器关闭不影响后台计划；后台服务停止就不能声称持续执行。

## 6. 收益口径

假设不计申赎手续费，首次买入 1,000 元，成交净值为 1.0000，得到 1,000 份。净值变为 1.0200 时，市值为 1,020 元，持有收益为 20 元。之后再投入 100 元并按该净值确认，市值约为 1,120 元，但收益仍约为 20 元，新增的 100 元是本金。

| 指标 | 口径 |
| --- | --- |
| 持仓市值 | 当前有效份额 × 对应日期的单位净值 |
| 持有收益 | 当前市值 − 剩余份额成本；分红另列并纳入累计收益 |
| 持有收益率 | 持有收益 ÷ 剩余份额成本；成本为零时不显示无穷值 |
| 已实现收益 | 已确认卖出净收入 − 这些份额对应的批次成本 |
| 累计收益 | 持有收益 + 已实现收益 + 已确认分红收益 |
| 累计收益交叉核对 | 当前市值 + 应收分红 + 累计卖出净收入 + 累计已派现金分红 − 累计确认买入总投入 |
| 最近一期收益 | 按有效持仓及成交日期计算本期盈亏变化，排除投入和转出本金，包含本期应计费用与分红 |

“应收分红”与“已派分红”互斥转移，不能同笔重复累加。以上交叉核对适用于本草案的现金分红、无现金钱包及无期初导入模式。

再举一个独立卖出例子：1,000 元按 1 元买入 1,000 份，净值到 1.1 元时卖出 500 份，净收入为 550 元（无费用）。剩余市值 550 元、剩余成本 500 元、持有收益 50 元、已实现收益 50 元、累计收益 100 元。全部卖出后，累计收益不能归零。

每只基金显示实际净值日期。当天净值未公布显示“待更新”；多只基金日期不一致，组合标为“尚未全部更新”，不可把不同日期收益伪装成同一天收益。补齐多天净值时按日期重算，不能把几天变动全部计为今天。

金额与份额采用定点小数计算。委托金额最多两位小数；买入份额保留八位小数并向下取整，卖出所得四舍五入到分，部分成本分摊保留八位小数。全部卖出释放批次全部剩余成本。订单同时保留金额、份额、成交净值，可核对舍入差额；前端“全部卖出”按十进制字符串传递，不使用浮点运算改写委托份额。

## 7. 与已有持仓快照的关系

原有确认快照继续作为独立历史记录，不自动变成模拟买单或参与模拟收益汇总。因为其中保存的展示金额与收益，并不足以还原全部买入批次、份额和成本日期。

后续可增加“补录已有持仓”：至少确认基金份额类别、截至日期、份额与剩余成本；需要按历史持有期计费时还需原始批次日期。可区分“从某日开始记录的模拟期初仓位”和“完整历史交易导入”。前者不伪造开始记录之前的每日收益或累计交易收益。

## 8. 后端与数据设计

### 8.1 分工

- Vue：表单、订单进度、持仓/计划/流水展示；不决定最终成交份额和收益。
- Java：按当前登录用户隔离模拟组合、订单、份额、成本、定投、每日估值及审计；复用现有 Spring/JdbcClient/Flyway 工程方式。
- Python：复用现有基金基础数据、单位净值、现金分红及已核验沪深开市日日历；不接收用户金额或个人持仓。日历是本版模拟约定，不代表拥有逐基金申赎开放状态。

公共基金刷新范围需覆盖关注、仍有份额的持仓、有效定投计划、待结算订单及尚未处理完权益的基金并集。后台负责持续刷新；取消关注后不能让持仓停止更新。是否已具备合适的开放日和交易状态数据源，应在实施时按实际授权核验。

### 8.2 逻辑数据对象

| 对象（建议名称） | 主要职责与关键约束 |
| --- | --- |
| 模拟组合 `sim_portfolio` | 用户归属、币种、模拟规则版本；首期每人一个组合 |
| 模拟订单 `sim_order` | 买/卖、金额或份额、手动/定投来源、提交/成交/确认日期、状态、净值证据、费用、请求幂等键 |
| 账务流水 `sim_ledger_entry` | 份额、成本、收入、分红、冻结/释放及更正的可追溯变动；同一业务事件不重复入账 |
| 买入批次 `sim_position_lot` | 初始/剩余/冻结份额、批次成本、取得日期；卖出时确定消耗顺序 |
| 持仓汇总 `sim_position` | 当前份额、成本和累计指标；按组合及基金份额类别唯一，可由账本重建 |
| 定投计划及期次 `sim_recurring_plan` / `sim_recurring_execution` | 周期、金额、有效状态、修改版本；计划及原始期次日期唯一 |
| 每日估值 `sim_daily_valuation` | 日期、份额、市值、收益、净值版本、是否完整；支持历史重算 |

以上为逻辑对象，具体物理字段和索引在实施时沿现有迁移工具补齐。不能只新增一个可直接编辑的“当前金额”字段作为交易模型。

### 8.3 接口与关键约束

已注册 `/api/v1/sim-portfolios/current` 组合概览（含持仓）、`preview/{fundCode}`、`orders`、`ledger`、`recurring-plans` 与 `performance/{fundCode}`。订单提交、撤销、计划修改/暂停/恢复/结束采用明确写操作；详细路由以 Java `SimulationController` 为准。

原 `GET /api/v1/portfolio/current` 保持快照语义，避免同一返回字段有时表示截图展示值、有时表示模拟结算值。

- 用户编号只取自当前认证上下文；订单、计划、持仓及流水的读写均校验归属。新增明确的本人模拟交易和计划操作权限，不能仅靠前端隐藏按钮。
- 用户重复点击使用请求幂等键；卖出按组合/基金在事务中锁定和校验可用份额，防止两个卖单重复消费。
- 结算状态、流水和批次变动同事务提交。定投暂停与本期执行争抢时串行裁决，先成功的一方决定是否已经产生本期订单。
- 净值、费用、规则和事件数据保存来源及版本；已确认记录不能静默改写。源数据修正通过更正事件并重算受影响结果，保留原证据。
- 历史查询分页；每日估值按基金批量取得公共数据，避免每个用户、每笔持仓分别请求上游。
- 日志记录订单/计划 ID、状态、日期和 TraceID，不输出完整个人持仓或金额。
- 任务结果能查看最近成功时间、待确认订单数、失败原因、错过期次和数据滞后，后台停机/更新失败要能被发现。

## 9. 实施顺序及完成标准

这是开发依赖顺序，不表示第一批完成就把整套功能标为完成。

1. 建立统一模拟订单与账本，完成从关注/详情买入、待确认、持仓展示、加仓、卖出、撤单和交易记录。
2. 接入准确日期的净值更新、估值历史、现金分红、费用口径和更正处理；验证本金投入不会增加收益、卖出不会丢失历史收益。
3. 在同一买单链路上增加定投计划、后台执行、修改/暂停/恢复、重复执行保护和停机恢复。完成这一步才覆盖本次四项需求。
4. 后续增强：补录旧仓位、真实渠道费率、红利再投资、更多产品规则、现金钱包及资金加权/时间加权收益率。

关键验收：

- 无持仓从关注买入，出现待确认订单；对应净值确认后只建立一次份额。
- 同基金第二次买入合并展示为一条持仓，同时保留两笔订单及批次。
- 在净值不变的条件下追加投入，累计收益不凭空增加。
- 部分卖出后的剩余成本、浮动收益、已实现收益和累计收益满足交叉核对公式。
- 双击买入、并发卖出、重复结算、同一期定投重复触发均不重复记账或超卖。
- 净值未公布、非开放日、数据修正、分红除息、服务错过执行、订单延迟确认均符合上述规则。
- 取消关注后仍能卖出与查历史，定投及必要净值刷新正常，且没有绕过关注资料权益。
- 全部卖出暂停定投的选项有效；已有待确认买单能明确提示，不虚称已完全清仓。
- 不同用户不能通过替换订单或组合 ID 读取、修改他人的记录。
- 浏览器关闭期间后台正常执行；后台停止期间如实记录错过执行，不事后按已知净值补造正常交易。

## 11. 实现与验收（2026-09-10）

### 实际落点

- Vue `src/views/SimulatedPortfolioPage.vue` 接管 `/portfolio`，含持仓、计划、订单和流水；`SimulationTradeDialog` 共用于关注列表、两种详情页和持仓。旧确认快照保留在 `/portfolio/confirmed-snapshot`，原快照 API 不变。
- Java `com.fundradar.core.simulation` 负责本人授权、交易、定投、账务重放与后台任务。`V13__create_simulated_portfolio.sql` 创建 `sim_account`、`sim_order`、`sim_position`、`sim_plan`、`sim_plan_execution`、`sim_ledger_entry`、`sim_daily_valuation`、`sim_job_state`，并授予两项本人写权限；所有新表及字段有中文注释。
- FIFO 批次由确认订单在内存重放，未新增独立批次物理表。订单保存当前结算版本，流水追加原版本及更正证据；同时间的更正按数据库序号排序。历史曲线按日期批量更新。
- Python `/internal/v1/simulation` 使用既有服务 Token，拒绝浏览器 Origin；仅接收基金代码及日期。`20260910_20_simulation_market_refresh.py` 跟随原迁移 `20260909_19`，保存逐基金净值和分红刷新水位。
- 公共数据沿用 Tushare 现有适配器；`fund_div.div_cash` 按每份现金金额使用，`base_unit` 不作除数。字段来源：[Tushare 基金分红文档](https://tushare.pro/document/2?doc_id=120)。

### 后台与异常边界

Java 服务启动后默认每分钟检查，数据库锁阻止多实例重复执行；每个用户写账使用同一行锁。定投上午 10:00 起生成委托，15:00 截止；错过期次记为错过，不补造过去买单。网页关闭不影响后台，Java/Python 服务及数据库必须保持运行。

已有关注同步继续使用原机制；模拟订单和有效计划独立提供所需基金集合，不依赖关注关系。结算每分钟读本地公共资料；来源资料初次缺失时刷新，随后在 07、20、22 时段及失败重试时刷新，单基金至少间隔 30 分钟。复用原公开净值与分红接口，不新建数据源或发起个人交易。

现金分红资料未核验、精确成交日净值缺失、净值与分红不符或历史更正导致份额不足时，保留最后可靠估值并展示原因。没有净值的日期不伪造收益；不保证每天上涨。

当前日历覆盖 2026 年，超出覆盖范围时拒绝新交易或暂停计划，不能猜测下一年的节假日。规则仍为零申赎费、现金分红、无钱包，未模拟渠道限购及临时暂停。特殊产品、旧仓位导入和真实交易均不在本次实现范围。
