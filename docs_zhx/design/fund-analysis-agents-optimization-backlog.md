## 1. 本次记录的结论

优先借鉴证据组织、固定分析输入和分块报告展示。继续沿用本项目的净值处理、模型训练、时间可得性校验和发布规则；不整体迁移上游的技术栈或多 Agent 决策流程。

本次只记录优化方向，不启用新来源、不调用外部大模型、不改动接口或数据表，也不代表相关功能已实现。上游仅做过源码与文档核对，没有完成部署、接口可用性或分析效果验证。

### 当前工作的优先顺序

截至记录日，本项目实施手册记载：首个逻辑回归研究候选已训练、验证并保存 JSON，尚未做概率校准、滚动回测或发布。该状态来自现有交付记录，本次未重新查询数据库或运行训练。

1. 继续当前候选模型的训练期内部时间隔离校准与滚动验证工作，保留既有数据准入和发布条件。
2. 后续接入结果解释时，优先选取本清单中的证据结构、固定输入和分块报告。
3. 获得实际数据和使用需求后，再扩展多来源、新闻/持仓分析及模型调用管理。

预测主线的后续状态以实施手册为准。阅读本清单不能自动开启所有候选项，也不能把研究分数当作已发布概率。

## 2. 六项后续优化候选

以下编号用于后续讨论与跟踪；复选框表示实际功能是否完成，记录完成不勾选功能。

### FR-OPT-01｜程序计算指标，大模型解释结果

- [ ] 完成结果解释模块及其验证。

**上游设计：** 数据采集节点调用 `NavAnalysisUtil` 计算收益、回撤、波动率，再将摘要传给分析模块。[采集与指标计算源码][s1]

**本项目已有基础：** Python 的净值处理、特征快照、历史样本、候选训练与验证流程；Java 对外提供业务读取；Vue 展示结果。

**建议落法：**

- Python 继续负责数值计算、模型分数、校准与回测。大模型只解释白名单中的事实及允许展示的结果，不重新计算或修改概率。
- 解释输出应关联实际使用的数据和模型版本；本轮未纳入新闻、持仓或经理特征时，文字不得声称已综合这些因素。
- 事实资料解读与预测解释分开标识。研究模型未发布时，不通过解释文本绕过预测展示限制。

**进入条件：** 有可追溯的事实或已发布结果，并明确解释模块的输入、输出范围。实际外部模型调用沿用项目的配置与授权边界。

**完成标准：** 输出数值与输入一致；缺失信息不补造；解释失败时不影响事实和既有结果读取。

**不能照搬的细节：** 上游收益窗口使用自然日，部分风险窗口使用记录条数。本项目保持自己的有效净值日、复权和时间窗口规则，不能只复制窗口名称或公式。

### FR-OPT-02｜区分事实、计算结果、模型输出与文字解释

- [ ] 完成证据关联及用户可读展示。

**上游设计：** `EvidenceItem` 保存来源、数据类型、证据等级、采集时间、数据截至日和快照编号。[证据结构源码][s2]

**本项目已有基础：** `source_registry`、来源编号、净值公告日期、特征快照、数据与模型指纹，以及已有事件读取契约。

**建议落法：**

- 在上游事实/估算/推断分类的启发下，明确区分披露事实、程序计算、模型输出、文字解释；若以后引入盘中估算，单独标注，不能与正式净值混用。
- 每条关键解释引用实际证据编号。来源链接、业务日期、最早可得时间 `available_at`、采集时间分别表达，不以采集时间代替历史可得时间。
- “页面可展示的资料”与“本次模型实际使用的特征”分开记录。

**进入条件：** 确定一份最小分析结果与证据契约；优先利用已有数据，不以此为理由启动新的采集。

**完成标准：** 用户能从解释定位具体输入；无法核实、已过期或缺失的材料明确标注，不能归类为已证实事实。

**上游实现限制：** 当前 `buildEvidences()` 默认只生成一条 LLM 推断，快照编号为空，没有逐条绑定真实输入。借鉴的是结构设计，实际关联需要补全。[默认生成逻辑][s3]

### FR-OPT-03｜一次分析固定一份输入，结果可追溯

- [ ] 完成输入、模型和报告之间的关联。

**上游设计：** `AnalysisContext` 在各分析节点间共享基金、日期、输入、分项报告与证据列表；另有 `SnapshotService` 提供快照存取。[分析上下文][s4]、[快照服务][s5]

**本项目已有基础：** 特征快照、历史样本批次、数据集指纹、模型 JSON 及模型指纹。已有模型/结果实体不意味着当前研究候选已经接入发布。

**建议落法：**

- 一次分析先固定数据截止时间与输入引用，各模块使用同一份材料，避免执行中刷新数据造成结论不一致。
- 串联“基金和周期 → 数据截止时间 → 输入快照或数据指纹 → 模型版本 → 解释模板版本 → 报告”。候选字段需在实际设计时确认，不据此直接新增表。
- 统一任务与报告标识，并区分生成时间和数据业务时间。公开数据引用与用户专属内容按现有权限边界处理。
- 数值计算可以重算核对；大模型文字保留原始已审核输出与调用版本，不承诺重调模型会产生完全相同的文字。

**进入条件：** 开始设计结果解释的保存和读取方式时，与 FR-OPT-02 一起收敛契约。

**完成标准：** 历史报告能定位当时输入和规则；重新同步数据不会改变旧报告的依据；同一数值产物可按记录重算。

**上游实现限制：** 源码搜索未发现分析主流程调用 `saveSnapshot()`；报告保存也没有绑定 `inputSnapshotId`，尚不能视为完整的输入快照闭环。[报告保存源码][s6]

### FR-OPT-04｜按分析职责拆模块，按输入覆盖启用

- [ ] 完成所需分析模块与缺失输入处理。

**上游设计：** 基金、技术、行业、经理、情绪、新闻六个分析师分别产出报告，再进入汇总流程。[并行分析节点][s7]

**建议落法：**

| 分析部分 | 本项目的使用条件 |
| --- | --- |
| 历史表现、历史风险 | 使用已校验净值与确定性指标。 |
| 经理、分红资料 | 可以解释已有披露事实；是否成为预测特征需独立验证。 |
| 行业、底层持仓 | 等对应来源、披露时间和数据覆盖满足要求后启用。 |
| 新闻、政策、公告事件 | 等来源接入、事件审核与基金关联完成后启用。 |

各模块区分可用、缺少输入、不适用、执行失败、已过期等状态。没有对应输入时跳过分析并显示原因，不能只因存在某个 Agent 名称就声称已分析该领域。

**进入条件：** 有真实的新增分析需求及相应输入；先扩展一个模块，不默认启用六个角色。

**完成标准：** 分项输出有输入依据；局部失败可被识别；关键必需输入缺失时阻止综合结论，不能把失败当成功或中性结果。

**上游实现限制：** 数据采集失败可返回空或不完整的上下文，随后仍进入分析节点；该采集节点没有读取新闻，却会启动新闻分析师。上游行为不能直接沿用。[采集异常路径][s1]

### FR-OPT-05｜关注详情先给摘要，再展开依据

- [ ] 完成关注详情中的分析结果展示及权限、空态验证。

**上游设计：** 报告组件按领域展示内容，流程弹窗可点击节点查看各部分输出。[报告组件][s8]、[流程组件][s9]

**本项目已有基础：** `WatchlistFundDetailPage.vue`、基金资料、净值图表、来源与缺失状态；入口继续使用“我的关注 → 单基金详情”。

**建议展示顺序：**

1. 当前状态或允许展示的结果、适用范围、数据截至时间。
2. 实际使用了哪些数据，哪些信息未纳入。
3. 支持依据、反向证据、限制和数据缺口。
4. 可展开的来源、模型/模板版本及历史结果。

第一版优先采用卡片和折叠区域；复杂流程图作为后续可选展示。状态必须来自真实执行记录，不能仅以“有一段文字”判断节点成功。模型未发布时不显示方向概率；普通资料解读不能包装成预测。

**进入条件：** FR-OPT-02/03 的最小读取契约可用。涉及概率的区域还须有通过准入并发布的真实结果。

**完成标准：** 正常、未发布、缺少数据、过期、失败等状态可区分；服务端落实本人关注范围；外部文本按安全渲染规则处理；页面读取不触发训练、采集或重复模型调用。

### FR-OPT-06｜按需统一数据源适配与模型调用

- [ ] 在确有第二个来源需求时补齐统一适配与按能力选择规则。
- [ ] 在恢复模型解释时补齐统一调用记录、模板版本与预算控制。

**上游设计：** `DataSourceAdapter` 统一供应商能力，`DataSourceManager` 提供优先级和缓存兜底；`LlmService` 记录模型、Token 用量与耗时。[来源管理][s10]、[模型调用][s11]

**本项目已有基础：** Tushare 接入、来源登记、逐接口授权列表、同步记录、水位、缓存降级与 Java/Python 服务边界。

**建议落法：**

- 增加实际来源时，在 Python 数据接入层统一能力接口；分别判断净值、经理、持仓等能力是否授权、可用、新鲜。
- 来源切换必须保留来源与口径，不能直接拼接不同来源的净值序列；缓存数据带原始数据时间和过期标记。
- 解释调用集中管理超时、有限重试、输入输出范围、模型版本、模板版本或哈希、Token 用量和耗时。
- 同一输入与版本的已保存解释可复用，避免每次打开页面都重新调用；缓存范围遵守用户数据隔离。

**进入条件：** 有实际第二来源或解释模块需求；新增成本和接入按任务当时的授权处理。本清单不构成新付费或接入授权。

**完成标准：** 能区分未授权、不可用、缺失、陈旧；错误不会触发来源混用或伪造结果；能定位一次模型调用使用的输入与模板，日志中没有凭据。

**上游实现限制：** 主采集节点使用的是第一个可用适配器，没有覆盖完整的逐能力降级；`LlmService` 虽有模板版本字段，当前赋值为 `null`。这些都需要按本项目补齐。

## 3. 暂缓或不直接采用的部分

| 项目 | 原因与本项目处理 |
| --- | --- |
| 全套多 Agent、多轮多空辩论 | 多个角色共享输入不会增加新的市场事实，调用数量与维护工作会增加。先借鉴支持证据/反向证据的组织方式，待有对照效果后再决定是否扩展。 |
| LLM 自报置信度 | 上游分数来自模型回答，解析失败会回退为 50。不能将它视为经校准的上涨概率；缺少可用结果时保持不可用状态。[解析逻辑][s3] |
| 交易、仓位、组合建议 | 不属于当前仅净值、20 个有效净值日的研究切片；不从报告样式顺带引入。 |
| 整体迁移 Spring AI Alibaba 或重建 Java 多模块 | 继续使用 Vue → Java → FastAPI 的职责分工，在现有服务内实现必要能力。 |
| 直接复制上游报告保存与用户处理 | 当前保存代码含固定 `userId(1L)`。本项目沿用真实认证上下文及本人关注授权，不复制固定用户归属。[报告保存][s6] |

上游主分析链是数据采集、多角色分析与报告生成。本次没有发现它具备与本项目同类的历史候选训练、概率校准、滚动回测和模型发布闭环，不能用该流程替代当前模型验证工作。

## 4. 后续实际启动时的检查入口

- 先读取预测实施手册的最新恢复点，不能按本文件记录日的状态直接续跑。
- 从 FR-OPT-01 至 FR-OPT-06 中选一个明确范围，确认已有输入、要交付的可观察结果及依赖。
- 只有实际变更接口、数据模型或关键流程时，才维护对应需求、设计和验收文档；本清单中的建议字段不是已定契约。
- 按实际风险验证来源与时效、错误降级、结果一致性、权限和必要的端到端行为；静态检查不能记为真实数据源或模型验证。
- 完成后在实施总入口记录真实结果，再更新本清单的对应状态。外部来源、持仓、模型发布等原有边界继续适用。
