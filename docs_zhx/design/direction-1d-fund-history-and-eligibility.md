# 单基金一日预测历史与准入简化

本次按用户确认范围实施：单基金入口只查看自己的历史，日常预测取消业绩比较基准关键词白名单。继续使用已有三组实验模型，不重训、不替换模型或改写已保存预测。

## 页面与数据范围

- 关注详情新增 `section=prediction-history`，沿用同一基金代码与左侧导航；模型分析中的链接改为“查看本基金预测历史”。账号总管理页仍从关注列表独立进入。
- 复用 Java `/api/v1/watchlist/prediction-1d/history`，必传当前基金代码；Java SQL 同时限制当前认证用户和基金代码。单基金页面不请求账号覆盖清单、统计或启停接口。
- 每页20条，按目标日期和记录编号倒序，使用已有游标翻页。切换基金清空记录和游标，忽略过期请求；代码无效、接口失败或数据混入其他基金时停止展示，不回退到全账号范围。
- 固定模型和每周更新模型分别显示方向与对错；只有已确认提前保存且有正式净值答案的有效分支才判对错。平盘归为非上涨，未公布、不可用分支和失效原文不算预测成绩。

## 预测准入

- `classify(..., prediction=True)` 使用 `PROFILE_ASSET_TYPE_V2`：可信来源档案、正常运作状态和主产品身份成立时，按已确认的 STOCK/MIXED/BOND 类型选择既有模型；不要求比较基准含指定境内指数名称。
- 海外、港股、商品、FOF、货币和REIT等边界继续保留，已有主状态码不变，`reason_codes` 附加具体原因。前端将其说明为日期/数据/模型尚未验证等实际限制，不显示含糊的“独立协议”。
- 覆盖检查与真实推理使用相同新规则；新输入快照记录当时的分组依据。默认 `classify(...)` 保留原研究规则，既有冻结范围、独立研究和训练流程不受此修改影响。
- 净值完整性、预测截止、模型完整性、首次提前保存与到期核对均沿用原实现。放宽资料规则不等于全部基金都已适用或效果已被证明。
