# 境内净值补拉与四周期预测规则

确认日期：2026-09-24。范围为现有境内股票、混合、债券基金预测；跨境及特殊基金不猜测估值日历。用户已确认实施，无提交或推送要求。

## 业务契约

- 估值日15:00前，以上一估值日完整净值为基准，首个待预测日为今天。
- 15:00及之后，以当天完整净值为基准，首个待预测日为下一估值日；未取得当天净值时等待，不能跳过当天净值直接顺延。
- 非估值日以最近已结束估值日为基准，目标按已核验日历顺延。历史所需日期缺失先补齐，不前值填充。
- 一日取消18:00—08:30门槛。生成及提前留档截止改为目标估值日15:00；跨过截止的排队作业拒绝更换目标日或补造旧预测。
- 五日、二十日收益从基准净值计算到第5、20个后续估值日；半年从基准日加6自然月，再按日历顺延。页面同时显示净值基准与待预测起止日期。
- 新多周期规则为`PREDICTION_POLICY_V3` / `NAV_ANCHORED_CASH_REINVESTED_THREE_STATE_V3`。训练标签、实时预测、到期核验使用同一收益基准；旧V1/V2原文、模型、路由及核验口径保留。新目标不能直接采用旧标签训练的模型，新路由先采用该目标的基础方法，再由已有自动训练与选优链路更新。
- 一日模型输入及标签定义未变，沿用原模型协议；新增`generation_policy=CN_NAV_READY_CLOSE_V1`明确时间规则，Java兼容校验旧窗口与新规则。
- 同一基金、周期、目标期和规则，只保存首次成功结果。更换模型不覆盖本期原文，历史修订只能新增核验版本。

## 净值同步与恢复

每只基金独立校验来源代码、拉取、规范化及提交。单只失败继续其他基金，已成功的批次不会因后续异常回滚。按200只批量读取本地日期，避免逐只读取完整历史；境内在既有已核验2021—2026日历覆盖内扫描本地历史起点至最近收盘日，并请求缺失的连续日期段。没有基线时要求成立日在已核验范围内，否则单列待补历史基线，不猜测起点。

新增`nav_sync_state`保存每只基金的缺日、状态、原因、连续失败次数及下次重试时间。请求成功但所需日期仍缺失记`STATUS_UNKNOWN`，不能根据空响应判定来源未公布。`NOT_PUBLISHED`仅供有明确发布状态证据的来源使用，当前Tushare净值接口未提供该证明，不生成此结论。

临时失败在已有请求级有限重试后，按30分钟至6小时退避继续补拉；状态未知每30分钟复查。授权、配置、基线等不可重试错误保留记录，修正后手动任务可以重试。成功后清零连续失败次数。自动检查从数据库恢复状态，进程重启不丢失缺口。

API生命周期启动独立净值补拉线程，首次延迟30秒，每轮结束后等待30分钟；沿用`tushare_market_incremental_enabled`开关。手动、API后台与既有Celery任务共用数据库互斥锁。Celery无日期的定时执行也遵守持久重试时刻。现有Java一日、多周期定时任务在净值补齐后的后续检查继续生成，不要求用户再次点击。

`source_sync_run`仅在完整成功时更新最近成功时间；部分成功保留写入计数与错误摘要。页面区分新生成、本期已有、等待净值及其他失败，并显示所需净值日期；不把任务执行结束等同净值齐全。
