## 1. 设计结论

预测模块服务于“我的关注”中的单基金复核，而不是后台管理页，也不是公共市场详情的替代品。后台负责准备、回测和发布；用户只在本人已关注的基金详情中读取已经发布的结果。

当前已有的 `M3_STOCK_MOMENTUM_BASELINE_V1` 是单股票型、20 个交易日、仅净值历史统计的工程基线。它不等同于 7/15/30/60 天多周期预测，也不代表已经纳入持仓板块或新闻公告。

## 2. 总体链路

```text
已授权的净值、持仓/板块、公告/新闻、市场基准
  -> 来源登记、同步水位、披露/发布时间校验
  -> 按基金 + 截止日形成可复现输入快照
  -> 按 5 / 10 / 20 / 40 交易日分别构建特征与标签
  -> 按周期独立评分
  -> 时间滚动回测 + 发布闸门
  -> 已发布的多周期 forecast_result
  -> Java：当前会话 + 本人关注关系校验
  -> Vue：/watchlist/:fundCode 的“未来趋势预测”模块
```

其中 5/10/20/40 个交易日分别是对用户“约 7/15/30/60 天”的初始映射。交易日历、节假日和基金估值频率确定后，页面继续按自然语言显示，同时在说明中展示精确交易日数。

## 3. 前端呈现与状态

### 3.1 位置和交互

`WatchlistFundDetailPage.vue` 在基础资料、净值趋势和结构化分红之后新增“未来趋势预测”区域。公共 `FundDetailPage.vue` 可以保留基础数据和公共摘要，但不承担“我的关注预测”的完整交互。

区域固定包含：

1. 四张周期卡：约 7 天、15 天、1 个月、2 个月。
2. 每张卡的状态：`AVAILABLE`、`DATA_INSUFFICIENT`、`MODEL_NOT_RELEASED`、`STALE`、`NOT_APPLICABLE`。
3. `AVAILABLE` 才显示上涨/下跌概率和置信度；其余状态只显示原因和恢复条件。
4. “为什么这样判断”抽屉：按净值趋势、持仓/板块、公告/新闻、市场基准分组列出已实际使用的事实。
5. “数据缺口”与“非交易提示”：始终显示，不折叠为免责声明。

首期未满足任何周期发布条件时，页面显示“预测准备中”：列出已具备的历史净值基础，以及持仓板块、新闻公告、真实回测或模型发布还缺哪些；不展示占位百分比。

### 3.2 防误导文案

- 仅净值参与时：`净值历史基线（未纳入持仓/板块、新闻公告）`。
- 综合输入参与时：逐项列出覆盖率、来源和最新可用日期，不能只写“AI 综合判断”。
- DeepSeek 文本：标作“对已发布结果的解释”，不可作为概率来源，也不能在页面打开时自动调用。

## 4. 数据契约与时间边界

### 4.1 预测输入快照

每次预测的逻辑业务键为：

```text
fund_code + as_of_date + feature_version + horizon_trading_days
```

最少应保存：基金类型、净值来源水位、特征哈希、输入覆盖清单、每类输入的业务日期/披露日期/发布时间、完整度和不可评分原因。持仓与事件不可把“采集入库时间”当作可用时间；必须以对当时市场公开可见的披露日期或发布时间为准。

### 4.2 多周期结果

现有 `forecast_result` 的单周期业务键不足以表达四个窗口。实现阶段需以非破坏性迁移引入 `horizon_trading_days`、`horizon_label`、`input_coverage` 和每周期的目标定义，并将唯一性升级为：

```text
fund_code + as_of_date + model_version + horizon_trading_days
```

迁移前的 20 个交易日历史结果仍保留原语义；新多周期模型使用新模型/特征版本，不回填或改写旧结果。

### 4.3 尚需新增或补全的输入模型

| 逻辑对象 | 关键粒度 | 用途 | 当前状态 |
| --- | --- | --- | --- |
| 基金持仓快照 | fund_code + report_period + disclosed_at + source | 还原基金在公开披露时的行业/标的暴露 | 未接入 |
| 板块暴露快照 | fund_code + as_of_date + exposure_version | 将持仓归集为行业/指数/主题特征 | 未接入 |
| 事件关联 | event_id + fund_code + relation_version | 将已授权且已审查的公告/新闻关联到基金 | 表/读取骨架存在，无真实数据 |
| 多周期预测结果 | fund_code + as_of_date + model_version + horizon | 存储四个周期独立概率与状态 | 现有表仅支持单周期基线 |

所有对象均须保存来源、业务键、内容哈希、`wide_updated_at`/同步时间、删除状态和模型/字段版本；增量运行不能因重复同步无意义地推进业务水位。

## 5. 模型、回测与发布

### 5.1 分两步交付

| 阶段 | 对用户的真实含义 | 最低输入 | 允许展示 |
| --- | --- | --- |
| A. 净值历史基线 | 仅用历史净值的可验证统计基线 | 净值、已授权市场/基准、四个周期标签、独立回测 | 明确标为“净值历史基线”的单周期或多周期概率 |
| B. 综合预测 | 历史净值 + 已披露持仓板块 + 已授权事件/公告 + 市场基准 | A 阶段合格，并满足各扩展输入覆盖与时效阈值 | “综合预测”及各输入贡献和缺口 |

阶段 A 不能被包装成阶段 B。若某基金缺少当前持仓或可靠事件关联，即使其他基金可以做综合预测，该基金也必须降级到基线或“数据不足”。

### 5.2 回测规则

每个周期独立保存训练、验证和测试窗口。任一评分日只允许使用该日及以前可获得的净值、持仓披露和事件信息；未来标签只用于训练/验证/测试的目标计算，不能进入特征。

模型发布至少检查：样本量、时间滚动测试、上涨/下跌命中情况、概率校准、最大回撤/波动、与长期持有/定投/已授权基准的对照、覆盖率和数据漂移。任一周期不合格，只暂停该周期结果，不影响其它已合格周期的历史只读记录。

## 6. 权限、安全与稳定性

1. Vue 只经 Java 读取；Java 按当前用户的关注关系校验后才返回完整预测。未关注返回 `403/WATCHLIST_REQUIRED`，不因公共详情存在而放行。
2. Python 只存和计算基金层面的非个人化数据；不接触 `user_id`、个人仓位、成本、交易记录或外部账号。
3. 页面读取不触发同步、训练、评分、回测、发布或大模型请求。管理员操作需要单独权限、审计和异步运行记录。
4. 预测服务不可用时，最多返回明确标记为陈旧的已发布结果；没有可用结果时返回受控不可用状态，不生成新概率。
5. 对持仓/新闻来源按授权、限频、保留期限、展示范围和删除策略隔离；未经确认的网页公开展示不等于允许自动批量采集。

## 7. 实施前仍需确认的外部边界

1. 持仓与板块数据的具体授权来源、许可范围、刷新频率、保存/展示期限。
2. 公告、新闻和政策事件的授权来源，以及是否允许自动同步；当前 M2 仍暂停，不可因预测模块自动恢复。
3. 首批覆盖的基金类别。建议先从历史净值充分、基准可取得的股票型基金开始，随后再逐类扩展；不得默认全部基金类型同一模型。
4. 多周期模型的正式发布阈值和“基线/综合”切换门槛。

## 8. v0.2｜控制面退役后的架构边界

分析运行相关的 Vue 路由、Java 管理 API、Python 内部运行任务和外部大模型解释已从当前三端代码移除。公共基金详情仍可只读查询模型/回测摘要，但不再返回解释快照。

后续 P2/P3 的训练、回测和发布只能作为服务端批处理能力设计，并以四周期预测的真实输入、输出和发布证据为中心；不能先恢复一个让管理员手工点击的页面再反推用户价值。
