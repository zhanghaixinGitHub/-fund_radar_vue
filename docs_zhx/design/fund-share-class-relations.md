# 基金份额关联

## 目标与边界

基金市场与关注详情不再依赖前端手工名单，后台按当前基金目录统一维护同产品份额。现有市场范围动态读取，新增基金随既有资料同步纳入检查。关联发现不把外部份额自动加入市场、关注、交易、评级或净值任务，不修改未经核实的历史产品主键。

## 事实与来源

从该基金公开公告目录选取截至检查日最新的定期报告，只接受“基金基本情况”中的主代码及下属份额交易代码。必须包含当前基金；明确排除目标 ETF、持仓证券、其他基金及报告正文中的任意代码。不通过删除名称后缀猜测归属。各份额名称由精确代码的公开档案核对，A/C、人民币/外币标签仅在名称明确时提取。

原始目录、报告及档案按 SHA-256 留存。当前投影以原子文件写入并保留历史版本；查询核对出处指纹。来源变化、冲突、抓取或解析失败均不写成无其他份额。已保存关系失败时标记待更新，没有依据则待核实。产品归属相互冲突时关闭该关系。不同基金的错误互不阻断。

## 接口与同步

Python `/internal/v1/funds/{fundCode}/share-classes` 仅服务令牌访问；Java `/api/v1/funds/{fundCode}/share-classes` 要求登录及 FUND_READ。返回基金代码、状态、报告日期、核对时间及该产品的各份额；原件路径、哈希、抓取接口等不返回页面。浏览器只访问 Java；GET 仅读取快照，不联网采集或写入。

接入已有市场资料同步，通常七天复查，新基金立即检查；失败项下次继续。独立 CLI 支持按全目录或指定代码同步及预览，使用相同的预算、来源和发布逻辑。同步使用数据库会话锁避免多进程覆盖，公开来源限制请求大小、超时、串行速率和单轮请求数。

## 展示与验收

仍在基础资料网格展示其他份额，排除当前份额；不同币种保留名称中的区别。待核实或读取失败显示简短业务提示，单份额报告不制造空类别。切换基金立即清理旧关系并丢弃过期响应。

验证包括来源身份、目标 ETF 排除、单份额、多类别、多币种、冲突、损坏原件、失败保留与版本发布、同步复用和新增范围、内部令牌与 Java 权限、跨基金响应隔离；最后逐项核对当前全部市场基金，并在真实页面抽查。
