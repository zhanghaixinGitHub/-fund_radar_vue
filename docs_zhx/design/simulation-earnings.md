# 模拟收益明细契约

日期：2026-09-30。入口名称为“收益明细”，与本人实际账户资料保持独立。

## 用户入口

- `/portfolio/earnings` 默认整个模拟账户；`fundCode` 切换单基金，左侧菜单统一选中收益明细。
- 名称/代码搜索包含清仓历史；默认近一个月，支持近三个月、今年、全部、自选日期。
- 持仓卡片非交互区进入指定基金；综合建议整块及底部操作区排除。基金名称和明确收益入口使用原生链接，普通鼠标选字在捕获阶段阻止导航，键盘和辅助打开行为保留。
- `from` 仅允许本人持仓列表白名单参数，保留搜索、排序、页码、每页条数、清仓条件；滚动位置仅保存在当前浏览器内存。

## 本人只读接口

基路径 `/api/v1/sim-portfolios/current`，服务端 `PORTFOLIO_SELF_READ` 从当前会话取得用户，所有 SQL 以该用户键限定；不接受任意用户查询。

| 路径 | 参数 | 返回 |
| --- | --- | --- |
| `/earnings/funds` | keyword（最多50字）、page、pageSize | 本人历史基金目录，含清仓和待首笔确认；支持名称/代码查询 |
| `/earnings` | fundCode可选、range（MONTH/QUARTER/YEAR/ALL/CUSTOM）、startDate/endDate（CUSTOM必需）、page/pageSize | 所选范围、期间合计、已知部分、完整性、倒序日明细、升序累计曲线 |
| `/earnings/days/{date}` | page、pageSize | 本人账户当天基金构成，独立分页 |

页码 1—100000，每页 1—100；默认 20。日期不晚于上海当日，单次区间最多相差 3660 天。ALL 超出上限明确报错，要求自选分段，不能静默截断。账户目录最多 2000 只，超过时明确报错；完整代码搜索及单基金读取仍可用。只读可重复读事务保证目录、汇总来自同一数据库快照。无新表、迁移、定时任务或个人数据对外发送。

## 计算和状态

沿用 `SimulationAccounting` → `SimulationRepository.saveCalculation` → `sim_daily_valuation`：

- `cumulative_gain = 市值 − 剩余成本 + 已实现收益 + 现金分红收益`；原账务同时校验 `市值 + 净卖出额 + 分红 − 总买入额`。按原订单费用规则，V1 无费、V2 含申赎费；查询不更改该口径。
- `daily_gain` 为相邻有效交易日的累计差；首次有效估值相对零计算。跨缺失交易日为空，不把多天变动归入一天。本金投入、收回不计盈利。
- 账户先在数据库按同一 `valuation_date` 聚合，再与当日应有基金数核对；基金集合取本人非撤销交易与收益历史并集，不按当前份额过滤。自首次交易日起期待记录，已清仓后若缺少投影也保守保持未知，不能仅凭当前清仓状态推断过去零收益。
- 当日收益只在应有基金全部具有有效 `daily_gain` 时返回。`knownGain` 是已知部分，必须如此标注；待核对的投影不计入已知收益。累计收益需要全部应有基金存在当日有效累计值。
- `PENDING` 表示晚于已有估值或尚无首笔估值；`MISSING` 是历史中断；`PARTIAL` 是当日已有记录但不完整；`NON_TRADING` 只由既有核验日历确认；日历覆盖外/不可用为 `CALENDAR_UNKNOWN`；`REVIEW` 为待核对。真实零保持数值零。
- 期间完整收益取整个匹配区间全部逐日收益之和。只要有待更新、缺失、未知或待核对日期，完整合计为空，同时可显示已知部分。非交易日没有每日金额，不冒充零。空账户/空范围无虚构收益。
- 累计曲线显示截至各日的历史累计值，非从查询区间零点累加；空点不连线，悬浮提示也不将空值转零。

## 验证边界

- Java 合成单测覆盖日期对齐、清仓历史、合计跨分页、缺失与零、日期范围、容量和权限；保留原账务回归测试。
- 仓储 SQL 使用独立 PostgreSQL 容器、会话临时表、合成用户验证，既不加载项目数据源也不运行 Flyway。
- 页面预览使用本地只读合成 API，验证导航、搜索、日期、自选合计、展开分页、选字、键盘和返回恢复；不能作为用户已登录页面生效证明。
- 正式页面依赖用户自行启动加载新代码的 Java/Vue 服务，以及既有公共交易日历服务；本任务不启停共享 5173/8080/8000 服务，不执行真实交易、结算或历史重算。
