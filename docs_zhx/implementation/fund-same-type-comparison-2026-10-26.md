## 1. 实施范围与完成条件

- Python：基于可追溯资料建立细分类别，固定准入规则，执行有效期检查、独立产品去重及同份额比较；仅使用共同起止日的有效单位净值。
- Java：保留现有基金读取授权与服务令牌链路，完整传递分组、区间、数量、状态及业务说明。
- Vue：展示实际同类标准、共同区间、真实样本数量及按变化幅度降序排列的基金；分类或净值不足如实说明。
- 运行：相关单测、编译/构建、本地真实接口和内置浏览器验证。页面检查不操作桌面应用。
- 不修改历史评级、预测、交易或个人持仓；不扩展数据源付费权限、基金目录或定时任务。

完成条件是三端能力能够实际工作，资料缺口能够准确退出并有记录，而不是强制让全部基金都出现排名。缺资料不能用大类、名称或未来资料补齐。对资料已经存在且能核实的样本，继续补充事实与实现，不把可自行完成的工作留给用户。

## 3. 冻结的执行规则

1. **分类先于结果**：先记录来源、产品身份、有效期、正式类别、主动/被动/增强、投资市场、合同资产配置约束、主题/指数、币种和汇率处理，再计算涨跌。规则不能参考本次涨跌优劣调整。
2. **证据准入**：只有已经核实且定义完整的分类参与严格比较；证据不足、相互冲突、被撤回或有效期不覆盖区间时明确退出。不得把所有“未知”组合在一起。
3. **分类存储**：优先复用现有原件及身份关系；缺少维度时使用版本化、可追溯的比较分类资料，不覆盖评级分类。先采用与现有本地资料快照一致的文件交付方式，避免为本次功能修改历史评级表；发布前检查引用与结构，保留旧版本。
4. **独立产品**：来源证实的同一产品只占一个位置。目标保留正在查看的份额；其他产品选同份额类别，多个符合者固定按代码顺序选择。没有合适份额不换用另一收费类别凑样本。
5. **共同区间**：目标截止日为终点，近 30 天基准日为起点，核对适用日历；所有候选使用完全相同的起止日，各自端点同来源且值为正的有限数。
6. **计算与排序**：单位净值终值/起值−1，不含分红和买卖费用；不以累计净值比值冒充总回报。高到低排列，同值按代码排序；不扩展为全市场名次。
7. **样本不足**：只有目标时说明暂无其他可比基金；缺分类与缺净值分别提示；禁止静默降级为大类排名。真实数量不受截图旧数量限制。
8. **接口兼容**：保留原端点、原字段及原计数的行数含义；补充业务分组、起点、样本单位、独立产品数量和退出原因。新增信息由服务端计算，前端不自行构造同类名单。

各基金的具体分类及原文依据在资料盘点产物中固定。合同允许范围宽且持仓风格变化时，不凭单季持仓永久细分；股票/债券分档无可靠依据时保持未就绪。指数身份、指数增强、境外市场、主题和可转债等按修改方案分别核对。

## 5. 验证用例

- 相同大类但合同配置、投资市场或主题不符的样本排除；指数同名近似、普通与增强不得误合并。
- 分类缺失、未来生效、到期、冲突、被撤回均不能参与；历史比较不使用之后才生效的资料。
- 同产品多份额只保留一只；目标份额不被替换；不能按表现挑代表份额。
- 候选起点/终点缺失、端点不同来源、非正数、非有限数和不适用指标均准确退出，不补零。
- 正负收益按数值降序，同值顺序稳定；数量与返回行数、产品去重结果一致。
- 正常、有分类无其他样本、分类不足、净值不足、服务失败以及快速切换基金均有准确业务说明。
- Java 保留 `FUND_READ` 和内部服务令牌边界，新增字段不丢失、不改变精度或日期。
- 页面只显示业务分组、基金名称与括号代码、变化幅度、必要区间与口径；无模型/算法选择、技术状态码或调试内容。
