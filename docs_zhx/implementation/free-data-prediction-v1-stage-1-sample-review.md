## 0. 这一步做了什么，没有做什么

本记录只从本机 `fund_ai.nav _daily`读取已经落库的历史净值，手算 3 只股票型基金各 2 条样本。

已做：核对基金类型、净值日期、公告日期、20 个后续有效净值日、历史涨跌标签和几个最简单的输入收益率。

没有做：没有调用 Tushare、没有写数据库、没有训练逻辑回归、没有生成用户概率、没有改 Python/Java/Vue 业务代码。

对应文件和职责：

| 文件 | 本阶段只需理解的职责 |
| --- | --- |
| `C:\pythonProject\workSpace06\app\services\tushare_fund_sync.py` | 把来源净值规范为应用内部记录，并控制同步运行。 |

## 2. 为什么挑这三只基金

本次从 24 只股票型基金中按代码选择三只：`001632`、`006730`、`008888`。它们都有完整的累计净值、公告日，并且历史长度足以支持后续 20 日样本。

| 基金代码 | 基金名称 | 历史净值点 | 累计净值缺失/非法 | 公告日缺失 |
| --- | --- | ---: | ---: | ---: |
| 001632 | 天弘中证食品饮料ETF联接-C | 2,709 | 0 | 0 |
| 006730 | 万家中证500指数增强-C | 1,753 | 0 | 0 |
| 008888 | 华夏国证半导体芯片ETF联接-C | 1,521 | 0 | 0 |

这里选累计净值，是因为这三只基金的累计净值全程有效。累计净值能减少分红导致的机械跳变；后续正式代码仍要对每只基金按完整序列检查口径，不能只看这 6 条样本就下结论。

## 3. 六条真实历史样本

### 3.1 怎么读表

- `净值业务日`：这个净值属于哪一天。
- `可用日`：公告日；从这天起，外部才能看到该净值。V1.0 以后会把它保存为 `available_at`。
- `输入收益`：站在可用日当时，可以回头算出的已知历史特征。
- `未来收益`：20 个有效净值日后才知道的历史答案。它只能用于训练和回测，不能作为当时输入。
- `标签`：未来收益大于 0 为 `1`（上涨），否则为 `0`（非上涨）。

## 4. 逐行拆开一条样本：008888，2025-08-07

假设现在是 **2025-08-08**：市场刚刚看见 008888 在 2025-08-07 的累计净值 `1.12280000`。当时最多只能使用 2025-08-08 及之前公开的资料。

### 4.1 当时模型可以知道什么

| 回看长度 | 起点业务日 | 当日累计净值 | 到 2025-08-07 的已知收益 |
| --- | --- | ---: | ---: |
| 5 个有效净值日 | 2025-07-31 | 1.11150000 | 1.0166% |
| 20 个有效净值日 | 2025-07-10 | 1.05110000 | 6.8214% |
| 60 个有效净值日 | 2025-05-14 | 1.09430000 | 2.6044% |

例如 20 日输入收益的计算是：

```text
1.12280000 / 1.05110000 - 1 = 0.068214... = 6.8214%
```

这是输入特征，2025-08-08 当天可以合法获得。

## 7. 可复查的只读 SQL

下面查询可以在本机 `fund_ai` 中重新列出上面 008888 的 21 条净值；它只有 `SELECT`，不会修改数据。

```sql
WITH ordered AS (
    SELECT
        nav_date,
        ann_date,
        accumulated_nav,
        ROW_NUMBER() OVER (ORDER BY nav_date) AS sequence_no
    FROM nav_daily
    WHERE fund_code = '008888'
),
anchor AS (
    SELECT sequence_no
    FROM ordered
    WHERE nav_date = DATE '2025-08-07'
)
SELECT
    ordered.sequence_no - anchor.sequence_no AS offset_after_start,
    ordered.nav_date,
    ordered.ann_date,
    ordered.accumulated_nav
FROM ordered
CROSS JOIN anchor
WHERE ordered.sequence_no BETWEEN anchor.sequence_no AND anchor.sequence_no + 20
ORDER BY ordered.sequence_no;
```

如果未来数据重同步或被来源修订，查询结果可能变化；每次进入新阶段都要重新记录运行时间、来源运行和数据哈希。
