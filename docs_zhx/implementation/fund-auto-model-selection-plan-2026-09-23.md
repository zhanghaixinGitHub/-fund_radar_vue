## 1. 用户已经确定的方向

用户只需要使用系统给出的预测和建议。模型怎么训练、比较、采用、更换、回退，由后台完成。用户不需要理解历史学习法、近期走势法，不需要挑新旧方法、候选模型或手动选择训练日期。

“最优模型”在本项目中的可执行含义是：在已接入且可运行的候选中，按事先固定的条件，自动选用当前表现更合适的版本；不宣称找到了永远最好的模型。对用户提供统一预测服务，内部允许不同周期使用不同模型。

本轮主要交付两件事：

1. 打通无需打开页面或手动启动研究的“数据就绪→训练/比较→采用→真实预测→建议引用→到期核验→下一轮改进”。
2. 日常页面聚焦预测、建议、实际效果和运行状态；模型研发过程仅保留在有权限的技术排查入口。

### 1.1 继承的业务约束

- 全部关注基金进入多周期预测，不要求先持仓，不受个人实验订阅限制。首批沿用五日、二十日、半年，不扩大成一次实现所有周期。
- 持仓建议综合实际接入的信息给出明确动作及理由；短中长偏好属于建议，小金额不拒绝判断。
- 实验阶段允许预测不成熟或错误。无专用模型时使用可复现的已登记基础方法；不因没有80%正确率、没有长期显著优势、信心不足而停止判断。
- 必要数据缺失、包损坏、推理失败必须具体记录。缺失新闻、经理历史等可选信息如实说明；本轮不新增收费源、新闻大模型或外部账号。
- 更好的可运行版本进入实际实验使用，保留旧版本、选择理由、实际推理身份和故障回退。不能只训练不使用，也不能只改页面上的版本名称。
- 历史实验与每天真实预测并行。真实原文不可改写；历史回看不能称作当时已提前预测。
- 不自动交易、不改变个人模拟持仓、不扩成全市场无差别训练；保留服务端认证和本人数据隔离。

### 1.2 本轮明确替代的旧要求

- 同步中心不再展示“现在用什么方法预测”的方法卡、候选排行和研究操作表单。
- 日常效果页不展示旧二十日动作规则、去公告组，也不让用户从候选模型中选赢家。
- 上一轮刚接通的多模型扣费回放继续复用，作为后台评价工具；不删除其证据和测试来实现页面简化。
- 旧方案中研发详情需要直接放在同步中心的约定，以本方案为准；数据时间边界、回退与不可变证据要求继续保留。

效果回看必须区分：

1. **真实预测效果**：只统计当时已发出且到期的记录，显示基金数、到期/未到期/失败数量；多周期或候选多条记录不冒充多只基金。
2. **系统建议模拟效果**：按当时实际采用的版本和已发出的建议推进隔离账本，版本更换按真实生效时间衔接；与相同资金、日期、费用的一直持有比较。它仍是模拟账本，不是用户真实收益。
3. **当前模型历史模拟**：如保留，必须明确是今天的模型回看历史，作为可选详情；不能把它替代前两项，不能让它的日期选择控制后台正式选优。

## 4. 自动运行流程与职责

### 4.1 唯一编排与持久化状态

Java沿用统一多周期入口，Python沿用研究队列和模型登记。不得新增第二套会重复训练/切换的独立定时器。

一次自动周期依次推进：`WAITING_DATA → QUEUED → TRAINING → EVALUATING → REPLAYING → DECIDING → VERIFYING_ADOPTION → COMPLETED`，另有`FAILED / CANCELLED / INTERRUPTED`。每个阶段保存输入指纹、检查点、阶段错误和下一次尝试时间。无改进以`COMPLETED + KEEP_CURRENT`结束；不要伪装失败，也不要反复训练同一批数据。

后台检查接口必须快速返回，训练/大范围评价由独立有界worker执行。研究不能占满真实预测worker、连接池或数据库锁。关闭浏览器仍自动推进。

### 4.2 可直接起步的版本化默认值

以下是实验起点，不是已证明最优的参数。实施时存为一个版本化配置和hash，调整要产生新版本，不散落在前后端。

| 项目 | 首批默认与边界 |
| --- | --- |
| 自动检查节拍 | 复用现有30分钟维护入口；成功同步后可请求一次幂等检查 |
| 初次建立 | 发现从未完成过自动研究且必要数据齐备时排队一次，不要求用户点击训练 |
| 新训练日程 | 北京时间每周日02:00之后首个维护时点；未运行时恢复后补一次，不补造一周的多份任务 |
| 到期评价 | 有新成熟答案或答案修订即排队评价；没有新数据则跳过，不反复切换 |
| 训练数据跨度 | 默认最多近4年，按已保存数据和各周期成熟标签确定；不强制后台回放补齐新数据源 |
| 切分起点 | 训练24个月、验证6个月、选优6个月；按标签可知时间留隔离，半年标签不能跨进后续区间；不足时缩短可用窗口并记录协议，真正无法拟合则保留当前方法 |
| 候选范围 | 沿用现有已接入算法与配方；每周期最多3个候选，本轮不自动搜索无限算法/参数 |
| 并发 | 全局最多1个自动研究在执行，同范围最多1个排队周期；手动任务与自动任务共享资源预算和租约 |
| 基金规模 | 全部关注基金去重分页；沿用单研究最多50只等已有上限分片，固定基金集合/分片清单/失败分母后再比较，不写死44只或三只基金 |
| 历史资源预算 | 不超过已有4年/步长不少于5的研究边界；扣费回放最长732天，组合数有上限，先做规模与耗时核验 |
| 重试 | 仅瞬态接口/数据库故障有限退避，默认1/5/30分钟最多3次；数据不足等待下一数据版本，模型契约错误不无限重试 |

任务唯一身份至少包含：范围与基金集合hash、各周期、数据截止与版本、训练/评价窗口、算法/策略/费用/日历版本hash。租约过期恢复原配置，不使用恢复时的新数据替换已冻结输入。

### 4.3 时间与样本边界

- 训练样本的输入必须是当时可知的信息，答案必须在训练截止前已经成熟；标准化、阈值选择和调参也受同一边界约束。
- 验证/选优样本与训练样本分开；多周期目标跨界时按目标结束/答案可用时间清除重叠，不能只按起始日期切分。
- 每次评价冻结相同基金、日期、目标、输入版本、失败分母和费用。晚修订资料使用原可知版本；无法恢复的历史明确标记假设。
- 当前模型如果使用了评价期内的训练答案，不能拿它回测同一期间冒充公平对照。选择双方都合格的后续区间或按既定历史截止重训同配方；技术不合格则保留当前服务并继续积累公平数据。
- 已经用于选优的区间继续标为开发证据，不重复包装成独立盲测。每天真实预测另行保存并用于后续滚动评价。

## 5. 比较、自动采用与回退

### 5.1 预测与建议分别评价，统一发布证据

预测评价继续使用现有按日期/基金家族聚合的方向主指标、覆盖率、类型和月份分组；原始准确率/类别召回只作辅助，不能把上涨多数样本的高正确率当作全部收益。

方向比较先生成待选模型清单，不直接在研究循环内逐周期完成最终发布。对将供持仓建议使用的版本，后台自动组成**当前发布组合及少量完整候选组合**，使用相同 `DecisionPolicyV2` 和费用/成交规则进行扣费回放。首批最多当前组合加3个候选组合，固定生成次序，禁止无限组合穷举。

最终发布清单包含各周期模型ID/指纹和统一策略/费用版本。可只替换一个周期，其他周期保持原模型；用户仍得到完整多周期服务。若某个周期技术不合格，不用缺周期的组合宣称胜出。

### 5.2 首批确定性采用规则

1. 先检查可运行、时间合法、同题同输入和覆盖率不降低。合格候选即允许参加实验，不增加“80%正确率”“先等半年”之类门槛。
2. 预测阶段：相同主指标比较，容差沿用`1e-8`；平分优先保留当前，避免无收益切换。新训练日期本身不是优势。初次无模型时登记基础方法，不因候选暂不合格拒绝预测。
3. 综合采用阶段：在预测不劣的完整组合中，按共同基金/日期的扣费收益主指标比较，最大回撤恶化上限先沿用2个百分点；同时保存换手、费用、空仓、卖出后错过上涨及再次买入效果。聚合口径固定为每只基金等初始本金、基金家族等权，并展示各基金失败/差异，不选一只上涨基金代表全部。
4. 候选相对当前完整组合有可复现改善且满足上述条件即可自动实验采用；是否跑赢一直持有必须披露，但不把所有模型必须先跑赢一直持有作为永久停工门槛。改善可以是亏得更少，仍保留负面结论。
5. 所有组合均较差或平分时继续当前可运行组合，下一数据版本再比。方向改善但费用/回撤明显变差的候选继续后台并行，不向用户要求选择。
6. 真实成熟结果与历史开发结果分别评价，不混成同一准确率。首批可由合法历史开发证据启动实验采用；真实成熟样本齐备后优先用于后续同题判断，未到期不算错误也不阻塞其他周期工程工作。

如果在实施中发现上述双阶段规则与现有覆盖/资金口径冲突，先在S0/S1记录具体证据，按用户“后台负责选择、实验可用”的目标修正版本化协议，不回到泛化需求讨论；不能静默省略扣费比较。

### 5.3 采用事务与真实调用确认

- 重用`model_route`、`model_activation_event`及修订号CAS；增加发布清单身份，将同一组合涉及的路由更新放在同一事务内。先固定预期修订，冲突则重新评价最新当前版本，不强行覆盖其他窗口采用结果。
- 保存前/后组合、评价证据、适用范围、策略/特征版本、生效时间、旧包路径指纹及回退原因。版本必须可重新加载，不只记录名称。
- 真实预测批次冻结一个发布清单；一次批次不能前半用旧路由、后半用新路由。持仓建议保存自己实际引用的预测ID/模型ID/发布清单，不能事后按当前路由回填。
- 激活指针变化之后状态先为“等待实际调用确认”。取得真实推理、结果保存、页面/API回读、建议引用的一致证据，才记为“已实际使用”。图上出现新名字但真实记录为0条不等于采用链已完成。
- 同一日期/周期已有不可变预测时不得覆盖旧结果。等待下一合法新预测标识/窗口；若需要同日修订，先按现有唯一键和不可变契约明确追加修订规则，不通过更换任务号绕过。
- 新包不可加载、指纹错误、推理异常等技术故障使用旧可运行版本/基础方法，记录实际执行身份并有界隔离问题包。接口数据失败与算法效果差分开处理；不因一次预测错就无限训练或来回切换。
- 新版可选数据未来接入后，作为新特征/策略版本加入同一流程；不用恢复“去新闻/去公告”默认展示组来让用户判断。

## 6. 数据、接口与工程边界

### 6.1 持久化契约

优先扩展现有表与JSON快照；需要检索/唯一约束的关键字段使用真实列和索引。实现时由各仓库既有迁移表达，不绕过不可变证据触发器。

| 对象 | 必须保留的业务字段 |
| --- | --- |
| 自动周期 | cycleId、唯一请求键、协议版本、范围/数据hash、阶段状态、租约/心跳、触发原因、重试次数、下一次检查、错误及关联runId |
| 数据切分与评价 | 训练/验证/选优截止、labelAvailableAt边界、计划题集hash、成熟/未成熟/失败计数、主辅助指标、历史/真实证据类别、评价水位 |
| 发布清单 | releaseId、各周期modelId/hash、预期/实际revision、策略与费用hash、旧releaseId、采用/保持/故障回退原因、实际调用确认状态 |
| 简洁运行摘要 | 数据更新时间、最近预测批次、去重基金总数及成功/部分失败/全部失败数量、周期项数量、自动改进是否运行及具体错误 |
| 效果摘要 | 统计范围、基金去重口径、记录模式、到期水位、收益/回撤/费用、当时版本序列、一直持有对照、缺失日期说明 |

### 6.2 接口分层

- Python仅内部服务Token调用，接收公共基金/模型/研究范围；个人持仓与用户ID留在Java。
- Java负责权限、本人关注/持仓范围、管理员研究权限和前端中文摘要；后台可重复请求必须幂等。
- 复用维护/研究/状态接口；确需新增接口由S1-03固定请求、响应、权限、分页及错误码，避免前端直接拉全量模型包和巨大回放输入。
- 技术详情保留管理员权限和分页，普通用户仅拿业务摘要。失败时保留上一份结果的原时间，并明确本次更新失败，不把旧数据显示为刚生成。
- 不引入新消息平台、训练平台或付费部署依赖。研究结果/曲线分页或摘要读取，避免定时刷新返回全部frames。

## 7. 30个实施步骤与完成条件

每行只有在完成条件实际满足后才可在进度页标为完成。依赖和实时状态在进度页维护。

| 编号 | 工作 | 完成条件 |
| --- | --- | --- |
| S0-01 | 核对三仓库、规则、基线和进程 | 读适用AGENTS/技能；保存HEAD、脏文件边界、实际服务版本及启动方式；确认不覆盖无关修改 |
| S0-02 | 核对已有自动链与真实引用 | 追踪维护/研究/选优/路由/推理/保存/页面/建议，记录已有和缺失部分及真实/静态证据 |
| S0-03 | 固定首批协议与交接验收范围 | 冻结数据切分、候选、费用、比较规则、资源和日程版本；确认复用边界，更新本方案实际映射 |
| S1-01 | 落地自动周期/发布状态与迁移 | 幂等键、检查点、租约、发布身份、索引、回滚兼容完整；旧历史报告可读 |
| S1-02 | 落地统一版本化运行配置 | 数据就绪、日程、预算和阈值有单一权威来源及hash；缺失/无效配置明确失败 |
| S1-03 | 固定摘要和技术接口契约 | 定义运行摘要、效果摘要、技术详情的权限/分页/错误；内部调用保持Token边界 |
| S1-04 | 去重、租约与阶段状态检查 | 重复调度、多实例、租约过期、取消/恢复和CAS冲突均有相关检查；失败不吞成完成 |
| S2-01 | 接入自动研究触发 | 初次/每周/同步后检查无人点击可排队，数据未就绪等待，重复维护不重复训练 |
| S2-02 | 实现成熟标签滚动窗口 | 训练/验证/选优按可知时间隔离；跨期和半年未成熟答案不能泄漏；不足有明确路径 |
| S2-03 | 复用训练并输出候选包 | 当前/候选真实登记、加载、推理、文件hash一致；研究输出不提前逐周期发布 |
| S2-04 | 接入历史与真实到期评价 | 成熟/修订水位推进同题评价，分母和证据类别独立；无新数据不重复评价 |
| S2-05 | 完成资源隔离与研究恢复 | 长任务不阻塞日常预测；阶段中断从冻结检查点恢复；重试和资源上限可观察 |
| S3-01 | 自动生成完整候选组合 | 当前加少量候选，周期齐全且身份明确，固定组合顺序，不人为挑选最好区间 |
| S3-02 | 接入公平的扣费策略比较 | 相同基金/日历/本金/费用/成交/策略；无法恢复数据、失败日期和分红处理明确 |
| S3-03 | 固定胜出/保持/不合格决策 | 预测质量、净收益、回撤与覆盖按第5节执行并保存原因；无改进不中断日常预测 |
| S3-04 | 原子采用及真实使用确认 | 发布清单CAS一致；真实推理→保存→页面/API→建议身份一致，指针更新不单独算完成 |
| S3-05 | 故障隔离、回退与恢复 | 包损坏/不兼容/推理失败能回退并保留原身份；避免抖动，恢复后按协议重新评价 |
| S4-01 | 简化同步中心 | 移走研发卡片/研究表单；保留同步进度、基金数量、时间、失败重试且无重复导航 |
| S4-02 | 核对关注页和持仓结果 | 用户不选模型也获得周期预测及明确建议；小金额/未持仓/无订阅原行为不回退 |
| S4-03 | 提供受控技术排查入口 | 采用/保持/回退原因和版本按需可追溯；普通用户接口越权被拒绝 |
| S4-04 | 补齐日常页面边界体验 | 首次无结果、等待数据、任务运行、部分失败、旧结果、窄屏和刷新一致，有真实页面检查 |
| S5-01 | 建立真实预测效果摘要 | 只使用实际发出且成熟记录，按基金去重并分周期，未到期/失败独立统计 |
| S5-02 | 建立实际建议版本序列账本 | 按当时报告及采用时间推进模拟，考虑成交/费用/在途资金/再次买入，与一直持有同条件 |
| S5-03 | 提供简洁效果回看 | 默认只看系统与一直持有；真实效果/历史回看清楚分开，无候选选择或误导性最优结论 |
| S5-04 | 校验修订、分页与数据隔离 | 原报告不重写，修订追加；分页去重正确，普通账号只看授权范围，无模型条数冒充基金数 |
| S6-01 | 执行相关静态与契约检查 | lint/type/build及有意义的边界/回归测试通过，列出实际范围，不以数量代替真实链路 |
| S6-02 | 执行真实数据自动闭环验收 | 无手动训练点击，从自动触发到比较/真实调用/保存/读取取得可复现证据；自然未胜出如实保持 |
| S6-03 | 执行权限、故障和恢复验收 | 技术错误回退、并发冲突、重启恢复、无认证/跨账号请求实测并区分受控夹具 |

| 编号 | 验收场景 | 通过条件与必要证据 |

- 执行窗口从S0-01开始，不重做需求讨论；新进度表才是本轮工作位置。先查看实际工作区并保护其他窗口修改。
