## 1. 先说清当前做到哪里

### 已完成的基础，不等于已完成预测

- [x] 历史净值可生成股票型特征快照：当前有 24 条 `M3_STOCK_FEATURE_V1` 快照，包含 5/20/60 日收益、20 日波动率和 60 日最大回撤。
- [x] 已有单股票型、20 个交易日的可回放基线评分/回测/发布状态机代码和公共基金详情的受限“模型/回测摘要”。
- [x] 已删除偏离产品目标的分析运行控制面、人工基准表单和外部解释骨架。
- [x] 已有“我的关注”详情路由和本人关注关系校验。

### 尚未完成的用户目标

- [ ] 关注详情没有“未来趋势预测”模块，也没有 7/15/30/60 天预测卡。
- [ ] 没有真实 `forecast_result`、真实 `backtest_run`、`ACTIVE` 模型或用户可读概率。
- [ ] 没有已授权的基金持仓/板块暴露数据。
- [ ] 没有已授权且已关联的新闻、公告、政策事件数据；当前 M2 仍暂停。
- [ ] 没有多周期标签、特征、回测、发布、API 或提醒链路。

## 2. 实施顺序

### P0｜锁定范围和展示口径

- [x] 将产品入口固定为 `我的关注 -> 某基金详情 -> 未来趋势预测`，而非后台分析运行页。
- [x] 固定用户展示为约 7 天、15 天、1 个月、2 个月四个周期；工程初始映射建议为 5/10/20/40 个交易日。
- [ ] 确认首批试点基金类别和正式交易日历口径；推荐先只做股票型基金。
- [ ] 确认“净值历史基线”与“综合预测”的发布阈值、页面文案和最低样本量。

完成标志：每个周期和模型层级的名称、状态、数据截至日和降级文案可被产品、数据和开发共同理解。

### v1.0｜已确认的单周期学习切片（2026-09-02）

- [x] 首批仅为股票型基金、20 个有效净值日、仅净值历史输入。
- [x] 概率仅在“我的关注 -> 单基金详情”向已关注用户展示；公共详情不承载完整概率。
- [x] 训练顺序固定为：手算样本与公告日核对 -> 历史逐日样本 -> 朴素对照 -> 逻辑回归候选 -> 严格回测 -> 发布读取。
- [ ] 完成手算样本和时间可得性核对；在此之前不开始逻辑回归训练。

本切片的详细学习步骤和单周期测试见 `docs_zhx/implementation/free-data-prediction-v1.md` 与 `docs_zhx/testcase/free-data-prediction-v1.md`。它不会替代后续四周期目标；20 日通过并不自动使 5/10/40 日可发布。

### P1｜补齐可授权输入来源

- [ ] 对基金持仓、板块分类、公告/新闻/政策、市场/业绩基准逐一登记来源、授权依据、限频、刷新频率、保存期限和展示范围。
- [ ] 用最小日期窗口完成只读验权与字段样本核对；未通过时保持来源禁用，不以网页可访问替代授权。
- [ ] 设计并迁移持仓快照、板块暴露快照和事件关联的版本/时间/删除/血缘字段。
- [ ] 为每一类来源实现独立同步、失败隔离、数据水位、质量指标和手动受控重试；不能由基金详情页面触发。

完成标志：每类实际参与模型的输入均能回答“来自哪里、何时公开、是否可保存、是否新鲜”。

### P2｜构建四周期特征与标签

- [ ] 在现有单周期特征基础上，按 5/10/20/40 个交易日构建独立标签、特征版本和完整度。
- [ ] 将持仓/板块和事件特征接入时，按披露日期/发布时间执行截止校验，杜绝未来信息泄漏。
- [ ] 对每个基金、日期、周期记录实际输入覆盖；未覆盖的输入不能在解释中声称已纳入。
- [ ] 对不同基金类型分别定义允许特征和不可评分规则，不复用股票型口径到债券、QDII、FOF 或货币型。

完成标志：同一输入水位下重跑结果一致；数据不足的周期没有方向、概率或置信度。

### P3｜多周期评分、滚动回测与发布闸门

- [ ] 以非破坏性迁移扩展 `forecast_result`，支持 `horizon_trading_days` 和输入覆盖摘要；保留旧 20 交易日结果语义。
- [ ] 每个周期独立运行时间滚动训练、验证、测试，记录样本量、校准、命中、回撤、波动、基线比较和失败原因。
- [ ] 先发布“净值历史基线”；持仓、板块和事件覆盖与时效达到阈值后才允许发布“综合预测”。
- [ ] 每个周期独立审核、激活、暂停和回滚；任何一个不合格周期不得输出概率。

完成标志：至少一个试点基金类别存在真实回测证据和已发布模型；无真实回测不得称为预测已上线。

### P4｜受限读取 API 与关注详情接入

- [ ] Python 提供只读、多周期、白名单化的基金预测摘要；不接收用户身份，不在读取时评分。
- [ ] Java 增加仅面向本人已关注基金的预测读取接口；未关注统一拒绝，缓存不能携带用户授权结论。
- [ ] Vue 在 `WatchlistFundDetailPage.vue` 实现四张预测卡、依据展开、数据缺口、加载/陈旧/错误/未发布状态。
- [ ] 公共 `FundDetailPage.vue` 与关注详情明确分工：公共页不替代关注预测；已有摘要只能作为基础信息。

完成标志：用户从“我的关注”进入单基金详情即可理解每个周期的结论或不可用原因；浏览器只访问 Java。

### P5｜解释、提醒和运行保障

- [ ] 只在真实已发布预测后，允许 DeepSeek 根据已使用的白名单事实生成解释快照；不让大模型生成或修改概率。
- [ ] 为已关注用户实现按周期、状态变化和已授权事件的站内提醒；去重、冷却、日上限和本人隔离由 Java 负责。
- [ ] 配置评分/回测/消费的并发、超时、重试、失败隔离、数据漂移和发布/暂停操作手册。

- [ ] 执行真实数据库、真实授权来源、三端端到端和回滚演练验收。

## 3. 依赖关系

```text
P0 产品与周期口径
  -> P1 授权输入与数据血缘
  -> P2 四周期特征
  -> P3 回测与发布
  -> P4 我的关注详情预测
  -> P5 解释、提醒和运行保障
```

P4 的页面壳可以提前开发，但在 P3 没有真实已发布结果之前，只允许显示“预测准备中”和具体缺口，不能显示任何方向百分比。

## 4. 恢复工作的第一步

下一次实际开发优先执行 P0 中尚未确认的试点类别/交易日历阈值，并开始 P1 的**只读来源验权**。持仓、公告或新闻来源一旦涉及新付费、授权、保存范围或自动采集，必须先完成相应确认，不能直接接入。
