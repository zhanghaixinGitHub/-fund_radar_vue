## 1. 先用通俗的话说清楚

**离线训练、复现及比较已经完成。002112 的同一批 230 个开发日期，A 对 111 天，B 对 115 天，C 对 121 天。** B 比 A 多对 4 天，C 比 B 多对 6 天；但两者都没超过始终猜下跌的 122 天，且下跌命中低于 A，均未通过预先固定的筛选规则。本轮未证明新增资料达到继续实验的要求，不追加调参。完整真实证据见第 13 节。

训练采用“002112 自身历史＋固定的 10 只参照基金”。每只参照基金都用自己的净值和持仓，不能把别的基金的经历算成 002112 自己的经历。002112 自身完整的持平记录仍只有 18 天，单独使用它自己的资料仍未达到原定门槛。

本轮只比较三种固定做法：

| 做法 | 模型能看到什么 | 要回答的问题 |
| --- | --- | --- |
| A：只看净值 | 基金过去的涨跌、波动、回撤等 7 项资料 | 作为同条件起点，单靠净值能判断到什么程度？ |
| B：再看持仓 | A 加上当时已公布的持仓及对应股票表现，共 16 项 | 持仓信息是否有帮助？ |
| C：再看大盘 | B 加上沪深 300、中证 500 的近期表现，共 20 项 | 大盘资料是否还有额外帮助？ |

三种做法使用**完全相同的训练记录和检查日期**，算法和参数也一样。这样才能把差别归因于新增资料，避免一个模型挑容易的日期，另一个模型承担困难的日期。

本轮完成后必须给出：三个模型各自判断了多少天、对了多少天，上涨/持平/下跌分别表现怎样，以及新增资料是否值得继续验证。结果不理想也应如实结束这一轮，不能不断换参数直到出现好成绩。

**“训练完成”不等于“已在页面使用”，也不等于“准确率提高”。** 本文主体负责离线训练和比较；后续实验采用及真实效果检查的边界见第 9 节。

## 3. 训练目标和不变的规则

### 3.1 一日模型究竟预测什么

用基准交易日 T 及此前已获得的资料，预测紧接着的下一个交易日 U 的**单位净值方向**。周末和休市日不算一个交易日，不能简单使用日历日期加一。

例如，基准日单位净值为 1.0000，下一交易日为 1.0020，则真实答案是“上涨”；为 0.9980 则是“下跌”；两者原始数值完全相等才是“持平”。先比较原始十进制净值，再计算展示用涨跌幅，不能因为显示四舍五入为 0.00% 就把它改成持平。

这是单位净值方向，不是包含分红再投资、手续费的持有收益。训练报告应同时说明这一口径，不用方向命中率推算用户赚钱多少。

## 4. 开始训练前固定这一轮资料

同步任务仍可能继续补资料。训练期间三个候选不能各自读取一次不断变化的 `ready.json`，否则会使用不同数据。

实施要求如下：

1. 通过现有 `execution_lock()` 取得与持仓维护一致的锁，读取一次就绪清单。
2. 对该清单指向的数据包、来源快照、原文、有效期、交易日历和方案进行只读复验；失败则结束为“资料复验未通过”，不进入拟合。
3. 将这次的数据摘要、来源摘要、方案摘要、完整样本日期、产品家族、标签、权重、输入顺序和依赖版本写入独立运行清单。
4. 一次读出 20 项完整输入，三个版本分别取前 7、16、20 项；保留行级身份用于生成逐日对比结果。
5. 使用完成校验的同一份内存数组和运行快照训练。快照创建完成后可释放资料维护锁；后台即使产生新包，也不会改变本轮输入。
6. 对训练运行另做互斥和幂等控制。相同数据、方案、代码和环境的重试复用已完成阶段，禁止重复消耗全部训练预算。

原 `training_inputs()` 仍读取当前资料指针；本轮已通过 `verify(reference=..., publish=False)` 和独立运行目录完成**指定快照读取适配**，保存完整逐行日期、来源、标签及权重。A/B/C 从同一已验证内存数组截取列，不循环调用该函数重新选资料。

资料来源有留存期限，快照不能延长原许可。校验发现到期时，停止使用该来源；按现有权限重取并生成新版本，或如实标记受阻。禁止修改到期时间让检查通过。

## 5. 三个模型怎么训练

### 5.1 固定配方与预算

沿用现有多分类逻辑回归及标准化方式。通俗理解：先把不同单位的输入转换到可比较的尺度，再让模型学习三种方向与这些输入的关系。第一轮不增加深度学习、树模型、额外调参或新的付费服务。

| 项目 | 固定值或规则 |
| --- | --- |
| 三个版本 | `NAV7`、`NAV7_HOLDINGS`、`NAV7_HOLDINGS_MARKET` |
| 配方 | `C=1.0, solver=lbfgs, tol=1e-8, max_iter=1000, random_state=0`，与既有 `RECIPE` 一致 |
| 标准化 | 只在训练集上计算，使用既有家族权重；开发集只转换，不参与拟合 |
| 样本权重 | 使用训练包已验收的权重，不按开发集成绩调整，不另加过采样或持平类别权重 |
| 类别顺序 | `DOWN, FLAT, UP`；分数相同按 `FLAT, UP, DOWN` 决定方向，沿用现有三分类规则 |
| 线程与复现 | 沿用单线程限制；记录 Python、numpy、scikit-learn、threadpoolctl 版本与相关代码指纹 |
| 拟合预算 | 每个版本主训练 1 次、同配方独立复现 1 次，总计最多 6 次 |

预算按实际进入拟合的尝试记录，包括出现收敛错误的尝试。复现失败或预算耗尽时记录技术失败，不在后台悄悄更换种子、加次数或改参数。数据检查、指标统计和从已保存模型推理不算新的拟合。

标准化、模型参数、特征顺序及类别顺序必须完整保存。优先沿用项目可核验的 JSON 参数形式；禁止把本地模型路径或不可信序列化对象作为普通用户输入。

### 5.2 现有训练代码不能直接照搬的地方

- `direction_1d_three_state_training.fit()` 和 `direction_1d_three_state.predict()` 目前绑定原来的 7 项净值输入。16/20 项候选需要独立、严格校验维度的离线适配，不可仅修改已有模型的特征名称。
- `fund_exposure_features.study()` 是原单基金研究检查入口，其行为包括保留“不足以训练”的历史结论；它不是本轮跨基金训练器，不应修改它以绕开原门槛。
- `direction_1d_three_state_training.train_registered()` 会读取既有训练人口并登记模型；本轮不能调用它替代独立候选训练。
- 原一日推理按基金分组选择模型。002112 专用候选不能登记成所有混合基金的默认模型，否则可能误影响其他基金。

已新增 `app/services/fund_002112_training.py`、`fund_002112_training_model.py`、CLI `scripts/fund_002112_train.py` 和 `tests/test_fund_002112_training.py`。原资料复验器仅增加指定内容地址的只读参数；复用现有资料重算、权重、三分类和文件留存能力，没有新建采集程序。

### 5.3 每个版本的完成条件

1. 主训练和唯一复现使用同一组输入、标签、权重与配方，类别必须包含三种方向。
2. 训练过程无收敛警告、无非有限数值，模型维度与版本匹配。
3. 两次模型的核心参数及规范化模型摘要一致；生成时间、运行编号等日志字段不参加模型等同性比较。
4. 从保存的模型参数还原推理，与训练库输出的三类分数最大绝对差不超过 `1e-12`，方向一致。
5. 两次都能对同一批 230 条目标开发记录产生合法结果，且每条可追溯到模型和输入。

任一候选失败保留已完成文件和错误原因，其他独立候选可继续完成；缺少候选不能补写成绩，也不能出具“三种做法均已完成”的结论。

## 6. 怎么判断新增资料有没有帮助

### 6.1 主比较只看 002112

训练可以使用参照基金，成绩主表只能统计 002112 的 230 个相同开发日期。参照基金训练成绩不能宣传成 002112 的准确率；拟合时见过的数据也不能作为最终考试。

每个版本至少输出以下结果：

| 指标 | 通俗含义与统计要求 |
| --- | --- |
| 正确天数 / 总天数 | 例如“对了多少天 / 230 天”；不预填任何候选的正确天数 |
| 三类命中情况 | 实际上涨 106 天、持平 2 天、下跌 122 天，各有多少天判断正确 |
| 三类混淆表 | 实际是上涨/持平/下跌时，被模型分别判成了什么 |
| 平均类别召回率 | 分别计算三类命中比例再平均；同时保留每类分母，不用一个平均值掩盖持平仅 2 天 |
| 相对 A 的逐日差异 | 新模型对而 A 错多少天、A 对而新模型错多少天、两者都对/都错多少天 |
| 分季度表现 | 原模型不重训，分别统计同一年的四个季度，检查是否只靠某一段行情获益 |
| 资料覆盖 | 合格日期和被排除日期分别统计，说明只能评价这些合格日期 |

缺少某类的季度，相关类别指标显示“该季度没有这类样本”，不得填 0 伪装测得差表现。分类分数未校准，不能在用户页面称为“上涨概率”。

### 6.2 同时提供简单参照

在同一批目标日期上，列出始终猜上涨、始终猜持平、始终猜下跌，以及根据训练集加权多数类固定猜一个方向的结果。这些规则不消耗拟合次数。多数类只能从训练集确定，不能看完 2024 答案再选择。

在当前 230 条开发记录中，始终猜下跌能对 122 天，始终猜上涨能对 106 天，始终猜持平能对 2 天。它们是简单参照成绩，**不是已训练模型的成绩**。三个常数规则必须全部展示，不能只选择最弱的一项与候选比较。

同条件训练的 A 是本轮主要基线。若要补充“与当前在用模型相比”的结果，必须先证明该旧模型在对应历史时点已经可用、训练截止日期合规、输入一致；无法证明时列为不可直接比较。不能把今天训练过较晚数据的在用模型回算 2024，再称为公平历史对比。

### 6.3 本轮开发筛选规则

以下规则是本实施文档为下一轮固定的**开发筛选规则**，不是已实现或已验证有效的上线门槛。首次拟合前将它写入新的运行方案，不修改原研究方案文件。

- B、C 只有在正确天数严格超过 A，且超过三个常数规则中的最好结果时，才进入“值得继续实验”的候选范围。
- 同时检查：上涨和下跌的命中数分别不低于 A，持平命中数也不低于 A；不得只靠忽略某类方向获得总数优势。
- B、C 都满足时，优先正确天数更多的版本；正确天数相同优先输入更少的 B。逐日差异和季度结果仍完整展示，不另行按结果临时换评分方式。
- 没有增强版本满足条件，结论为“本轮未证明新增资料改善目标开发表现”；保留全部模型和结果，不自动扩大模型或调参范围。
