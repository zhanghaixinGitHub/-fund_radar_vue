依据回答“系统当时为什么这样判断”，不证明真实市场的因果关系。缺少可核对材料时明确说明，不根据预测方向反向编写理由。此次没有更换模型、调整分类或修改历史结果，也没有完成准确率比较。一日保留旧二分类是历史实现边界，不能据此声称比一日三分类更准确；后续选择须基于同一周期、同一评价口径的独立验证。

## 原预测一致性

- 5 日、20 日、半年：使用已有预测原文的 `featureSnapshot` 和 `modelManifest`。基础趋势方法核对实际回看区间、涨跌与原判断门槛；线性三分类核对各类别得分和并列规则。原结论还原不一致即停止归因。到期持平带和计算时的判断门槛分别处理。
- 一日：使用保存的输入、当时登记模型和原始系数还原各指标贡献，核对原分数及方向。相同模型的两个分支去重。解释分数、贡献值不作为概率或收益率显示。没有详细依据时保留真实原预测和原输入，并提示原因暂不可用。

## 新增只读契约

浏览器请求 `GET /api/v1/watchlist/{fundCode}/prediction-1d/evidence/{forecastId}`。Java 检查登录、个人关注读取权限、已关注基金、本人档案关联，再从档案获取作业编号；不能由浏览器直接指定内部作业或用户编号。

Java 请求 `GET /internal/v1/direction-1d/forecast-jobs/{job_id}/evidence`。Python 沿用服务令牌认证及拒绝浏览器 Origin 的边界，仅接受成功且未过期的预测原文。核对原文哈希、输入哈希、登记模型哈希及原分数后返回：

- `fundCode`、`contentHash`、`inputHash`、`baseNavDate`、`targetNavDate`：原预测身份；
- `branches[]`：原分支及模型身份、方向、截距、七项输入及对应贡献。

Java 再核对基金与原文哈希。前端核对输入哈希、日期、原分支及模型身份。缺材料或不一致时不显示指标影响。读取没有训练、生成、归档或数据库写入副作用，不新增表或迁移。既有服务仍可使用旧接口，前端对新增接口不可用提供明确降级。
