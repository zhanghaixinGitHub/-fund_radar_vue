## 1. 第 4.2 节：先说明“预测多久、怎样算预测对了”

**完成标志：** 系统实际显示正确的起止日期，分红和到期涨跌核对按相同约定计算。查看 [P0、P2 的逐步状态](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p2)。

以二十日预测为例，系统需要说清楚三件事：

1. **用了哪一天之前的信息。** 例如今天生成，但最新公布的净值只到昨天，就说明“净值截至昨天”。
2. **观察从哪一天开始，到哪一天结束。** 起点根据基金下一次可按交易规则操作的日期确定；终点按约定再往后数二十个交易日。页面显示实际起止日期。
3. **最后拿什么判断对错。** 看这一整段时间的总回报方向，分红也按约定算进去。

可以假想在观察起点放入 1,000 元。到终点，把期间分红按方案假定再投入后，合计价值如果是 1,020 元，就是上涨 2%；如果是 970 元，就是下跌 3%。这是解释计算方法，不要求你真的买入。

模型今天预测“这一段整体上涨”，等终点结果出来后再核对。今天还不知道未来净值，所以现在能给的是预测。

**二十日预测看的是这一整段的结果。** 中间可以先跌后涨，也可以先涨后跌。它并不提供二十个每天的涨跌答案；如果以后要每天的预测曲线，需要另外设计。

旧一日预测原本只看单位净值，新方案准备看包含分红的总回报，所以旧成绩和新成绩分开保存，避免更改“正确答案”的定义。

原文中的字母只是在缩写这些日期：D 是输入净值截至日，S 是观察起点，E 是观察终点。页面不会要求你理解这些字母。

## 2. 第 4.3—4.4 节：全部关注基金都处理，每次结果都记下来

**完成标志：** 全部关注基金的各个开放周期都有结果或具体失败，原始记录能够查到。查看 [P2 的逐步状态](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p2)。

有更合适的模型，就用它；暂时没有专门模型的基金，先用简单、固定的实验方法给判断，再记录实际效果。

例如黄金基金的专用模型还没准备好，可以先根据它已有的净值表现运行基础实验。页面说明用了基础方法，后续仍照样核对对错。

真正连必要净值都没有时，保存失败并解释缺什么。不能编一个涨跌结果充数。

每次都记下：哪只基金、预测哪段时间、当时判断、依据、实际用了哪个模型。后来换了模型，也保留之前说过的话。

## 3. 第 5 节：更好的新模型，要真的替换到页面里

**完成标志：** 可以用实际预测记录证明页面和持仓建议用了指定的新模型，并能查到换模理由。查看 [P1 的逐步状态](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p1)。

这一节解决你提过的问题：“明明训练了新模型，为什么还一直用旧的？”

准备采用的流程是：

**训练出新模型 → 与旧模型做相同条件的比较 → 按事先规定的办法选出更好的 → 用于下一批实际预测 → 核对页面和持仓建议确实引用了它。**

举个简化例子：同一组基金、同一段时间、同样的题目，旧模型答对 55%，新模型答对 58%。在覆盖范围和其他规定条件也一致时，新模型可以作为当前更好的实验版本使用。

这不代表它以后一定保持 58%，也不需要先等到 80% 才允许使用。后续每天继续记录它的实际表现。

新模型暂时没有胜过旧模型，也可以在后台同时出一份答案，继续比较。页面会明确哪个是当前主模型，哪个还在对照。

如果新模型文件损坏、程序无法计算，可以暂时切回能运行的版本，同时记清楚原因。一次猜错不会马上触发换模型。

原文中容易困惑的词：

| 词语 | 意思 |
| --- | --- |
| 登记 | 把新模型放入系统可识别、可调用的清单 |
| 并行候选 | 新旧模型同时作答，分别留结果作比较 |
| 激活 | 把某个版本设为实际预测要使用的模型 |
| 回退 | 新版本运行出问题时，切回之前可运行的版本 |
| 版本/指纹 | 用来辨认实际用了哪个模型，防止只改名字、实际没换 |

## 4. 第 6—7 节：把各种信息变成有理由的持仓建议

**完成标志：** 已接入的因素真正参与建议，动作和理由能复核；新公告等来源也完成本批对照。查看 [P4](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p4) 和 [P5](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p5)。

例如某只基金同时出现这些情况：

- 五日预测偏弱，二十日预测偏强。
- 最近波动和回撤增加。
- 基金经理发生变化。
- 有一条与其主要投资行业有关的公告。

系统需要按明确规则判断这些信息各自有什么影响，再给出建议，并解释支持和反对的原因。不会因为“换了经理”就直接认定应该卖出，也不会把没有接入的新闻写成已经分析过。

个人短线/长线偏好影响综合建议看重哪个周期。持仓金额和仓位用于考虑操作规模与费用，不决定基金自身是好是坏；只有十元持仓也照样可以得到卖出建议。

原文出现的“模型占 60%、其他因素各占 20%”“分数超过某个值就加仓”，**是我给第一版提出的可执行起步规则，还没有证明这些数字最好，也不是你已经决定的固定规则。** 后续要用历史回放比较和调整。

原文的“买入用一半现金、减仓卖出一半”等比例，首先用于模拟实验，让不同方案能在相同条件下比较。它们不会自动操作你的真实资金。

## 5. 第 8 节：用过去的行情加快改进，同时每天预测未来

**完成标志：** 跑出一次实际历史对照，能看到预测错误、扣费表现及与一直持有的差异；真实到期观察另列。查看 [P3](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p3)、[P4](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p4) 和进度页的 O 项。

准备同时做两件事：

| 做法 | 怎么做 | 用处 |
| --- | --- | --- |
| 历史训练和回放 | 假装回到过去某一天，只看当时能知道的信息，生成预测和建议，再往后模拟 | 现在就能检查过去多段行情中的表现，不用只等每天新增一个结果 |
| 每天真实预测 | 用今天实际收到的信息给判断，原样保存，到期后核对 | 检查离开历史练习题后，模型是否仍然有效 |

历史资料还要分开用途：较早部分用于学习，随后部分用于调整方案，再留一部分检查调好的方案。不能看到后面的答案后，回过头修改规则，再称自己当时预测正确。

持仓回放也不只看“卖出后有没有跌”。它要模拟：卖了多少、费用多少、钱何时到账、什么时候买回来、是否错过上涨，最后与一直持有比较。

这样可以分别发现：预测模型有问题、综合建议规则有问题，还是频繁操作和费用拖累了结果。

## 6. 第 9 节：每天怎么运行，失败时给你什么解释

**完成标志：** 自动和手动任务实际可用，失败原因具体、可以按条件重试，旧结果日期不会混淆。查看 [P2](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p2) 和 [P6](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p6)。

后台检查是否有新数据、是否到了生成时间；有新的有效预测期次就生成并保存。同一期重复点击，不会无限增加相同记录。

页面保留手动生成入口，同步中心可以批量处理全部关注基金。旧一日预测有原来的时间要求；新多周期预测可以按你点击时的真实时间建立有效观察区间，不补造过去的预测。

出现问题时，页面应说明到这种程度：

- “需要 21 个净值点，目前只有 12 个，补齐后可重试。”
- “交易日历缺少对应日期范围，无法确定本次观察起点。”
- “净值服务请求超时，本次没有生成，点击重试。”

上面都是示例。实际页面必须使用真实错误原因。如果保留上次成功结果，会同时标明它是哪天的，以及这次更新失败。

## 7. 第 10—15 节：开发怎样保证上面的功能可靠

**完成标志：** 22 项验收有实际结果，数据、权限、历史记录和回退均验证通过；不能只看代码写好。查看 [P6 的逐步状态](fund-prediction-holding-decision-progress-2026-09-22.md#stage-p6)。

这些章节主要交给开发执行。它们与你有关的结果如下：

| 技术章节 | 对你意味着什么 |
| --- | --- |
| 数据表与历史记录 | 原预测和建议保存下来，不被新版本覆盖；以后能查清当时依据 |
| 接口与权限 | 页面能拿到正确结果；你的持仓和报告不会被别的用户读取 |
| 页面交付 | 关注页看预测，持仓页看综合建议，失败原因清楚可见 |
| 实施阶段 | 先打通新模型实际采用和全关注预测，再补强回放、综合分析及新增因素 |
| 验收用例 | 用正常、缺数据、服务失败、切换模型等场景验证，不能只看代码写完 |
| 上线与回退 | 更新后确认真正生效，出问题能恢复，历史记录不丢 |

你验收时可以直接看这六件事：

1. 我的关注基金是否都被处理，每个周期都有结果或具体失败原因？
2. 当前模型是谁，找到更好的后，实际有没有换过去？
3. 持仓建议是否整合了真实的信息，理由能否看懂？
4. 历史回放是否说明费用、比较对象和实际效果？
5. 今天发出的判断是否原样保存，之后能核对对错？
6. 出错时是否说明原因，旧结果是否明确标注日期？
