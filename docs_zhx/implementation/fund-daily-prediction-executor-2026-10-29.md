## 续办文件和处理方式

`run.json`、完成守卫、补充结果及正式审阅文件沿用项目的 `hash/payload` 留存格式。`--reviews-file` 和 `--blocked-file` 是普通UTF-8 JSON；原始文件、旧输入和失败历史保持原样。

综合用途审阅映射以实际基金代码为键，每项包含：

```json
{
  "本基金六位代码": {
    "fund_code": "本基金六位代码",
    "target_nav_date": "本次真实目标日",
    "materials_path": "本基金实际整理资料路径",
    "note": "当前聊天阅读后形成的具体用途审阅说明，遵守原长度及证据标准",
    "resolutions": []
  }
}
```

可选 `notice_identity_reviews` 逐条传原入口所需的 `entry/source/catalog_source/scope/note/quotes` 及适用的 `identity_proof/manager_anchor/product_name`。`prediction_event_reviews` 逐条传 `article_id/source_hash/note/quotes`。这些字段仍经原文逐字校验；记录后重新同步公告和刷新标准衔接，不直接改成功状态。仅身份或事项审阅时可暂不传 `materials_path`，处理后继续准备综合包。

处理完上述资料审阅后，以同一目录和 `--reviews-file <实际文件>` 再执行。周期状态 `READ_AND_JUDGE` 提供真实冻结输入路径及应写的 `review.json` 路径，格式沿 `scripts/fund_codex_prediction.py` 原契约。必须阅读后逐周期写入标准哈希审阅文件，再执行同一通用命令，它会正式导入、归档、读回。来源变化时追加冻结版本，不覆盖原冻结输入。

`ASSEMBLE_OWN_MATERIALS`、解析未支持、原件待解析或 `ACTION_REQUIRED` 都是内部工作，当前聊天必须继续处理、做有限兼容修复和相关回归。命令非零退出码不是结束理由。只有真实来源、权限、身份冲突、完整阅读后仍无法支持方向或原日历确实不覆盖，才按原规则提供有实际尝试、原件摘要及基金/周期/目标绑定的外部回执。

外部回执原件不改写。续办器按原始输入摘要留存绑定；资料实际变化后，旧回执从当前视图移出，记录 `INPUT_CHANGED_RETRY_REQUIRED`，重新补查/审阅。来源仍无变化时复用，不能自动续写取得时间。错过窗口保留原目标 `MISSED_DEADLINE`，另期开独立运行。
