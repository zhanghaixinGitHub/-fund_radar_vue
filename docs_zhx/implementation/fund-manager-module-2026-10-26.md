# 基金经理模块实施与本机验收

日期：2026-10-26；最近数据库回查：18:20 北京时间。依据：[设计基线](../design/fund-manager-module-plan-2026-10-26.md)。

已完成顶部“基金经理”菜单、目录检索、经理详情、基金双向跳转和管理端更新，三端在本机真实连通。入口为 `http://127.0.0.1:5173/fund-managers`。这是已收录资料范围，不代表全市场经理已补齐；尚存的数据与验收缺口列在下方。

## 已实现的行为

- 经理目录支持姓名、公司、任职范围、基金类型及分页，查询条件保留在站内路由中。重复姓名保留本基金锚点，不自动归并人员。
- 经理详情沿用左侧分区，展示在管基金、历史任职、职业履历、具体基金任期表现及相关披露。未知项保留暂缺，管理规模和未核实的产品数不展示空零卡片。
- 原市场基金继续进入原详情；外部新发现的份额有独立基础详情，不借用其他份额净值，不自动加入关注、交易、预测、评级或日常净值范围。
- 任期回报复用已有现金分红再投方法；回撤使用同一增长序列。年化仅在可核对区间不少于365日时提供。完整任期与最近连续独立管理阶段分别展示，不把共管业绩归为个人收益。
- GET 只读已发布公共快照，页面可见时每60秒刷新，隐藏或卸载停止。后台更新沿用既有总批次最后一个阶段；管理员可独立重试。同一请求编号及范围返回同一任务。
- Java 验证 FUND_READ / SYNC_JOB_READ / SYNC_JOB_START，Python 沿用内部身份与来源校验。经理、基金、任期和快照归属均验证；公共缓存不含个人关注或持仓。

## 三端契约与持久化

Python 新增7张隔离表：`fund_manager`、`fund_manager_identity_evidence`、`fund_manager_profile_version`、`fund_manager_related_fund`、`fund_manager_tenure_version`、`fund_manager_coverage_snapshot`、`fund_manager_metric_snapshot`。`source_sync_run`仅增加可空的冻结范围和结果字段。迁移 `20261026_39` 已在当前本机 PostgreSQL 应用，未执行生产操作。

任期修订保留旧观察；每个稳定任期至多一个当前有效版本。每位经理在短事务中发布，失败保留上次完整快照；来源读取不持有写事务。目录分页绑定不可变版本。原件使用哈希定位，放在已忽略的 `data/fund-managers/sources/`。

Java公开接口以 `/api/v1/fund-managers` 为前缀，提供目录、经理详情、基金分页、履历、任期表现、披露、关联基金基础详情及基金经理链接。更新入口为 `POST /api/v1/sync-jobs/fund-managers`，状态为同路径 `/latest`。内部对应 `/internal/v1/fund-managers`，不允许浏览器传入任意URL或本机文件路径。

来源每页最多5000条、最多20页；拒绝重复页、跨人错误返回和中途失败。复用来源授权、共享数据库锁与跨进程请求预算；经理来源调用保守限制60次/分钟，同机Tushare总体不超过200次/分钟。没有增加新的定时器或更改自动化配置。

设计集成决策已修订：FUND_MANAGERS直接加入现有MARKET_ALL末尾，阶段分母从实际列表计算；保留既有预测结果核对阶段和分析门槛。未为了验收触发完整分析批次。
