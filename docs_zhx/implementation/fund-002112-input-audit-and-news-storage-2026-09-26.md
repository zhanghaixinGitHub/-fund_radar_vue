## 2. 新闻存储设计与当前实施范围

现有 `news_item`、`news_source_reference`、`market_event`、`event_relation` 保留业务职责。它们要求业务审核、置信分数或完整时间戳，无法完整表达这批日期级历史研究卡，不能通过编造分数和时分秒满足字段。

本次新增两张 PostgreSQL 研究表，沿用 SQLAlchemy、Alembic、已有本机 `fund_ai` 配置和有超时的存储连接池：

| 表 | 保存内容 |
| --- | --- |
| `news_research_bundle` | 研究集合、版本、解析版本、来源文件和 SHA-256、上下文、前版身份、实际入库时间 |
| `news_research_card` | 每份完整卡和原分析；可检索的基金/公司/目标日/公开日期/公告身份/原文摘要/事件主题和阶段；置信分数、业务/预测/训练资格分别保存 |

原文 PDF 和提取文本仍保留文件，数据库保存定位及摘要，不复制 PDF 二进制。JSONB 保存原完整结构，金额、单位、经济阶段、原文页码/锚点、未知事项、旧新信息及持仓报告版本不会压缩成一段摘要；索引字段用于定位，读回时与完整内容核对。

数据用途固定为研究，`LOCAL_ANCHORS_VERIFIED` 仅表示本地来源摘要及锚点核对，不等于自动语义正确。12 份样例的置信分数为空，业务展示、预测使用和训练使用三项资格均为 false；不会进入现有已审核事件查询。事实保存不以预测获胜为前提，之后业务投影和预测输入仍应依据各自资格实施。

公开来源只有日期就存 `date`；`created_at` 是本次实际入库时间，不冒充 2024 年已经取得资料。未知值保留 null，空金额列表表示没有结构化提取到金额，不表示金额为零。一文多事保存主题列表，一事多文保留多份证据，不累加计划、实际支付、保证余额或月报/日报重叠金额。

## 3. 一致性与失败处理

- 整批一个事务，任何卡片或读回不一致都会全部回滚。同一研究集合用事务锁串行提交，避免并发重试造成半批或重复版本。
- 同版本、同内容的重试返回原身份；同版本内容不同直接拒绝。更正使用新版本并显式指向前版，保留原内容，禁止分叉覆盖。
- 数据库触发器阻止对已保存研究版本和卡片直接更新、删除。业务资格和空置信分数也由数据库约束保护，不依赖页面处理。
- 迁移只新增两表、索引和保护函数，不改现有业务表。未导入时允许回退空表；已有数据时普通 downgrade 拒绝删除，需要单独备份和处置决定。本轮不会执行破坏性回退。
- 本次仅有独立本地命令入口，不增加对外接口、自动抓取、定时任务、外部大模型或付费调用；无需启停 Java/Python 服务。
