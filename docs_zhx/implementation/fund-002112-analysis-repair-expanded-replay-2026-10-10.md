# 002112 公告、引用和日期修复及扩大历史回放

日期：2026-10-10。范围仅为 002112；本轮没有训练基础大模型或拟合分类器。

本轮完成代码修改、测试和 60 天历史回放。原 20 天生成失败从 9 天降至 3 天，但没有证明方向准确率提高：全部共同有效 42 天，新分析 24/42（57.1%），旧净值加行情 26/42（61.9%）。扩展样本新分析为 15/25（60.0%），低于同日期恒跌基线 16/25（64.0%）。解释真实性仍有已确认问题，不能宣称已经全部修复或具备采用条件。

## 验证边界与冻结方案

最终运行版本为 `20261010-history-replay-v5`。原 20 天只作为工程回归样本；新增此前最近 40 个同口径合格日期，范围为 2026-06-17 至 2026-08-12，共 60 天。所有日期都进入过既有历史数据集和季度滚动研究，不能称为全新独立验证；其中部分扩展日期也在本轮工程诊断阶段使用过。

固定在目标日北京时间 08:30，判断该日单位净值相对上一交易日的上涨或下跌。只使用该时点可得的净值、已公开持仓、已收盘行情和关联公告。沿用已有资料的公开时点重建和保守可用时间，不用今天取得的正文补过去，不把披露持仓当实时持仓。

代码、输入、旧证据及比较预测的哈希在运行前写入新协议。全部计划日期先保存首次判断或失败，再统一读取答案评分。比较日期、时点一致的旧净值、净值加行情、净值行情加事件方案，以及恒涨、恒跌基线。分别报告成功生成比例、有效判断的方向准确率和全部计划日中的有效且正确比例。

本轮调用总上限 420 次，包含失败、格式修复和单独解释复核。V2—V4 工程诊断已消耗 172 次，V5 剩余上限 248 次，其中回归队列 75 次、扩展队列 173 次；分别预留最多 20 次、40 次给单独解释复核。单日最多 28 次、15 分钟。实际拟合次数固定为零。

## 核实的旧问题

- 旧实验 9 个失败日期完整保留：4 天归并失败，4 天引用或解释检查失败，1 天服务响应无法解析为 JSON。
- 旧归并由模型自由返回事件编号，程序事后拒绝跨公司、遗漏和重复，但没有从构造方式上保证正确分区。
- 长引用编号有漏前缀问题，校验只返回泛化错误码，修复时无法准确定位。原逐字校验会去除空白再比较，本轮改为输入中的连续原字符匹配。
- 2026-08-26、2026-09-29 已有比较基准日行情，成功文本仍声称缺少最近交易日行情。审校还把 2026-09-25 中秋休市日当成比较基准日；2026-09-28 的正确基准日是 2026-09-24。
- 旧非 JSON 响应只保存异常类型，无法恢复其原始正文。本轮保存完整响应正文、解析结果、用量和失败类型。

## 修复内容

程序按公司身份划分事件。原文明示具体计划名称、年度或报告期时归入同一事项；不能确认时保留为独立事项，不按事件类型强行归并。每个抽取事件必须恰好出现一次，每份输入公告必须通过解析和引用校验，处理失败明确记为失败。

每家公司提供一份综合公告依据，内部保留所有已抽取事项及各自的文件成员。相同引文去重，实际使用的依据集合去重，事项数量和文件数量没有方向分数。不同事项或同一事项的正反机制可以分别解释，但不会生成更多公告依据单位。公告、新闻、政策分别归组，政策或新闻与持仓的应用领域关联不冒充公司发行人身份，也不代表已经取得订单。程序保证的是全部输入文档得到解析、已抽取事件无遗漏无重复地分区；不能保证模型已经识别原文里的所有重要事项，也不能保证自动识别任意复杂交易的事项身份。

引用使用确定的短编号，保留完整事实身份；错号必须重新原样选择，不猜测补前缀。新增抽取通过原文片段编号选择，由程序原样取出字符；旧缓存文字引用仍需通过同样严格的逐字核对。每条引用保存文档身份、来源哈希及字符区间，数字、空格、否定和条件均不得擅自改写。无法解析的 JSON 仅允许一次有界格式修复，不补造原文或事实。

表达检查区分指数正式名称和数值复述：输入里确有“沪深300”“中证500”时，不因其正式名称包含数字而报错；财务数值和中文比例复述仍拒绝。明确的“现金分红不等于提升每股收益”不当作改善每股收益的断言，真实的改善断言仍必须有对应事实。

目标日、基准日、最新净值日、每只持仓股票和指数的行情日、截止时刻和缺口状态由交易日历和输入计算。日期说明由程序统一生成，拒绝与状态矛盾的缺数叙述，允许正确的“截至基准日”等表达。只有日期没有行情数值，也不算齐备。目标日尚未收盘属于尚未发生，不当作数据缺口。

完整引文区间、事项成员等审计索引写入独立不可变快照，页面结果保留其身份和哈希；页面原文、公司关系与全部来源保持完整。这样避免新增审计索引使原有结果大小上限被触发。该保存调用链已用替身测试，没有写真实数据库。

Java 接收端同步支持同公司依据的多份来源，逐个验证网址、日期、唯一性和解释中的对应关系，保留旧单来源兼容。公司依据可以包含完整的多事项引文，不再受原来单条 2500 字限制；整体结果仍受原有 150000 字限制。42 份成功回放的实际依据、解释和来源均已通过 Java 契约夹具测试；没有连接运行中的 Python/Java 服务或真实数据库做集成写入。

以上三次停止时各有 1 个请求没有完整返回，全部计入预算。原始文件、失败记录、输入、协议和执行代码完整保留。此前阶段没有评分，也没有读取新回放的涨跌答案来修改规则；这些重复尝试不能当作独立验证，诊断阶段的失败没有从档案中删除。

### 解释真实性和资料日期

42 个成功判断另作一次不带目标答案的解释复核，得到 7 个无问题、34 个有质疑、1 个复核失败；失败原因是审校条目缺少 refs（09-21），不是该日原判断失败。另 18 天无成功分析，不调用解释复核。这些是同一服务的第二次意见，不能把 34 个质疑直接等同于 34 个真实错误，也不能把 7 个无问题等同于完全真实。

人工针对 11 个日期留下 15 项对照记录，未改预测或评分：

- **确认的解释错误：** 07-13 环旭电子《2026年6月营业收入简报》只支持六月单月同比/环比、上半年累计同比及第二季度环比，解释却概括成“月度及累计营收同比、环比均增长”。同日长芯博创《2025年年度权益分派实施公告》写“将进行调整、将履行程序”，解释未保留股权激励价格调整的待执行状态。
- **日期正确但方向推断仍有限：** 08-26、09-28、09-29 的基准日和缺口状态正确；分析仍主要假定已发生的下跌可能延续，不能将其理解为已验证的预测规律。部分摘要仍混用基准日压力与目标日压力。
- **政策时效和传导仍有问题：** 扩展输入中的两份广东政策保存日期标为 2026 年，但来源 URL 均含 2024，其中“粤算”文件明确是 2024—2025 年计划。06-26 仍把它表述为政策持续支持；07-22 从数据中心/基站储能进一步推出光模块需求支撑，传导缺少直接证据。该结果不能解释成 2026 年新政策催化。
- **审校也会误报：** 07-20 审校称长芯博创业绩预告缺少 quote_receipts，实际存在与正文一致的逐字原文、文档身份和字符区间。07-22 审校误读政策事实身份；它是持仓应用领域关联，不是把几家公司合并成一个发行人。06-23 审校将正常解释不是逐字抄写本身当作错误，也超出了逐字引用规则的适用范围。
- **表达检查仍有漏检：** 06-17 成功解释出现“正两个百分点”，数词规则未覆盖“两”。没有改变原始引文，但说明不能仅靠正则判断所有数字转述。

本轮没有宣称全部解释真实，也没有只对审校通过的日期重新计算一个更好看的准确率。详见 `manual-semantic-audit.json` 和 `semantic-review`。
