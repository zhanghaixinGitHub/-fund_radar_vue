## 1. 当前恢复点

当前可复用基线：

- fund_ai 已有 24 条股票型基金特征快照；forecast_result、backtest_run 和 analysis_model_release 仍均为 0 条。
- fund_core 已有 alert_rule、signal_snapshot、notification 表；当前只完成本人提醒规则的幂等配置，不会生成通知。
- Vue 已能展示基金的基础事实和详情，但没有可发布的 M3 评分、回测或提醒结果。
- 浏览器到 Java、Java 到 Python 的服务边界、服务令牌、认证会话和审计基础已存在。

当前不得开始的动作：

- 不调用新的外部资讯、公告、基准、社交或交易接口。
- 不创建方向评分、回测结果或站内通知。
- 不将现有 43 个基金市场描述为全市场或已具备真实投资预测能力。

恢复本看板前先核对三个仓库均处于同一版本，并阅读关联需求、设计、验收文档。若来源、模型口径或用户提醒策略发生变化，先更新需求和设计，再改变任务状态。

## 2. 启动门槛

以下三项由业务确认后才允许进入 M3-01：

1. 试点范围：首个基金类别、目标周期、已授权输入来源、数据截至时间和最小样本量。
2. 模型准入：滚动回测窗口、费用口径、长期持有/定投/基准比较方式，以及上线或暂停阈值。
3. 用户呈现：评分状态文案、提醒冷却时间、单日上限、历史保留期限和仅关注基金规则。

任何一项未确认时，可继续维护基础资料同步和数据质量显示，但 M3 必须保持无方向、无概率、无提醒投递。

## 6. 实施中的强制边界

- 所有用户范围必须由 Java 的 CurrentUserContext 导出，禁止前端提交 userId 作为数据范围依据。
- fund_ai 与 fund_core 不允许跨库直写；跨服务只使用已认证的内部接口。
- 非 SCORED 结果不得写方向、概率或置信度；未发布或暂停模型不得触发通知。
- 任务重复运行必须依赖业务唯一键、内容哈希、去重键和消费水位，不依赖内存标志。
- 日志使用 模块.方法   >>> 前缀，带 TraceID、模型版本和业务计数；不得记录 Token、Cookie、完整个人数据或原始外部响应。

## 7. 每阶段验证与恢复

测试用例按 docs_zhx/testcase/m3-decision-assistance.md 执行。测试结果只证明对应场景，不等同于授权来源、真实模型有效性或生产发布。

任一阶段失败时：

1. 停止后续阶段，不推进实施看板状态。
2. 保留当前已提交版本和运行审计，记录失败条件、影响和恢复前置。
3. 若已经有 ACTIVE 模型，先切换为 SUSPENDED，停止新评分和通知。
4. 修复后从最后成功的数据水位或消费 checkpoint 重试；不得删除历史派生数据来掩盖失败。

## 8. 完成定义

M3 只有在以下条件全部满足时才可标记完成：

- 每个输入来源已获授权并完成授权、刷新、保留和展示登记。
- 已确认试点基金类别、目标周期、回测基线与准入阈值。
- 特征、评分、回测、模型发布、信号消费和提醒均可追溯、幂等、可恢复。
- 未通过准入、数据不足、来源陈旧、服务故障和用户无权场景都安全降级。
- 用户只能收到本人、已关注基金的站内风险解释；系统不存在任何交易执行能力。
- TC-M3-01 至 TC-M3-10 已按批准环境完成，且真实运行与回测证据独立归档。
