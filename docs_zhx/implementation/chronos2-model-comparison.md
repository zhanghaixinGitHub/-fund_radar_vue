## 4. 先固定“比较的究竟是什么”（C03）

### 4.1 两种方案及共同对照

| 方案 | 核心输入与计算 | 训练/校准范围 | 用于比较的结果 |
| --- | --- | --- | --- |
| A：自训练模型 | 同一已知历史序列计算七项指标，现有 L2 逻辑回归 | FIT 训练基础模型，CALIBRATION 拟合独立校准器 | 未校准分数、校准分数和方向 |
| B：Chronos-2 | 同一已知历史的 61 点 `growth_index`，单基金独立预测 | 预训练权重保持不变；CALIBRATION 只拟合概率校准器 | 原始方向分数、校准分数、方向、预测分位数 |
| C：简单对照 | 复用始终上涨、历史上涨频率、20 日动量等已有规则 | 需要历史标签的规则只使用 EXAM 前已可得答案 | 同一评分器计算的成绩 |

“相同输入条件”指相同已知原始资料、历史范围和截止时点。A 使用摘要指标、B 使用完整序列，是两种方案本身的差异，不能说它们的输入张量完全相同。首轮不额外给 B 更长历史、其他基金、指数或新闻，也不自动启用跨基金 cross-learning。

原有模型和报告保留。旧模型只有在模型哈希、口径、FIT/CALIBRATION 样本指纹均一致时才能复用；否则用同一自训练方法产生新的研究副本，不覆盖旧产物。

### 4.2 两种模型必须回答同一个日期问题

当前实际标签是：从截止日及以前最近的交易日 `label_base_date` 起，到 cutoff 之后第 20 个交易日 `label_end_date`，现金分红再投总回报是否大于零。不能用早期“累计净值高低”或“后面 20 条有数记录”替换。

- `anchor_nav_date`：截止时已经公告的最后一个净值日，是模型能看到的输入终点。
- `label_base_date`：答案的起算日；当日净值可能尚未公告，不得提前塞进输入。
- `anchor_lag_sessions`：上述两天相差的交易日数，沿用现有 0 或 1 的限制。
- A 与 B 必须共用同一 `label_up_20d`。标签按现有 12 位总回报口径，正数为 1，零和负数为 0。

Chronos-2 从 anchor 后开始预测，因此预测长度应为 `20 + anchor_lag_sessions`。lag=0 预测 20 步；lag=1 预测 21 步，第一步对应答案基准日，最后一步对应答案终点。不能固定取第 20 步造成比较日期错位，也不能因缺净值顺延终点。

### 4.3 Chronos-2 的数值如何转为可比较分数

Chronos-2 提供各未来时点的分位数，并不直接返回本项目定义的“20 日上涨概率”。尤其 lag=1 时，起点也未知，两个时点的边际分位数不能直接当成收益差的联合分布。

首轮采用一个固定的研究适配办法，C03 在看新比较成绩之前写入协议：

```text
end_median = 答案终点对应的预测中位数
base_reference = lag=0 时的最后已知 growth_index
                 lag=1 时答案基准日对应的预测中位数
scale = max(答案终点 q90 - q10, 1e-8 * max(abs(最后已知 growth_index), 1))
chronos_raw_score = (end_median - base_reference) / scale
```

- 这个值只是方向强弱分数，不叫上涨概率；分位数之差也不叫收益置信区间。
- B 的原始方向由 `chronos_raw_score > 0` 判断。主概率比较使用独立校准后的分数。
- CALIBRATION 中以真实二元标签拟合一维 sigmoid 校准器，沿用固定 L2、基金均衡权重、单类别拒绝及正斜率检查的现有思路。A/B 各自拟合，各自绑定基础模型和资料哈希；不把 Chronos 对象伪装为 `LogisticModelArtifact`。
- 比较表必须写“Chronos-2 冻结权重 + 本地概率校准”。不能把这一整条流程宣传成完全无需标签的零样本概率预测。
- 预测含非有限值、分位数顺序异常、无效基准值或校准失败时，记录失败原因；不默认填 50%，不静默回退到 A。
- 若今后要评估分位数直接反推概率、其他输入表示或微调，另建试验；不能看到本轮成绩后追加多个方案只保留最好的一种。

### 4.5 用哪些成绩判断

主表比较 **A 校准后与 B 校准后**，原始分数及简单对照作为辅助。只对成对的相同样本计算差值，同时单列全部应考样本的覆盖与失败情况。

| 指标 | 用人话解释 | 规则 |
| --- | --- | --- |
| Brier 分数（主指标） | 百分比与真实涨/不涨答案的距离 | `mean((p-y)^2)`，越低越好；先逐基金平均，再对基金等权平均 |
| 对数损失 | 是否出现很自信却预测错误 | 越低越好；仅计算对数时将概率裁剪到 `[1e-8, 1-1e-8]`，A/B 一致，原始分数保留 |
| 方向准确率、平衡准确率 | 方向猜对多少，以及是否只偏向多数类别 | 概率严格大于 0.5 判涨；单类别导致未定义的指标记为空并说明 |
| ECE / 可靠性分箱 | 说七成的那批预测，实际是否接近七成 | 沿用固定分箱，保留每箱样本量；不能单凭 ECE 宣布可靠 |
| 覆盖率与失败率 | 有多少预定题目真正给出了结果 | 固定日期计划作分母；分别列数据不足、模型失败和共同有效样本 |
| 耗时与内存 | 好一点是否需要明显更多资源 | 分开记录下载、首次加载、冷启动和预热后的同批预测；同机器/线程预算 |

每条误差按 `(fund_code, cutoff_date, label_end_date)` 配对。20 日标签互相重叠，误差不是独立样本；差值区间采用按交易日成块、跨基金同步重采样，默认块长 20、重采样 2000 次、随机种子 42、95% 区间，全部写入 C03 协议。主窗口任一基金少于 5 个完整的不重叠 20 交易日共同有效块时，不作明确胜出判断；不能把缺失日期压缩拼成连续时间块。区间只是本轮探索的误差估计，不解除资料和预训练独立性限制。

“历史探索中较好”的默认标准：主窗口宏平均 Brier 差值的 95% 区间不跨零，至少两只基金方向一致，第三只没有显著反向劣化；覆盖情况可比，没有通过漏算困难样本获益。否则写差异不明确或仅某基金较好。该规则是本次研究比较约定，不是业务发布阈值。

如果某方案只在共同子集分数好、却有更多失败，不宣布整体优胜；报告应分别说明分数与可用性。即使 A 胜过 B 或 B 胜过 A，两者都不及简单对照时，也要明确“相对较好，但尚不值得采用”。

- 操作：准备独立研究环境，拟放在 `.local-runs/chronos2-runtime/`；核心服务环境保持稳定。CPU 起步，小批量；GPU 仅在现有设备可用时试用。
- 产物：兼容性报告、计划安装的精确版本、模型文件大小和预计下载等待、CPU/内存/单批/超时预算。依赖冲突通过研究环境隔离处理，不直接升级主服务。
- 验收：得到可执行的安装方案，无新增付费服务；这一步不运行数据库查询或训练。

### C03｜生成冻结的比较协议

- 输入：第 4 节方案及 C02 兼容结果。只读取官方元数据和已有协议，不看新的考试成绩。
- 操作：锁定 `amazon/chronos-2` 的确切 revision、文件哈希核验方式及依赖版本；把三基金、61 点输入、20/21 步映射、三时间窗、校准、评价、覆盖与运行预算写入 `protocol.json`。
- 产物：协议版本、SHA256、原模型信息、预训练重叠审查、应考日期清单。该研究协议单独命名，不能改正式 DRAFT 规则为 APPROVED 或伪造规则冻结回执。
- 验收：能够在训练/推理前判断一个输入属于哪段、为什么可用，以及运行后如何判定差异；协议改变必须产生新版本。

### C04｜准备共同资料

- 输入：明确的现金版本批次 ID，不能扫描整个库后自动挑分数最好的批次。
- 操作：复用批次恢复、日期先行、只读一致性事务和哈希检查，取出完整历史路径；单独导出 FIT/CALIBRATION/EXAM 答案。推理输入结构不含 `offline_label`、未来数值或未来质量标记。
- 产物：`inputs.jsonl`、隔离的 `labels.jsonl`、`dataset_manifest.json`、覆盖与排除原因。完整 61 点必须来自原批次中的历史路径，不用七个指标反推，也不拼接当前修订值。
- 验收：A 的七列指标能从同一历史路径复算；B 的 61 点、anchor、基准日和终点一一核对。记录源版本及现金完整性未获证的限制；有问题拒收，不插值、补现金或篡改答案。
- 最低条件：至少主窗口达到原数量条件并能做有效比较。资料不足可继续 C05/C06 的独立开发，但 C04/C08 不因此勾选完成。

### C05｜实现模型适配与评价

- 操作：安装 C03 锁定的研究依赖和官方权重；缓存于 `.local-runs/model-cache/`，核对哈希后本地推理，不上传基金资料，不使用云端自动部署示例。
- A：通过现有纯计算入口拟合/恢复逻辑回归和校准器；保持原产物格式和能力。
- B：使用独立适配器读取 61 点、逐基金分组、预测正确长度，按第 4.3 节生成分数；在专用研究产物中保存校准参数及权重 revision，不塞进旧模型类型。
- 共同评价：同一接口记录原始分数、校准分数、日期、输入/模型指纹、耗时和失败原因；冻结 EXAM 预测文件后才加载 EXAM 答案评分。
- 验收：未装 Chronos 依赖或权重不可用时，只有研究命令报告明确错误；原 Python 服务和自训练入口仍可运行。

### C06｜必要的正确性验证

- 日期：lag=0/1 分别映射 20/21 步；节假日、跨年、公告延迟、缺数和保护期均覆盖，不能顺延标签终点。
- 时间隔离：改变未来答案不会改变历史输入或原始预测；校准只接收 CALIBRATION；A 的标准化与拟合只接收 FIT。
- 一致性：同一数据协议下双方样本键一致；冲突、过期/损坏模型、非有限数、分位数异常、单类别校准和超时均保留失败记录。
- 评分：用可手算样本核对 Brier、方向阈值、覆盖分母和成对差值；不把重复/重叠题当成独立证据。
- 回归：执行受影响的现有历史训练/校准及现金样本测试；必要数据库测试用隔离 schema，实际导出事务证明只读。测试替身只用于边界测试，不能代替 C07/C08 真模型证据。

### C07｜小批量真实试跑

- 三只基金分别选择协议允许的少量日期，覆盖 lag=0/1 中实际存在的情况；缺少的边界由 C06 人工数据覆盖，并注明。
- 使用实际下载权重，检查目标日期、61 点输入、原始分数、校准输出和 JSON 回读一致性，记录冷/热耗时及内存。
- 试跑数据来自开发范围，不用新考试成绩反复挑参数。试跑成功只证明可执行，不能给出“谁更准”的结论。

### C08｜固定协议下的真实批量比较

- 按预定顺序运行全部窗口和全部应考清单；FIT/CALIBRATION 共用已冻结的可用样本条件。未满足原门槛的窗口明确保留不足状态。
- 先保存各方案 EXAM 预测与哈希，再统一关联答案；不得让某方案逐条偷看答案调整输出。
- 失败重试只补失败条目，必须保持输入、协议及模型哈希一致；不得覆盖已成功预测或只保留最好的随机运行。
- 输出双方全部有效样本成绩、共同样本成绩、逐基金/逐窗成绩、差值区间、简单对照和资源统计。超时/缺数列出完整原因，不删除难题后改分母。
- 完整性核验通过后最后写 `complete.json`。如果只有不足报告，C08 保持待条件，C09 可以先交付阶段诊断。

### C09｜中文比较报告

## 7. 验收和异常处理

| 情况 | 应有结果 |
| --- | --- |
| 权重下载失败或CPU速度不足 | 给出具体失败/实测预算；调整有界批量或恢复下载，不偷偷切收费API |
| 输入或日期冲突 | 拒绝该条并保留原因，两方覆盖报告都可见 |
| 某窗口训练/校准样本不足 | 保留不足，不改时间段、门槛或借用EXAM标签 |
| B输出错误/超时 | 标记B失败，A正常结果保留；不冒充B成功 |
| 校准后更差或没有稳定差异 | 如实报告，不删除原始结果或继续调到胜出为止 |
| 历史首次版本/预训练独立性未获证 | 报告明确历史探索范围，不转成正式发布证明 |
| 所有模型均不及简单对照 | 对比可有真实结论，但不宣称模型有应用价值 |

本阶段完成标准是有真实、同条件、可解释、可复跑的比较证据。不能仅以“所有测试通过”“模型已加载”或“页面能显示数字”替代。
