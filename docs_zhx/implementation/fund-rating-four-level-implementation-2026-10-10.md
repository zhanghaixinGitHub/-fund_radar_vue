# 基金四级评级实施方案

日期：2026 年 10 月 10 日

状态：以下保留原设计与候选规则；三端实现和本地验证已落地，真实等级尚未开放。当前进度、验证证据及外部资料缺口见[实施与验证记录](fund-rating-four-level-delivery-2026-10-10.md)。

基金市场以「偏弱、一般、良好、优质」四个等级展示基金评价，基金详情新增「基金评级」菜单，集中解释评级依据。评级只评价基金本身，同一基金在相同日期、规则和数据下，对所有用户给出相同结果。

**八个维度全部计入总评级。必要资料不足时显示「暂未评级」，不得删掉缺失维度、补零或重新分配权重凑出结果。** 这是本次已确认的范围。

本文将已经确认的产品要求与候选计算规则分开。四级名称、区间、八维全部计分、列表与菜单分工属于已确认要求；权重、数据门槛、统计方法、更新频率和分类实施顺序属于本次提出的工程方案，需在实施时通过资料核验和试算固定，不代表已验证的行业标准。

## 1 产品要求和交付边界

### 1.1 已确认要求

| 项目 | 确定规则 |
| --- | --- |
| 评价对象 | 基金及具体份额本身，不读取个人持仓、年龄、资金量、风险偏好或持有期限 |
| 内部计算 | 保留 0—100 的数值，用于计算、核验和映射等级 |
| 对外展示 | 普通用户页面不展示总分、分项分数、权重或计算版本 |
| 四个等级 | 偏弱、一般、良好、优质 |
| 市场列表 | 原「历史评价」位置仅展示评级标签或必要的不可用状态 |
| 详情入口 | 左侧新增「基金评级」，位于「同类对比」之后 |
| 详情内容 | 总等级、八维依据、主要优势和不足、比较范围、评价日期、资料限制 |
| 缺失处理 | 关键资料不足时暂未评级，不能归入最低等级 |
| 八维范围 | 收益能力、风险控制、风险收益性价比、业绩稳定性、管理与策略、持仓结构、规模与流动性、费用水平 |

评级不依赖用户是否关注该基金，不使用未来走势预测的分数或概率，也不输出买入、卖出或个人适合程度。日常页面保留「历史评价不代表未来收益」这一简短边界，不重复增加大段提示。

### 1.2 本次文档和后续实施的关系

本文最初为实施设计稿；本次实施按用户明确要求开展三端代码、数据库迁移隔离验证、真实资料盘点和页面验收。原候选参数不因此变为已验证标准。范围仍不包含生产部署、付费采购、接入新账号或对外发布。

目标覆盖基金市场的基金类型；按类型和资料条件逐步开放真实评级。未完成专用规则或资料不合格的类别仍可浏览基金事实，但保持暂未评级。不能把「页面已经有四种标签」当作评级功能已经全部交付。

不顺带增加评级排序、筛选、通知、自动交易或预测功能。我的关注列表本期不增加标签；公共详情组件可复用，但不得借此绕过关注详情原有的本人关系校验。

现有净值模型同时含单位净值、累计净值和调整后净值字段，但字段存在不等于已经证明可以直接用于本次总回报计算。现有管理费、托管费也不能证明全部份额的持续费率已经齐全。现有持仓资料任务还包含仅允许 `002112` 的范围限制，不能当作全市场持仓已经覆盖。

2026 年 9 月 29 日总方案中提出过六维评分和直接显示数字分数。本次就基金评级专项采用八维、四级、独立菜单的新要求；旧文档的预测、账户和新闻部分不在本次范围。实施时更新正式需求和设计中的冲突段落，不能同时维护两套现行评分口径。

## 3 四级映射与状态

### 3.1 等级区间

| 内部总分 S | 等级代码 | 中文名称 | 解释 |
| --- | --- | --- | --- |
| `0 <= S < 50` | `WEAK` | 偏弱 | 在本次同类比较范围内，综合表现较弱 |
| `50 <= S < 70` | `AVERAGE` | 一般 | 综合表现一般，部分方面有待改善 |
| `70 <= S < 90` | `GOOD` | 良好 | 综合表现较好，主要方面比较扎实 |
| `90 <= S <= 100` | `EXCELLENT` | 优质 | 综合表现突出，各主要方面较好 |

依据用于计算的确定性高精度结果划分区间，不先四舍五入到整数。例如 `49.999999` 为偏弱，`50` 为一般，`69.999999` 为一般，`70` 为良好，`89.999999` 为良好，`90` 和 `100` 为优质。

内部保留原始计算值与统一存储精度的最终值，映射只使用持久化的最终值。建议最终值为 `NUMERIC(20,12)`，明确舍入方式并测试边界；不得出现 Python 按原值、Java 按两位小数分别判级。负数、超过 100、无穷、NaN 和空值均不能映射为四级之一。

等级描述限定在该类别、该区间、该样本范围。优质不是低风险、保本或未来上涨概率；不同类别的同名等级不构成跨类别优劣榜。四个等级不预设人数比例，也不为了出现优质基金调整分界。

### 3.2 可用状态与等级分开

| 状态 | 列表文字 | 是否返回当前等级 | 详情行为 |
| --- | --- | --- | --- |
| 有效评级 | 偏弱／一般／良好／优质 | 是 | 展示同一份完整依据 |
| 首次读取中 | 评级读取中 | 否 | 显示加载状态，不产生临时等级 |
| 缺少必要资料 | 暂未评级 | 否 | 明确缺少哪项资料，已知事实仍可查看 |
| 该类别规则尚未就绪 | 暂未评级 | 否 | 说明该类型尚无完整评级依据 |
| 超过评级有效期 | 评级待更新 | 否 | 可展示明确标注日期的上次结果 |
| 网络或服务故障 | 评级暂不可用 | 否 | 可重试读取；不能改写成数据不足或偏弱 |

「暂未评级」「评级待更新」「评级暂不可用」都是状态，不是新增等级。无法获取评级不影响基金名称、净值、原有涨跌和分页显示。

## 4 页面和交互

### 4.1 基金市场列表

正常状态只显示一个紧凑标签，例如 `基金评级：良好`。保留原有基金名称、代码、关注标识、涨跌及净值日期；不在列表增加八维卡片、分数、长解释或后台状态。

评级标签可进入 `/funds/{fundCode}?section=rating&from=...`。基金名称及原主区域仍进入基金基础资料。`from` 沿用现有白名单和分页、关键词、类型参数，返回列表后位置与筛选条件保持一致。

当前整张基金卡片是 `RouterLink`，实施时必须拆成主内容链接和评级链接两个同级交互区域，保留原布局。不在一个链接内嵌另一个链接，也不仅靠阻止冒泡实现跳转。键盘 Tab 可访问两个入口，评级链接的可访问名称包含基金名与等级。

标签沿用现有圆角、间距、字体和 CSS 变量。用文字区分等级，颜色只作辅助；不直接复用涨跌红绿来暗示买卖，不通过颜色表达收益保证。390px 窄屏、1440px 桌面和键盘操作均需验收。

列表原「数据截至」仍仅表示净值日期。评级日期在评级详情说明，不能把当日净值日期冒充评级日期；若评级已失效，列表必须转换为评级待更新，不能继续无提示展示旧优质标签。

### 4.2 基金评级菜单

菜单顺序为：基础资料、净值走势、基金经理、份额规模、分红记录、同类对比、基金评级，后续投资与动态等分组保持现有顺序。

本期必须接入 `fund-detail`。公共组件可供关注详情复用；若同步开放 `watchlist-fund-detail`，在分红记录后加入同名菜单，读取同一公共评级，但仍先通过该页面的关注关系校验。不得要求用户先关注才能在基金市场看评级。

### 4.3 详情内容层次

页面依次展示：

1. 基金名称、综合等级及一句主要判断。
2. 评价范围与日期，例如「与本站已核验的同类基金比较」「截至某月末」「考察近三年」。
3. 八维依据表：维度名称、该维度等级、可复核数据与一句解释。
4. 最多三条主要优势、最多三条主要不足；有几条真实依据就展示几条。
5. 必要的数据限制及官方来源入口。

示例仅用于界面设计，以下内容不对应截图中的任何真实基金：

```text
示例基金                         基金评级：良好
近三年收益在同类中较好，但回撤控制仍有不足。
评价截至：2026-09-30             考察区间：近三年
比较范围：本站已核验的同类基金    样本：以实际结果填写

收益能力             良好       展示实际收益、期间和同类比较依据
风险控制             一般       展示最大回撤、波动和期间
风险收益性价比       良好       说明承担风险所获得的历史回报
业绩稳定性           良好       说明固定观察窗口中的表现
管理与策略           一般       展示任职、变更和策略执行事实
持仓结构             一般       展示集中程度、报告期和披露范围
规模与流动性         良好       展示资产规模和流动性测算条件
费用水平             良好       展示统一条件下的费用比较
```

总分、分项分数、版本、公式、内部任务号不进入页面、悬浮提示或折叠区。收益率、最大回撤、费用率、日期、样本数是业务依据，可以展示。不得用「表现稳定」「管理优秀」替代实际证据。

在未形成总评级时，八维仍可展示已核验事实；对缺失维度写明暂缺。未通过同类样本门槛时，不对现有少量事实生成分项等级。没有总评级的页面不得通过综合文案暗示优质或良好。

## 5 分类与数据准入

### 5.1 按实际投资类型比较

页面左侧大类仅是浏览分类，不足以直接作为评级分组。评级分组至少考虑资产类型、主动或被动、投资地区、币种、股票仓位区间、行业主题、期限或信用特征、份额适用人群以及交易形式。

| 类型 | 分组与专用重点 | 开放条件 |
| --- | --- | --- |
| 主动股票、偏股混合 | 风格、仓位、行业主题、地区与币种；历史收益与风险、管理连续性、组合结构 | 先实现本方案八维候选规则，逐个细分类别开放 |
| 纯债、短债、混合债券 | 久期、信用、权益和可转债暴露；信用与流动性资料 | 专用八维指标及权重全部完成，不能套权益公式 |
| 可转债 | 与纯债分开；股性、债性、集中度与波动 | 独立类别及八维规则通过 |
| 被动指数 | 同目标指数或经证实等价的投资目标、币种、交易形式 | 管理与策略重点评价跟踪偏离，补跟踪基准与交易成本 |
| 货币基金 | 同币种与可比申赎机制 | 使用真实收益分配、期限与流动性资料；不能用接近不变的单位净值计算高夏普 |
| QDII | 按底层股票、债券、商品等继续分类，增加地区、币种和时区条件 | 净值日期、海外交易日、汇率和披露时差可复核 |
| FOF | 股票、债券等目标配置与策略相近 | 可穿透底层基金、识别重叠持仓与费用，不能重复计费 |
| 其他或无法归类 | 不猜测类别 | 暂未评级，补分类后再评估 |

第一批按类别实施，不代表只交付四维。任何实际发布的总等级都必须来自该类别完整的八维配置。后续类别不得静默回退到主动权益配置。

### 5.2 产品去重与份额差异

同一产品的 A/C 等份额不会当作多个独立产品扩充样本。以来源证实的产品关系为准，不能只靠名称、代码相似或数据库中的某个主键认定关联。

建立有生效日期、来源和核验记录的产品及份额关系。每个产品预先选定一个代表份额：限定同一币种和可比购买资格，优先选择历史完整的常规零售份额；多个符合条件时按成立时间、代码稳定排序。不能按事后收益最高或费率最低来选择代表。

同一产品各份额的实际净值表现和费用分别计算，所以 A/C 可以得到不同等级；产品层面的经理、组合、规模资料可以共享，但必须标明口径，不能把产品总规模在多份额之间相加。

### 5.3 候选门槛

以下为本方案建议的初始门槛，实施阶段需验证覆盖与偏差后固定：

- 主动权益首批：至少连续三年可核验收益历史，拥有月末起点和 36 个后续月末观察值。
- 同一细分类别至少 30 个资料合格、已去重的基金产品。份额数不代替产品数。
- 总评级的八维必需指标全部满足资料与时间条件；任何一维缺失，该份额暂未评级。
- 同一类别一次计算使用相同截止日、窗口、收益定义、币种、规则与比较样本。
- 无法解释的净值异常、分红遗漏、份额折算、币种混用、分类矛盾或来源冲突应阻断受影响对象。
- 不使用本人关注列表作为评级样本库，也不为达到样本数扩大到不可比类别。

门槛 30 和历史三年是候选工程选择，不是引用机构方法的原样复制。现有代码出现过 30 的盘点提示，也不证明当前任何类别已经合格。

## 6 八维评分候选规则

### 6.1 首批主动权益权重

| 维度 | 候选权重 | 在总评级中的作用 |
| --- | ---: | --- |
| 收益能力 | 20% | 中长期净值总回报的同类位置 |
| 风险控制 | 20% | 最大回撤和下行波动 |
| 风险收益性价比 | 15% | 相同口径下的风险调整后收益 |
| 业绩稳定性 | 15% | 固定观察时点的持续表现 |
| 管理与策略 | 10% | 管理连续性与可核验的执行事实 |
| 持仓结构 | 10% | 同策略范围中的发行人和行业集中程度 |
| 规模与流动性 | 5% | 规模对应的资产变现能力与持有人集中风险 |
| 费用水平 | 5% | 统一比较条件下的全部相关成本 |
| 合计 | 100% | 八维缺一不可 |

总分 `S = Σ(w_k × D_k)`，各维度 `D_k` 为 0—100。权重不按用户变化，不因为数据缺失而改变。八维并非统计独立，收益、风险和夏普之间存在关联；试算必须检查重复贡献和评级敏感性，不能宣称八维就是八份互相独立的证据。

开发用算例：八维依次为 `80、65、75、85、70、60、75、90` 时，按上表得到 `74.25`，映射为良好。该算例只校验计算，不对应实际基金，也不进入普通页面。

### 6.2 同类位置映射

先把每个指标方向统一为「越大越好」，例如对回撤幅度取负值。设被评份额之外有 `N_other` 个不同产品的代表份额：

```text
P(x) = 100 × (指标比 x 差的产品数 + 0.5 × 与 x 并列的产品数) / N_other
```

比较集排除被评份额所属产品的代表份额，避免同一产品自我比较。代表份额本身使用同一公式，对应平均名次法；相同指标得到相同分数，全部指标相同时为 50。指标比较前按规则固定精度，不靠任意浮点 epsilon 决定并列。

一批已准入产品及代表份额先冻结；一个原定成员发生技术计算错误时，不能临时剔除它再重算剩余基金。业务资料不合格可以在冻结前排除，必须记录原因及样本覆盖。冻结后资料被证实错误则中止该类别批次，形成新输入批次。

维度分算完后直接按权重合成总分，不再把总分重新转成百分位来强行安排优质比例。评级改变可能来自自身变化、同类变化、样本变化或规则变化，内部必须可区分。

### 6.3 八维的具体计算

本节给出主动权益首批可编码的候选方案；各项阈值和输入都须在试算前锁定。其他类别另建完整配置，不能只替换标题。

| 维度 | 候选计算 | 必需资料及解释边界 |
| --- | --- | --- |
| 收益能力 | `0.3 × P(近一年总回报) + 0.7 × P(近三年年化总回报)` | 采用分红再投资总回报序列；与业绩基准比较作为补充依据，不再对同一收益重复加分 |
| 风险控制 | `0.7 × P(-近三年最大回撤幅度) + 0.3 × P(-近三年下行波动)` | 最大回撤按日频收益指数计算；回撤修复时间作为事实展示，未修复写明未修复 |
| 风险收益性价比 | `P(近三年夏普比率)` | 全类使用相同可核验的无风险收益序列；不能缺少无风险数据就默认零 |
| 业绩稳定性 | `P(25 个固定滚动一年窗口的同类胜出比例)` | 每月末一个观察窗口，与冻结样本同一窗口的中位数比较，并列计半次 |
| 管理与策略 | `0.5 × P(现团队连续任职月数，上限 36) + 0.5 × P(-近 36 月团队变更次数)` | 仅量化管理连续性，不声称测得经理能力。投资策略及有证据的重大变化另外说明，并用于分类适用性检查 |
| 持仓结构 | `0.5 × P(-发行人集中度 HHI) + 0.5 × P(-行业集中度 HHI)` | 同策略细类、同披露口径；需要可重建的完整股票持仓和行业分类，不能只用前十大推算完整组合 |
| 规模与流动性 | `0.7 × P(标准五日变现覆盖率) + 0.3 × P(-最大单一持有人比例)` | 基于已披露持仓和规模的统一情景；不是承诺五日内实际可赎回。最大持有人数据必须有可核验精度 |
| 费用水平 | `P(-统一一万元持有一年情景的总成本率)` | 管理、托管、销售服务、标准申赎及适用交易成本均纳入；统一条件，与个人账户无关 |

管理连续性分只是在综合评价中低权重衡量可持续观察的记录。不能把成立早、经理年龄大、规模大直接解释成质量高。团队改善后的变更也可能降低该候选维度，因此试算必须检查这种偏差；若不能接受，调整整类规则并重新验证，不能对单只基金人工加分。

### 6.4 公式与时间窗口

建议采用最近已结束自然月的最后估值日为 `T`，月度评级。所有日期按相应估值日历处理，业务展示使用 Asia/Shanghai 时间；涉及海外数据时保留来源时区。

设经核验的总回报指数为 `I_t`，日收益为 `r_t = I_t / I_(t-1) - 1`：

- 一年总回报：`I_T / I_T-1Y - 1`。
- 三年年化总回报：`(I_T / I_T-3Y)^(365.25 / 实际间隔天数) - 1`。
- 最大回撤幅度：`max_t(1 - I_t / max_(u<=t)(I_u))`。
- 下行波动：`sqrt(252 × mean(min(r_t, 0)^2))`，主动权益首批使用日收益、零收益目标；不能混称为标准差。
- 夏普比率：`sqrt(252) × mean(r_t - rf_t) / sample_std(r_t - rf_t)`。无风险收益必须转换到相同日区间、币种及计息基础。标准差为零或输入不足则无效，不能输出无限高分。
- 稳定性：取 `T` 向前 36 个月的月末总回报指数 `I_0...I_36`，评价窗口终点为第 12...36 月，共 25 个完整一年窗口；胜出记 1、并列 0.5、落后记 0，再除以 25。窗口高度重叠，不把 25 次观察当成独立概率试验。

日频指标使用真实估值日历，节假日不补交易收益；应有但缺失的估值日不前向填充。窗口端点取对应日历的有效估值日，同类别一律使用相同规则。年化因子 252 只适用于本节国内主动权益配置，不能原样用于货币收益分配或不同市场日历。

收益序列需要统一分红和折算处理。累计净值端点相除不自动等于分红再投资总回报；来源调整后净值也必须核验定义和除息样本。已体现在净值中的管理等费用不从历史收益再扣一次，费用维度独立衡量成本水平。

### 6.5 管理和持仓指标补充约定

团队按照来源披露的完整在任名单识别。一个生效日内的多个变更合并成一次团队变化，不凭空指定首席经理；已公告未生效的变更单独作为事实，不提前改任期。任职记录覆盖不完整时不能把「没查到变化」当作零次变化。

发行人 HHI 为完整股票资产中各发行人权重平方之和，行业 HHI 为同一股票资产中各行业权重平方之和。权重分母与实际股票资产总额一致，保留股票占全基金净资产比例，不把股票内部结构当作全资产结构。关联证券先合并到同一发行人，行业采用固定有效版本；未知行业不能当成一个真实行业或默默剔除。

行业主题基金只与足够相近的主题及策略产品比较，避免因投资定位集中而天然被宽基样本扣分。高度专门化、样本不足或无法合理定义分散优劣的类别，在专用规则通过前不发布该维度及总评级。

### 6.6 规模与流动性候选情景

规模作为资产变现测算的输入，不单独按金额递增加分。候选五日覆盖率的规则为：以披露报告期末持仓 `h` 和同日估值为基准，按各证券过去 20 个有效交易日的成交额中位数，假设每日最多参与 10%，估算五日内可变现金额。

```text
证券可变现金额_i = min(持仓金额_i, 5 × 10% × 20日成交额中位数_i)
五日可用金额 = 可用现金 + Σ证券可变现金额_i - 五日内确定应付金额
标准五日变现覆盖率 = min(1, max(0, 五日可用金额 / 报告期末基金净资产))
```

该口径适用于能取得完整交易及持仓资料的主动权益类别，是统一压力情景，不是实际成交预测。交易停牌、限售等已证实限制按其真实可售上限处理；资料未知的资产不能擅自当成现金、零风险或可售。资产类型未被情景模型覆盖时该维度不合格。净资产与持仓金额单位、币种、日期必须相同，估算不向前假装成当前实时持仓。

最大单一持有人比例若只有「超过某比例」的区间披露，不能捏造精确比例进行排名。可以在一个完整的新类别配置中使用预先规定的区间评分，但不能和精确值方案混算；首批精确值候选配置下，缺少精确且可信的资料则暂未评级。

上述 5 日、10%、20 日是待验证情景参数，不是监管阈值或已验证的最优参数。若公开来源无法覆盖这些必要数据，必须形成全类替代口径的新方案并完成试算；不能悄悄改为「规模大则流动性好」。

### 6.7 费用候选情景

统一名义本金 10,000 元、持有 365 天、固定当前费率、无投资涨跌，选用同一普通零售购买资格下可核验的标准费率，不使用用户专属折扣。这是为了统一比较，不是对用户持有期限的建议。

场外产品按照真实申购计费方式、持有期对应赎回费、年度持续费用计算标准成本率；费率基数、内扣或外扣规则都来自实际费率文件。持续费用以统一本金按适用年化费率做标准化测算，明确属于费用比较情景，不冒充某笔真实交易的最终收益。

场内产品需要另有券商佣金统一假设、买卖价差和交易成本规则，不能套场外申购费。FOF 要识别费用减免和底层费用包含关系，避免重复加总。任一必需费率、适用日期或计费规则不明，费用维度不合格。历史费用更正保留原始版本，不用当前费率改写历史评级。

### 6.8 其他类别的八维规则交付

其他类别仍保留八个维度，但每个维度的指标和权重必须适配本类。不能把八个标题配齐就认为规则完整。

| 类别 | 必须单独完成的规则 |
| --- | --- |
| 纯债和短债 | 收益及回撤之外，明确信用质量、久期、发行人集中度、可交易性及赎回压力的输入；低波动不自动表示高质量 |
| 可转债 | 识别转股价值及股性风险，选择同类基准；持仓与流动性使用可转债实际交易数据 |
| 被动指数 | 管理与策略使用跟踪误差及跟踪偏离；基准总回报、费用和分红口径匹配；不能要求经理主动跑赢指数 |
| 货币基金 | 使用真实分配收益、投资期限、信用和流动性衡量风险收益性价比；不能对近似恒定净值使用普通夏普规则 |
| QDII | 按底层类别套经批准的八维模板，再处理币种、汇率、休市和申赎限制；不把净值披露延迟当作市场风险表现 |
| FOF | 管理与策略包括资产配置执行；持仓穿透识别底层重叠；规模流动性考虑底层赎回安排；费用识别双层收费 |

每个配置的交付件必须包含八维权重且合计 100%、全部子指标公式、来源、必要数据、缺失规则、窗口、并列精度、有效期和可复算样例。未完成时该类别保持 `UNSUPPORTED`，不能在运行时临时选一个近似配置。

## 7 数据来源与资料有效性

### 7.1 数据准备清单

| 数据 | 当前可复用入口 | 必须补齐或核验 |
| --- | --- | --- |
| 产品、份额、类型 | `fund_master`、`fund_share_class`、`fund_profile` | 产品家族关系、细分类别、币种、购买资格、历史生效区间 |
| 历史净值与分红 | `nav_daily`、`fund_dividend` | 总回报定义、除息和折算处理、修订、缺日、三年共同窗口 |
| 经理 | `fund_manager_assignment` | 完整任期及团队变更；不能将本基金任期当作总从业年限 |
| 基准 | `benchmark_series`、`benchmark_nav_daily` | 授权、启用状态、同币种、收益定义、历史覆盖；基准模型存在不等于序列可用 |
| 无风险收益 | 本次尚未确认可直接复用的完整序列 | 来源、币种、期限与日计息转换，冻结历史版本 |
| 持仓及行业 | 现有基金资料服务和公开定期报告解析能力 | 全市场覆盖、完整持仓、发行人合并、行业分类、权重分母 |
| 规模和流动性 | 净值模型的净资产字段、份额规模和报告 | 单位、产品或份额范围、现金、应付金额、交易量、资产可售限制、持有人集中度 |
| 费用 | 基础资料管理费和托管费、现有费率服务 | 全部适用费用、费率版本、购买资格、计费方式；模拟费率不直接当正式评级输入 |

优先复用已有登记来源，必要时依据基金管理人官网招募说明书、基金产品资料概要、定期报告、净值和分红公告补齐。来源权限、解析覆盖或关键口径未核实的数据只能作为待核对资料，不能直接入分。

正式采集前先做范围清单与只读覆盖统计。当前覆盖盘点脚本会保存本地审计文件，不能在标为纯只读的步骤中不说明就运行。数据补齐不借机购买服务或接入新账号。

### 7.2 日期与有效期

每条输入至少区分报告期或估值日、公开日期、实际取得时间、来源修订版本；没有小时精度时不伪造时刻。本期是当前可得资料下的历史评价，不能把今天补到的数据描述为过去已生成的评级。

批次同时固定评价截止日 `T` 与输入冻结时刻 `C`。参与计算的业务生效日、估值日或报告期不得晚于 `T`，资料必须在 `C` 前真实取得且来源公开时间不晚于 `C`；`T` 后才生效的经理或费率变化不能倒算进 `T` 的指标。今天取得的历史修订可以形成一个明确标注重新评价时间的新批次，不能覆盖旧记录或伪称当时已知。未来如做历史回放，还必须把 `C` 固定到历史决策时点；缺少当时可得性证据时只称历史重建。

月度评级规则建议：

- 评价截止日为上一个已结束月的最后有效估值日。
- 历史净值必须覆盖该截止日及完整统计窗口；截止日缺失不能偷换为另一个日期。
- 当月前 5 个国内交易日可保留上一份有效月度评级；第 6 个交易日起若上月评级仍未生成，列表显示评级待更新。该宽限值属于候选配置。
- 完整持仓、持有人和规模资料按同一报告期组合；候选最长报告期年龄为 210 个自然日，超过则不能生成新评级。这个上限不等于披露及时性已经验证，仍需检查是否遗漏更近的已公开报告。
- 经理与有效费率资料核对时间建议不超过 31 个自然日；已知生效变更必须及时纳入，不能仅因文件未过期而忽略。
- 资料有效期按类别调整并固定，不允许每只基金临时放宽。季度前十大和半年完整持仓不能被当作同等覆盖。

详情分别展示净值评价截止日、持仓报告期和费用核对日。公开资料更正、类别改变、份额关系错误或已知基础资料失效时，旧评级应撤回当前展示资格，不能等待固定有效期结束。

### 7.3 缺失与异常处理

缺失、真实零值、不适用和服务故障分别记录。资料完整程度只决定能否评级，不加入基金质量分。

出现极端收益时核验净值、分红、拆分与币种。经证实为真实大幅波动时保留；不能因为结果难看就裁剪。重复原始记录按来源主键与版本去重，不用多条相同净值增加历史长度。

当某类没有任何合格样本，交付实际缺口和已核验事实，并明确该类总评级尚未开放。数据门槛不能为页面填满而下降。

## 8 服务职责与计算流程

### 8.1 三端职责

```text
管理员手动单项或一键同步
  → Java 权限校验与任务入口
  → Python 读取已同步资料并冻结类别输入
  → 八维指标计算与同类比较
  → 保存完整类别批次并核验
  → 原子切换该类别当前有效批次

普通用户页面
  → Java 评级摘要或详情接口
  → Python 读取同一已发布批次
  → 仅返回等级与业务依据
```

Vue 不计算总分或等级；Java 不重新判分，只负责用户认证、权限、输入校验、业务 DTO 和下游故障翻译；Python 负责唯一的计算、等级映射、数据核验和公共快照。

读取页面不会启动采集、训练、评分或外部大模型请求。评级说明优先使用可核验的规则模板生成，避免通过自由文本模型凭空生成评级理由。

### 8.2 批次流程

1. 确定类别配置、评价截止日和目标市场目录，检查当前任务锁。
2. 分页读取资料，核验产品关系与份额，生成候选覆盖清单。
3. 固定完整类别样本和输入清单，记录缺失原因及排除数。
4. 在冻结输入上完成原始指标、分项映射、八维组合和总等级。
5. 保存所有成员、指标、依据和未评级原因，验证数量、哈希及计算不变量。
6. 在一个事务内发布该类别完整批次并更新当前指针。
7. 独立读取列表摘要和详情核对一致性，再把任务标为完成。

一个类别计算中途失败时不发布半批结果；其他类别可以独立成功。旧批次在仍有效且未被撤回时保留，失效后按状态展示。业务资料不足属于有原因的未评级；程序异常、来源故障和任务失败不能包装成正常数据不足。

单只基金的历史净值、类别或必要指标发生变化，会改变同类百分位，因此单基金更新入口只限定问题定位和触发范围，最终重算该基金所属完整类别。不能仅改一只基金后还声称所有基金基于同一比较批次。

## 9 数据存储与一致性

评级属于新增跨服务业务数据，建议放入 Python 所用 PostgreSQL 数据库，通过现有 SQLAlchemy 与 Alembic 维护。实际目标 schema 沿用连接配置和项目约定，不另建数据库或让 Java 写入 Python 业务表。

### 9.1 拟新增对象

| 表 | 主要字段 | 粒度及约束 |
| --- | --- | --- |
| `fund_rating_methodology` | `methodology_id`、类别、配置 JSONB、配置哈希、状态、有效期 | 一份不可变八维配置；权重和公式在发布前固定 |
| `fund_rating_classification` | 份额代码、产品标识、细分类别、币种、资格、生效起止、来源引用、核验时间 | 同份额有效区间不能重叠；不得以模糊名称自动归类 |
| `fund_rating_batch` | `batch_id`、类别、方法、截止日、输入冻结时刻、输入哈希、样本数、状态、创建与完成时间 | 一个类别一次完整计算；输入和方法相同的成功批次幂等复用 |
| `fund_rating_member` | 批次、产品、代表份额、准入结果、排除原因、来源快照引用 | 每批每产品至多一个代表份额；包含排除清单，避免只留成功对象 |
| `fund_rating_result` | 批次、份额、可用状态、内部总分、等级、八维明细 JSONB、业务依据 JSONB、数据日期、有效期 | 主键或唯一键为批次加份额；有效评级必须八维完整 |
| `fund_rating_current` | 类别、当前批次、更新时刻、撤回标识 | 每类一个当前发布批次，切换具有事务和并发保护 |

输入快照保存到现有受控资料目录下新的评级子目录，例如 `ratings/inputs/{inputHash}.json`，不复用 `002112` 专项研究目录或旧 `coverage` 文件当正式结果。文件存储采用内容哈希、不可变写入及原子完成；数据库保留摘要、受控相对路径和来源引用。

原始净值表和资料表可能被后续修订覆盖，因此仅保存原表主键或内容哈希不够复算。输入包必须保存实际参与计算的规范化数值、资料版本、样本成员、日历和基准序列，或指向已验证不可变的原始版本。

### 9.2 类型和约束

- 金额用 `NUMERIC`，单位统一人民币元或明确的原币；比例内部使用 0—1，展示才转百分数。
- 总分及维度分用 `NUMERIC(20,12)`，限定 0—100；日期用 `DATE`，时刻用 `TIMESTAMPTZ`。
- `RATED` 时内部总分、等级、八维计算值必须全部存在，映射关系必须一致。
- 非 `RATED` 的当前结果必须总分与等级为空，并带明确原因；历史成功记录另存，不混在当前字段。
- 结果引用的类别、方法、截止日与批次保持一致；发布前检查 JSONB 结构、八维集合和权重之和。
- 建立结果 `(fund_code, batch_id)`、批次 `(category_code, as_of_date, status)` 和分类有效期查询索引。
- 评级表不存 `user_id` 或个人持仓；任务操作者仅进入现有管理审计。

PostgreSQL 发布事务的逻辑如下，实际 SQL 在 Alembic 和仓储中按真实列名落地：

```sql
BEGIN;
-- 锁住该类别当前指针；首次类别由类别级 advisory lock 保护。
SELECT batch_id
FROM fund_rating_current
WHERE category_code = :category_code
FOR UPDATE;

-- 先核验候选批次 COMPLETE、输入版本未失效、成员与结果完整。
-- 在同一事务中写发布状态、更新当前指针，不能先切指针后补结果。
-- 正常更新不得将截止日回退；主动回滚必须使用独立授权路径并记录原因。
COMMIT;
```

这是事务逻辑示意，不是可直接执行的迁移。实施交付必须包含完整 Alembic revision、模型约束、必要索引及隔离环境验证。迁移编号实施时根据真实 head 生成，不能抢占当前尚在变化的 revision 序号。

### 9.3 并发和恢复

类别级数据库锁保护计算或发布，不仅依赖单进程布尔值。幂等标识至少包含类别、规则版本、截止日、冻结输入哈希和样本哈希。

发布前再次检查源资料或分类是否被撤回，以及是否已有更新截止日批次；旧任务晚完成不得覆盖新结果。超时或进程终止留下的未完成批次可重试，但不能被 GET 选为当前结果。

同一批量读取请求在同一个数据库一致性快照下解析全部当前指针，再按批次读取结果。不同类别可以有各自日期；同一类别不能混读新旧批次。

## 10 接口契约

以下新增路径与字段是拟定方案，尚未在当前代码中实现。Java 继续使用现有 `ApiResponse` 外层包装。

### 10.1 普通用户读取

| 接口 | 用途 | 关键边界 |
| --- | --- | --- |
| `GET /api/v1/funds/ratings?fundCodes=001021,002112` | 同页批量摘要 | 登录及 `FUND_READ`；1—100 个 ASCII 六位代码；去重但不改变首次出现顺序 |

详情在摘要字段之上增加：

| 字段 | 含义 |
| --- | --- |
| `summary` | 由实际维度结果形成的一句业务结论 |
| `comparison` | 比较类别、币种、样本产品数、实际覆盖范围、观察区间 |
| `dimensions` | 八项名称、等级、业务原始指标、单位、区间、解释及来源引用；没有分项分数 |
| `strengths / weaknesses` | 由明确数据规则生成的主要优点和不足 |
| `dataDates` | 净值截止日、持仓报告期、经理和费用核对日期 |
| `limitations` | 缺失、披露滞后、估算假设和适用边界 |
| `previousRating` | 仅在当前不可用且存在历史结果时，返回明确标为历史的业务摘要 |

普通页面不显示 `ratingRef`、内部状态代码或方法版本。业务指标采用规范化字段，禁止把整个后台 JSON 原样透出。

详情返回的每一条 `strengths / weaknesses` 都须引用该快照中的对应维度与原始指标。候选生成规则为：按维度等级及固定业务阈值选取真实依据，优点最多三条、不足最多三条；分项全为一般时不强凑优点。整体说明不得把「管理连续性较好」改写为「经理能力优秀」，也不得把流动性情景估算改写为确定的赎回到账承诺。

### 10.2 管理任务

沿用现有 `/api/v1/sync-jobs` 前缀和权限体系：

- `POST /api/v1/sync-jobs/fund-ratings/all`：明确发起市场目录范围的评级检查与计算。
- `POST /api/v1/sync-jobs/fund-ratings/single`：请求体必须有合法 `fundCode`，按该基金识别其完整比较类别后重算；管理响应说明实际类别范围。
- 读取任务状态继续使用现有任务查询能力；确需补任务类型时增加 `FUND_RATINGS`。

触发需要 `SYNC_JOB_START`，状态读取需要 `SYNC_JOB_READ`；只有后端权限校验通过才能执行。全量与单基金使用不同入口，单基金代码为空不能触发全量。浏览器不接受来源地址、规则文件路径、SQL、权重或后台目录参数。

规则切换属于内部经验证配置发布，不在普通基金页面提供选择器。不新增用户能够自行挑选评分模型或权重的入口。

### 10.3 兼容与错误

旧 `/evaluation-status` 在迁移期间保留原含义和空分数行为，避免现有调用因字段变更失败；新前端全部切换后再清理旧组件与无调用接口。不能给旧 `score` 塞新分数而留下旧日期、旧缺口和旧「暂不评分」文字。

批量中未知基金返回该项 `NOT_FOUND`，其余项正常；已知但不具备评级资料返回 `NOT_RATED`。批次损坏或服务不可用返回服务故障，不能把所有基金变成正常未评级。

参数错误使用项目现有校验响应，鉴权失败沿用现有认证与权限响应；任务冲突为冲突状态，数据不足为可解释业务结果，内部读取故障为服务不可用。用户文案不包含原始异常、SQL、Token 或内部地址。

## 11 更新与失效

建议在手动一键同步完成基金资料、净值和相应评级输入更新之后加入评级阶段。评级是月度结果，日常重复点击可检查数据指纹，未变化则复用成功批次，不制造新计算日期。

评级阶段独立判断输入完整性，不以之前任务 HTTP 成功作为数据齐全证据。必要输入失败时本次评级不发布；不影响已经独立成功的净值刷新，也不把评级失败传播成预测输入已失败。是否继续一键同步其他独立任务沿用现有任务协调方式。

本功能不新增服务启动自动采集、周期轮询或定时评分循环。管理员手动触发可以创建有界后台任务，页面关闭后由既有任务机制继续处理，并可查询、失败重试。

一期普通评级 GET 不增加新的长期 Redis 缓存，直接批量读取小型已发布快照。若压测需要缓存，必须以发布批次作为键且传播撤回标识，不能按基金代码长期缓存。HTTP 对登录后的评级查询设置私有或不缓存策略，旧详情引用只在其仍可读取且未撤回时有效。

## 12 性能 安全和日志

首批每次任务读取最多 5,000 个份额，超过范围应拒绝并说明需分批；内部按 100—200 只分批取数，每个完整类别固定样本。上限是初始保护值，需按实际目录和内存验证，不是新业务限制的永久承诺。

列表只发一个评级批量请求，不能每行请求一个详情。后台按类别批量读取净值、经理、持仓和费用，避免 N+1。计算与网络请求解耦，不在普通 GET 内等待数千只基金计算。

为任务配置查询超时、外部来源超时、可取消或有界执行时间，并记录实际范围与用时；不能只在 HTTP 层超时后无限后台重试。失败只对可重试的受控步骤执行有上限重试，已成功发布的批次不重复写入。

沿用日志格式，例如 `fund_rating.calculate >>> ...`，记录类别、截止日、方法标识、输入摘要、准入与排除数量、结果数量、耗时、任务号和 TraceID。异常保留堆栈；不输出完整净值数组、个人信息或服务令牌。

运营计数至少包含：目标份额数、可评级数、未评级数及互斥主原因、各类别成功与失败、四级分布、旧结果数量、平均计算耗时。一个基金可以有多条资料缺口，但缺口条数不能与未评级基金数相加当作总数。

## 16 发布 回退与完成标准

先部署增量表和后端读取能力，默认无已发布等级；再部署前端，未准备好时显示暂未评级；完成真实类别八维验收后才发布其首个批次。管理端可单独启停评级任务，不联动改变预测功能。

回退优先关闭新等级展示或切回仍有效的历史批次，保留全部输入、结果和审计。若旧批次依据已证实错误，不允许为了有等级而回切。数据库不执行清表式回退，Alembic 降级不能作为常规恢复操作。

单类别完整交付必须同时满足：

1. 分类和产品去重有依据，八维必需资料实际齐全。
2. 八维指标、候选规则和同类比较可复算，四级映射正确。
3. 同页批量读取和单基金详情引用同一已发布结果。
4. 列表只显示等级，详情能解释八个维度与日期，状态不误导。
5. 手动更新、失败、过期、撤回、并发和回退均有实际验证。
6. 交付明确已开放类别、未开放类别及原因，不以少数演示数据代替市场覆盖。

所有目标类型完成专用配置与上述验收后，才可以称为全类型基金评级功能完成。算法正确只能证明规则被正确执行，不证明等级能够预测未来收益。

## 17 实施前需要核实的事实

下列事项由开发和数据核验解决，不要求普通用户选择技术参数：

- 当前目录究竟包含多少个经核验的独立产品，各细分类别能否达到候选样本门槛。
- 完整持仓、精确持有人集中度、交易量、有效费率与无风险序列的来源和覆盖；尤其不能假定公开报告一定提供精确持有人比例。
- 当前调整后净值是否可复核为本次所需总回报序列，分红与折算样例是否齐备。
- 首批候选权重和管理连续性、流动性情景是否产生明显偏差，需如何形成固定版本。
- 实际 Alembic head、目标数据库 schema、任务状态持久化方式及合理批次上限。
- 其他基金类别专用八维规则的数据可得性和实现顺序。

这些核实项不改变已确认的八维全部计分与四级展示要求。必要事实未核实时，对应基金保持暂未评级。
