## 4. 时间与答案契约：先固定，再写训练

### 4.1 一条问题的定义

`T`为基准交易日，`U = nextTradingSession(T)`，必须是日历中紧邻的下一交易日。窗口从T的18:00开始，到U的08:30结束，右端不包含。所有业务时间用`Asia/Shanghai`解释，数据库时间用带时区时间戳保存。

```text
T 当天收盘 → T 官方净值确实收到 → T 18:00之后开始尝试
         → 两模型使用同一份截至T的输入 → 在 U 08:30 前完成留档与可读确认
         → U 当天交易 → U 官方净值实际收到 → 核对这条已保存的预测
         → 核对完成的样本进入此后某次固定训练快照
```

周五T的下一交易日通常是周一U，但节假日一律查日历。周末可以重试同一条问题，不新增“周六/周日预测”样本。若服务在U的08:30后才启动，这一期记为错过，不能用历史数据补造提前预测。

在目标日早晨展示时应写“预测今天（日期U）的涨跌”，在前一日展示可写“预测下一交易日（日期U）”，历史记录始终使用绝对日期，不能让“明天”随浏览日期改变。

### 4.2 必须保存且相互约束的时间

| 字段 | 含义/规则 |
| --- | --- |
| `baseNavDate` / `targetNavDate` | T/U，按冻结日历验证恰好相差1交易日 |
| `windowOpenAt` / `deadlineAt` | T18:00 / U08:30；服务器计算，不接受浏览器任意回填 |
| `featureAsOf` | 输入快照实际读到并冻结的时刻；所有使用的数据修订必须在此时已可见 |
| `latestNavDate` | 必须等于T；不能小于T仍标为可预测 |
| `maxInputObservedAt` | 使用的来源记录最晚本地观察时刻，不是来源公布时刻 |
| `generatedAt` | Python真正完成推理的时刻，须在窗口内 |
| `storedAt` / `receiptVerifiedAt` | Java真实写入时间/提交后新事务读取确认时间；二者及generatedAt都须早于deadlineAt |
| `labelObservedAt` / `assessedAt` | U净值实际可读取/本次核对的时刻；没有标签不核对、不训练 |
| `trainAsOf` / `trainedAt` / `registeredAt` / `modelSelectedAt` | 训练读取界限、真实完成、登记和模型选择时刻；完成并登记后可参与当前未截止预测，不得倒填 |

只写一条带`created_at`的INSERT不能独立证明它在截止前已提交并可读。Java预测写入提交后，用新事务回读验证并追加确认事件；统计仅接纳截止前完成此确认的记录。确认事件晚到则标为`LATE_ARCHIVE`，即使计算时间更早，也不计提前预测。测试须覆盖跨截止点提交、重启与重试。

时钟由服务端与数据库产生，不信任客户端时间。检查Java/Python/数据库的时钟偏差；默认超过5秒停止生成并报`CLOCK_SKEW`，不影响读取历史与已成熟答案核对。

### 4.3 标签公式、持平与分红

本版`targetDefinition=UNIT_NAV_DIRECTION_V1`，使用官方单位净值十进制值：

```text
return = NAV(U) / NAV(T) - 1
y = 1，当 NAV(U) > NAV(T)；否则 y = 0
actualDirection = UP / DOWN / FLAT，由两个原始十进制净值直接比较
predictedDirection = UP，当 score > 0.5；否则 NON_UP
correct = (predictedDirection == UP 且 y == 1) 或 (predictedDirection == NON_UP 且 y == 0)
```

先用精确十进制比较定方向，再按12位小数、`ROUND_HALF_UP`保存展示用回报；不能先把百分比显示成0.00%再判断持平。净值缺失、非正数、非有限数、错误币种、冲突来源不算答案。缺U净值时必须等待，不能跳到U后一天，也不能用估值或零值补上。

默认评估使用预测时冻结的T净值、其后首次被本系统接纳并冻结的U官方净值版本。保存二者完整来源/内容哈希。供应商之后修订T或U时，追加修订核对版本及原因，保留最初结论；主统计默认“首次核对口径”，另展示“最新修订口径”。新训练可以使用训练时已知的修订，但必须记录所选版本。两种评价口径不得混用。

现金分红、拆分、合并等可能引起单位净值机械变化：本目标仍按单位净值判定，记录`eventStatus=KNOWN_EVENT/NO_EVENT_IN_CHECKED_SOURCE/UNKNOWN`及证据时点，分别统计事件日/已检查无事件日/未知。不得因为模型在事件日错了才删样本，也不能把事后才知道的事件标识放进当时特征。交易回报分析是另一目标，本版不混入。

## 5. 1日特征与历史数据集

### 5.1 首版特征固定为七项

`featureVersion=UNIT_NAV_7_T_CLOSE_V1`，输入为`v[0..60]`，对应T前60个交易日至T的61条**单位净值**。不直接使用累计净值、复权净值或旧现金再投指数。即使复用数学函数，也不能复用20日模型的归一化参数。

| 顺序/名称 | 精确口径 |
| --- | --- |
| 1 `return_5d` | `v[60]/v[55]-1` |
| 2 `return_20d` | `v[60]/v[40]-1` |
| 3 `return_60d` | `v[60]/v[0]-1` |
| 4 `volatility_20d` | 最近21条净值得20个相邻简单收益，总体标准差，除以20，不年化 |
| 5 `max_drawdown_60d` | 最后60条净值即`v[1..60]`，逐点相对此前已见最高值的最小回报，非正数 |
| 6 `relative_position_60d` | `(v[60]-min(v[1..60]))/(max-min)`；全平窗口无定义，状态明确为特征不足 |
| 7 `consecutive_decline_days` | 从T往前连续严格下跌的区间数，持平或上涨终止，最大60 |

首版要求完整窗口，不补零、不跨日期压缩、不使用未来值填充。原20日容忍缺失策略不能自动带入；以后若改缺失处理须另立特征版本与对照。61条历史达到要求即可使用同组已训练模型做推理，**不要求每只新关注基金都先有252条训练样本**。

这是有意简单的1日初始基线，不是声称60日特征一定适合短期。先完成可核对的闭环，再单因素比较短期收益/波动、对应市场等增量，不能在首版偷偷追加多轮试验。

### 5.2 三类数据明确隔离

| 数据类型 | 用途 | 可以声称什么 |
| --- | --- | --- |
| `HISTORICAL_RECONSTRUCTION` | 当前可得历史版本构造开发训练/回看 | 历史开发结果；不证明当时已拿到该版本 |
| `FORWARD_ORIGINAL` | 系统实际提前冻结输入并留档的预测 | 此版本在当时确实做出的预测；先核对后可用于以后训练 |
| `REPLAY_DIAGNOSTIC` | 新模型重新计算已有历史问题 | 诊断/复现；不能混入真实提前预测成绩 |

历史输入只读取日期≤T的值，历史标签只比较T/U。回看默认假设T净值在U的08:00可得，U标签在其下一交易日08:00可得；此假设只用于缺乏真实时刻的开发数据，统一标`availabilityEvidence=ASSUMED`。能证明更晚到达的数据按更晚时间处理。真实流程必须使用实际可读时间，不能套用历史假设。

先建立`history-usage-manifest`：每个日期段的用途、是否已用于20日开发、是否受独立验证保护、来源修订限制。已用于20日选方案的数据仍可开发1日，但不是全新独立测试。2025/2026不能仅因1日尚未使用就自动宣称干净；遇到明确受保护的旧区间，保持排除并注明，使用其他已授权历史完成首版，不放宽旧代码保护条件。

### 5.3 切分、样本成熟与同题比较

- 所有同一天、同一产品家族的份额按日期一起切分；禁止打乱全表后随机分训练集/验证集。时间序列与相关样本需要匹配的切分，标准化只在训练集拟合。[scikit-learn交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)
- 每条训练样本需同时满足：输入已经可用，T/U净值与版本在训练界限前已可用，且标签成熟时间不晚于`trainAsOf`。不能只检查T落在训练范围就纳入尚未公布的U答案。
- FIT区间末端通过标签可用时刻剔除跨界样本；1日任务不复制旧20日的20/21日间隔，也不为“1日”机械删除一行就声称无泄漏。
- 初版开发回看默认2024Q1—Q4四个固定季度，每个季度开始前训练一次，最多取之前504个交易日基准日期的成熟样本；不得根据成绩改季度。无法覆盖的基金/组按原因计数。
- 上述四窗不足时，报告真实不足，不为了凑成绩改成事后最好时段。最终首版模型可使用登记允许的最新历史中最近504个交易日的成熟样本，不要求历史回看赢基线才进行实验观察。
- 全历史回看与真实前向统计分开。比较两模型时使用相同`fundCode,T,U,inputSnapshotId,targetDefinition`交集，同时报告各自覆盖率与交集之外的缺失原因；不能只报共同成功样本而隐藏更新版漏算。

## 6. 训练、冻结对照与每周更新

### 6.1 第一版算法与最低技术条件

每个已经核验的资产组独立训练`StandardScaler + L2 LogisticRegression`，固定`C=1`、`solver=lbfgs`、`tol=1e-8`、`max_iter=1000`、`random_state=0`，单数值线程，类别权重不自动平衡，阈值严格`>0.5`。参数须按本项目已安装scikit-learn API表达并记录版本，不升级依赖来适配网上示例。

初始技术门槛：每个组至少252个不同基准交易日；去同产品同日重复后，UP与NON_UP各至少30个有效样本；全部输入有限，拟合收敛，导出/恢复后分数可复现。门槛用于避免无法拟合或极端稀薄样本，不代表统计有效性证明。条件不足的组显示`MODEL_PENDING`并保留其他组进度。

样本权重：同一产品家族同日的多个份额平分该家族当天权重，各家族在组内总权重相等，家族内各有效日期均分。令家族数为G、家族g有效日期数为Dg、当天有效份额数为Mgd，原始权重为`1/(G*Dg*Mgd)`；再统一缩放，使总权重等于该组不同“家族×日期”数量。Scaler与分类器使用相同权重。这样增加A/C重复份额不会无故增加损失权重并改变正则强度。权重算法、映射与样本顺序写入训练哈希。

本轮只实现这一个配方，不同时做树、神经网络、网格调参、模型融合或概率校准。新关注基金可使用已支持资产组的模型，记录其是否参与过该模型训练；分组模型训练名单与当前预测关注名单是两个集合。

### 6.2 FIXED与WEEKLY的含义

| 分支 | 行为 | 评价用途 |
| --- | --- | --- |
| `FIXED` | 初次训练后参数、标准化和分组名单冻结 | 判断不再更新的初始版本后来表现怎样 |
| `WEEKLY` | 初始与FIXED指向相同模型，以后按同一配方、同一504日窗口长度每周重训 | 判断持续吸收新成熟数据的固定更新流程怎样 |

第一天两分支分数相同是正常情况，只能算同一问题的两个分支结果，不是两份独立证据。分支与模型哈希必须同时保存；WEEKLY累计成绩表示“每周更新这套流程”的成绩，不能宣称最新单个模型在整个历史期间都取得了该成绩。

初始`cohortId`冻结训练基金/产品家族与分组规则。后续新关注基金如果输入适用可直接接受推理；如需把新增产品加入训练、修改分组或新增资产组，生成新cohort与各自起始日期，不把新增样本与每周参数更新混成同一次对照。用户取消关注不删除既有历史，已冻结训练集合只包含公共数据、不包含用户身份。

### 6.3 简单基线

每条成功预测同步保存：恒上涨、恒非上涨、初始FIT多数类、上一日方向延续。多数类每组只从初始FIT算，平票为非上涨并冻结；方向延续用`NAV(T)>NAV(T-1)`。基线无需额外训练，与模型使用同一问题与答案口径。不能只和50%比较，也不能事后选最有利的基线。

### 6.4 周更新与启用规则

1. 每周日12:00取一次固定训练快照，先完成截止当时已到达标签的核对。`trainAsOf`固定后，后来新到数据不混入本次训练。
2. 每组本次最多一次主拟合及一次相同输入复现检查；固定特征、参数、名单、权重与504日窗口，记录输入/标签版本、类别计数、排除项、耗时、代码与依赖哈希。
3. 技术检查失败则WEEKLY继续使用上一可用模型，记录更新失败；不得由最新目录/修改时间猜测模型。
4. **2026-09-12按用户明确要求取消“训练必须早于窗口开启”的限制。** 技术合格的模型只要在实际选择前完成训练并登记、预测在截止前真实留档，就可用于当前目标日。策略为`AVAILABLE_AT_PREDICTION_V2`，记录实际训练、登记、选择和生成时刻；旧策略记录保留，不倒填时间。
5. 比如9月11日23:23完成的首模可以在周末真实预测9月14日。FIXED保持初始模型；WEEKLY使用该组首次实际选择时可用的周更新版本。同组同目标日的选择原文和每只基金已经成功留档的结果保留，重试读取原结果。尚无可用模型时不锁死空映射。
6. 技术有效的WEEKLY实验更新不要求通过旧20日发布门槛，也不要求这周回看一定赢FIXED；页面保留两个分支及不确定性，胜负由随后真实问题检验。正式发布是以后另一项决策。

周日停机后，允许启动时至该周下一个交易日12:00前仅补跑一次本周训练，仍按实际时刻取快照，只影响以后实际生成且未截止的预测；更晚则记本周跳过。不能补造几个过去周次的模型并回填为当时预测。

### 6.5 分数不是经过验证的概率

JSON模型产物保存系数、截距、标准化参数、特征顺序、算法/标签/协议版本、训练时间与范围、cohort、来源、样本哈希、代码/依赖版本、完整文件SHA256。从允许目录按已注册ID加载有大小上限的JSON，校验维度、有限数、horizon=1、hash及激活范围；禁止请求传模型文件路径或加载任意pickle。

页面默认只显示方向，展开依据时可显示“模型分数0.62（尚未校准）”；不得显示“上涨概率62%”“预期赚多少”，正式20日`MODEL_NOT_RELEASED`状态保持原样。

## 7. 真实预测、核对与不可变记录

### 7.1 每日主流程

1. 读取已启用实验用户的当期关注快照，按代码去重。每一只基金都登记本期状态，包含不适用、缺数据和失败。
2. 在窗口内补齐T及历史缺口，Python在一致性读事务中冻结公共输入，确保包含T且不含U；分红说明仅用当时已知信息。
3. 使用首次实际选择时可用的FIXED/WEEKLY及同一输入计算两个分支和基线，不要求模型早于T18:00完成；有一分支不可用也保留另一分支，但成对统计只使用双方有效交集。首版以整组结果作为归档单位：首次有效归档后连同不可用分支一起冻结，该问题不再补算缺失分支；失败原因与漏算数保留。两分支都未成功时只记录attempt，在截止前允许重试。
4. Java验证协议、时间、基金、模型、输入/内容哈希，将原始预测、当时覆盖理由和用户归属关系持久化。提交后回读确认，截止前完成才计为有效提前预测。
5. 重试只恢复缺失流程，不替换已确认预测。第一条有效预测是该分支本期唯一计分原文；之后数据修订或用户反复点击不换答案、不多计样本。
6. U官方净值到达后，由后台找到所有待核对历史记录（不依赖当前还关注该基金），固定答案版本并核对；用户没打开浏览器也要执行。
7. 把核对完成且时间满足训练边界的样本加入后续训练快照，不能修改旧预测。按先预测、答案到达后评估、再学习的顺序处理，标签延迟必须显式记录。[River渐进评估说明](https://riverml.xyz/dev/api/evaluate/progressive-val-score/)

### 7.2 状态不要塞进一个字段

| 维度 | 建议枚举 | 说明 |
| --- | --- | --- |
| 基金覆盖 | 第3节状态 | 该基金/数据/分组是否满足要求 |
| 本期预测 | `NOT_DUE / WAITING_DATA / PREDICTED / MISSED_DEADLINE / LATE_ARCHIVE / MODEL_UNAVAILABLE / FAILED` | 是尚未到时间、缺数据、确实提前预测、还是错过 |
| 核对 | `PENDING_TARGET / PENDING_NAV / ASSESSED / SOURCE_CONFLICT / EVIDENCE_EXPIRED` | 未出答案不是错误预测；修订另有版本标记 |
| 结论 | `CORRECT / INCORRECT / null` | 只有有效预测与有效答案才能给结论 |
| 实验状态 | `EXPERIMENTAL` | 与上述数据状态无关，不隐含已正式发布 |

持平样本保留且按NON_UP核对，另外单列数量；缺失、迟到、失败不能算错题，也不能默默从覆盖率分母去掉。样本证据过期的记录保留状态与可留的元数据，不伪装成仍可完整复现。

### 7.3 幂等、跨服务与原文完整性

- 预测任务键为`protocol + cohort + fundCode + targetNavDate`，分支结果再加`branchId`，每个结果固定`modelVersion`。同一目标日不能通过换版本ID重复计分。
- Python按任务键/输入快照ID返回稳定结果，Java事务按唯一键写入；Python已计算而Java失败时允许在截止前重取同一结果完成归档。超过截止只记录失败/迟到，不追认成功。
- Java保存公开预测主体一次，多用户仅保存授权归属关联，不因十个人关注同一基金而训练/推理/计分十遍。读取仍须逐用户检查关联，不能暴露其他用户是谁或关注了什么。
- 当期中途新增关注可在截止前关联已存在的公共预测，记录真实linkedAt；截止后新增关注不得回填本人过去的观察档案。个人覆盖范围按当期实际订阅/关注快照确定，不能用今天的关注列表重算过去的分母。
- 原始预测、模型映射、输入快照、确认事件、答案版本追加写入；应用层不提供修改旧分数接口，数据库对关键原文UPDATE设保护。
- `contentHash`不包含易变的查询时间，包含固定日期、输入、分支模型与分数、规则。读出时验哈希；错误时不给可用预测，历史损坏单独提示。

| `POST /api/v1/watchlist/{fundCode}/prediction-1d/generate` | 仅在允许窗口内请求本期生成/重试，返回202+任务ID或已存在记录；不接受历史日期、模型路径或阈值 |

| `GET /api/v1/watchlist/prediction-1d/reports/{forecastId}` | 本人原始记录、输入/模型身份、首次及修订核对，不暴露其他用户关联 |
| `GET /api/v1/watchlist/prediction-1d/metrics` | 本人授权记录范围内的覆盖/准确率/两分支同题比较；明确日期范围与标签口径 |

读接口要求`FUND_READ + WATCHLIST_SELF_READ`；当前基金状态/手动生成另校验仍属本人关注，历史按本人已有记录关联授权。启用/停用、手动生成要求已有`WATCHLIST_SELF_WRITE`或仓库实际等价权限并执行CSRF，若现有枚举不同则沿既有权限矩阵落实，不使用仅前端按钮判断。定时推理不重复扣关注积分。

返回`Cache-Control: no-store, private`。401/403按现有约定；格式错400；非本人记录按现有404/403规范；窗口不允许409；限频429；内部故障返回脱敏错误。数据不足是带原因的正常业务状态，不伪造成全接口500。

建议核心响应 `schemaVersion=DIRECTION_1D_EXPERIMENT_V1` 包含：`fundCode,status,reasonCodes,horizonTradingDays=1,targetDefinition,modelReleased=false,upProbability=null,baseNavDate,targetNavDate,deadlineAt,generatedAt,receiptVerifiedAt,inputHash,cohortId,branches[],baselines[],outcome,limitations[]`。不可用分支的score/direction必须为空。时间字段为ISO8601带时区，回报十进制字符串，所有状态在三端严格同义校验。

### 9.2 Python内部能力

| 方法与路径 | 行为 |
| --- | --- |
| `POST /internal/v1/direction-1d/coverage` | 去重基金批量检查，最多100；公共信息，无用户编号 |
| `POST /internal/v1/direction-1d/forecast-jobs` | 受控本期任务键，构建输入/窗口模型映射并推理；幂等，耗时操作返回任务ID |
| `GET /internal/v1/direction-1d/forecast-jobs/{jobId}` | 获取稳定结果或失败状态；不得返回尚未完成的可计分预测 |
| `GET /internal/v1/direction-1d/labels/{snapshotOrTaskId}` | 依据已登记问题返回公共官方净值证据及版本；无标签时等待，不接受任意horizon |
| `POST /internal/v1/direction-1d/training-jobs` | 仅调度服务/受控管理角色提交已冻结runSpec；不向普通关注用户开放任意训练参数 |

## 10. 后台执行与统计

### 10.1 调度与服务运行

采用Java独立`direction1dTaskScheduler`组织范围、生成、核对与周更新；Python沿用现有异步工作设施执行有上限的同步/训练。计算不得阻塞普通HTTP或现有持仓结算/建议调度线程。是否需运行Celery Worker按实际执行实现验证，不能只看配置就称自动执行成功。

| 任务 | 默认执行策略 |
| --- | --- |
| 预测 | 每30分钟检查一次，只对当前有效窗口内任务执行；T18:00开始，U08:30硬截止，所有分支按窗口固定模型 |
| 净值补齐 | 先查本地，缺失基金按现有同步锁、来源额度批量补；不会每次对每个用户重复拉相同基金 |
| 答案核对 | 每30分钟查待核对记录，分页50；只处理目标日已到且来源已有真实官方净值的问题 |
| 训练 | 每周日12:00每组一次固定run，有限补跑按第6节；无新有效样本则记SKIPPED，不空转拟合 |
| 状态 | 每轮记录真实开始/结束、数量、耗时、错误、下次运行与最近成功水位 |

使用PostgreSQL advisory lock或既有等价机制做到跨实例防重；网络请求单次默认30秒内、指数退避、每轮单基金最多3次，遇供应商限频服从现有限额。线程、批大小、截止时间可配置但必须形成协议/运行配置快照。到截止停止新预测；失败部分不拖垮整批，UI能区分PARTIAL与SUCCEEDED。

本地运行依赖Java、Python、数据库及选用的worker持续在线，关闭浏览器不影响后台；电脑/服务停止就不能生成当时的预测，启动后只能核对旧记录与执行当前允许窗口。不得用Codex聊天自动化代替项目后台，也不在本实施任务中默认创建短信、邮件或交易通知。

### 10.2 统计口径

- 每个基金目标交易日一题，每分支最多一个有效提前预测；多个用户、页面读取、重试、来源修订不增加题数。整体研究按公共问题去重，个人页面只统计本人关联范围。
- 覆盖率：同时报“全部关注覆盖检查数”“当前协议适用数”“模型/数据就绪数”“当期应预测数”“实际提前预测数”“错过/失败数”。主流程覆盖率为实际提前预测数/当期应预测数，全部关注未覆盖原因另外完整展示。
- 准确率=`正确数/已核对有效预测数`，同时展示分子/分母、尚未到期与缺标签数。持平按NON_UP计分并单列。不得把所有未核对记错或当对。
- 分别给出FIXED、WEEKLY、四个简单基线，同题交集上“多对/少对多少题”。报告按基金、资产组、月份、模型版本、事件状态分层结果。
- 展示UP召回、NON_UP召回及二者平均的平衡准确率；某期间只有一种真实类别则平衡准确率为空并解释。单看训练准确率高不是泛化改善证据。
- 普通准确率旁同时报告按“产品家族×目标日”等权的结果，避免A/C重复份额主导；不同日期数必须单列。禁止把100只基金×一天当作观察了100天。
- 少于20个不同目标交易日统一标“观察期很短”，20日仅作运行/错误分布复盘；约60个不同目标日后可做一次较完整分析，仍不据此自动发布或承诺显著性。
- 需要不确定区间时按日期块重采样并保持同日各基金一起，不能使用把全部基金行当独立样本的普通二项区间。正式概率校准与投资回报另立后续任务。
