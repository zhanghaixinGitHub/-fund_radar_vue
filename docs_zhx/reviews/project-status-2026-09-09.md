## 1. 当前做到什么程度

**项目已具备可使用的基金资料查询、账号权限、个人关注、积分和数据同步功能；预测已经完成研究到页面的工程阶段，但尚未交付真实可发布的上涨概率，更没有完成多周期综合预测。**

不能再把它说成“只有六只样本和几张页面”，也不能称为“全市场智能预测系统已经完成”。当前最准确的定位是：**43 只基金的数据查询和关注工具，加上三只股票型基金的 20 交易日预测研究原型。**

## 4. 真正尚未完成的功能和任务

### 4.1 当前预测主线：正式上线仍有四组工作

1. **确认并冻结正式发布规则。** 当前服务器规则仍为 DRAFT；最低样本、概率误差、行情覆盖和最终考试协议尚未完成真实批准。已有冻结接口并不等于已冻结。
2. **补齐可信的历史数据证据。** 历史首次公开版本、现金分红完整性、拆分/折算等非现金调整、行情分类，以及固定窗口缺少的有效样本仍有缺口。新建本地观察日志不能补证多年以前的首次版本。
3. **完成符合固定协议的模型研究和独立测试。** 前两轮滚动窗口样本不足；已完成的研究没有证明稳定优于简单对照；2025 独立测试尚未执行。现有研究也没有按新的冻结计划在训练前绑定，不能事后补手续冒充。
4. **实现正式发布凭证的生命周期。** 证据合格后签发、启用、停用、撤销，绑定模型/数据/规则，再贯通真实数值生成和本人页面。目前 `resolve_cash_authorization()` 最终始终抛出 `CashPublicationUnavailable`，是真实尚缺的工程实现，不只是数据问题。

本次对实际已保存研究重新执行了只读规则审查：118 项中 **50 通过、47 失败、21 缺证据**，总状态 `BLOCKED`，不允许发布、没有推理、没有写入、没有读取最终独立测试。三只试点均返回未发布和六类具体缺口。

上面第 1—3 项同时涉及真实条件与研究效果，不能承诺“再写几个接口、再训练一次就一定通过”。第 4 项明确仍需开发。它们是后续正式产品目标，不应反过来否定已经完成的“未达标也能正确显示原因”的研究页面阶段。

### 4.4 全市场覆盖和市场参考数据

- **真正全市场目录仍未完成。** 当前同步的是本地登记的 43 只启用基金。已有按精确代码扩展和回补能力，但不能视为完整市场覆盖；历史目录触及行数上限的问题仍需要完整返回条件及范围方案。
- **参考指数实际日线与权重仍未落地。** 有代码，但 `benchmark_series` 为 0，所以日线和权重阶段可以合法地零条成功。需要先选定、登记并核验参考指数，随后才有有效历史数据。指数目录 1,643 条不能替代这一步。
- **自动持续运行尚未确认。** 有工作日 20:00 的 Beat 计划，但最终检查未发现本机 Celery Beat/Worker 进程。当前手动同步能成功，不等于夜间自动执行已运行。此项是运行闭环，不是缺少同步算法。
- 完整资料和免费补齐目前按需手动运行，是现有设计，不应把“没有每晚全量同步”直接认定为漏做。

### 4.6 运行与交付保障（M3-07）

文档中仍未完成的是模型/评分/回测/结果消费的实际运行编排、唯一运行者、失败隔离、覆盖/延迟/失败率指标、漂移监控、发布暂停和回滚手册，以及可回退的分阶段部署。

当前同步任务已有单并发、锁、超时和重试基础，不能把这一整层说成完全没有。手动任务的实时进度保存在 Python 进程内；数据库保存来源运行和最后成功时间。进程重启后的完整任务进度恢复不是当前实现能力，如后续扩展多人或多实例部署，需要单独设计。
