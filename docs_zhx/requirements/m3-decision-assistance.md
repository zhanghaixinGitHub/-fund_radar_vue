## 1. 决策结论与目标

本需求建设的是可追溯的个人投资决策辅助基础能力，而不是收益预测器、投顾、自动交易或代客理财服务。系统只在已授权来源、数据新鲜度、类别适用性、特征完整度和回测准入同时满足时，向用户展示基金层面的概率型评分与风险解释；最终申购、赎回、持有或定投调整始终由用户在外部交易平台自行决定。

当前项目已具备四类数据的基础表和受限读取骨架；特征已有 24 条本地受控快照，其余三类真实记录仍为 0：

| 数据类别 | 已有对象 | 业务含义 | 当前状态 |
| --- | --- | --- | --- |
| 特征 | fund_ai.feature_snapshot | 某基金在某业务日、某特征版本下的可复现模型输入事实 | 股票型试点 24 条受控快照，非预测 |
| 评分 | fund_ai.forecast_result | 基于一条特征快照产生的概率型结果与解释 | 仅表结构和读取契约 |
| 回测 | fund_ai.backtest_run | 按时间滚动验证模型版本是否可发布的实验记录 | 仅表结构 |
| 提醒 | fund_core.alert_rule、signal_snapshot、notification | 用户规则、同步后的信号快照与实际站内通知 | 仅规则配置具备 |

## 2. 业务范围

### 2.1 本期建设范围

1. 建立按基金类型隔离的特征快照、评分、回测、模型发布和提醒投递链路。
2. 所有输出可追溯到基金代码、数据截至日、来源运行水位、特征版本、模型版本、回测运行和解释摘要。
3. 仅支持站内提醒；提醒规则只能由当前登录用户管理，提醒记录只能由本人读取和标记已读。
4. 数据不足、来源陈旧、来源失败、类型不适用、模型未发布或回测不合格时，统一输出数据不足或模型不可用，不输出方向、概率、置信度或行动倾向。

### 2.2 明确不在范围

- 不新增未经授权的新闻、公告、社交媒体、基准或持仓数据采集。
- 不接入支付宝、券商、基金销售平台，不保存第三方账户凭证，不执行申购、赎回、买卖、模拟点击或自动调仓。
- 不把基金层面的评分自动转换成某用户的继续定投、止盈、止损、减仓或收益结论；这类个人化结论需要后续持仓、风险画像和独立合规评审。
- 不以当前 43 只基金市场称为全市场样本，不把离线实验或空表结构描述为已上线模型。
- 不发送短信、邮件、微信、推送通知；一期只保留站内通知。

## 3. 用户、角色与可见范围

| 角色 | 可执行动作 | 不可执行动作 |
| --- | --- | --- |
| 基金用户 | 阅读本人有权基金的已发布评分、解释、数据状态；管理本人提醒规则和通知已读状态 | 启动评分、回测、模型发布；读取其他用户规则或通知 |
| 数据运营 | 查看来源、特征覆盖率、评分状态和回测运行摘要 | 发布模型、查看用户通知内容、绕过数据源授权 |
| 系统管理员 | 受控启动分析运行，审核模型发布或暂停，查看脱敏运行审计 | 绕过来源授权、修改历史评分、生成交易指令 |
| FastAPI 服务 | 生成和查询 fund_ai 侧派生数据 | 读取用户身份、关注关系、持仓或直接创建用户通知 |
| Java 服务 | 认证授权、接收不可变信号快照、计算本人规则命中并写站内通知 | 训练模型、直接写 fund_ai 数据库、调用外部数据源 |

## 4. 四类数据的业务定义

### 4.1 特征快照

特征快照是模型输入的可复现事实，不是预测结论。业务粒度为 基金份额 + 数据截至日 + 特征版本。它必须记录基金类型、来源数据水位、有效样本量、完整度、不可评分原因和特征内容哈希。

特征必须按类型分层，不能把不同风险资产混在同一套口径：

| 基金类别 | 一期允许的特征边界 | 一期禁止推断的内容 |
| --- | --- | --- |
| 股票型、混合型、指数型 | 已授权净值序列的区间收益、波动、历史回撤、观测数、数据新鲜度 | 未授权持仓、行业暴露、估值、资金流、实时行情 |
| 债券型 | 已授权净值序列的波动、回撤、观测数、数据新鲜度 | 久期、信用暴露、杠杆、票息归因，除非另有授权字段 |
| QDII、FOF | 默认数据不足；只有外部市场日历、基准与历史序列均获授权时才单独建模 | 用境内净值数据推断海外或底层资产方向 |
| 货币型 | 只输出数据新鲜度和不可评分状态 | 上涨、下跌、趋势、买卖方向预测 |

### 4.2 概率评分

评分是指定模型版本对一条特征快照给出的概率型、可解释结果。业务粒度为 基金份额 + 数据截至日 + 模型版本。评分状态分为 SCORED、DATA_INSUFFICIENT、NOT_APPLICABLE、MODEL_REJECTED。

只有 SCORED 状态才允许携带方向、概率、置信度和风险等级。方向仅是模型统计结果，可取 UP、DOWN、NEUTRAL；页面必须同时展示数据截至日、模型版本、特征版本、解释和不确定性，不得显示立即买入、卖出、止损或收益承诺。

### 4.3 滚动回测

回测是模型发布闸门，不是用户的模拟交易账本。业务粒度为 基金类型 + 策略版本 + 特征版本 + 模型版本 + 时间窗口。每次运行必须记录训练、验证、测试的严格时间顺序，以及费用假设、比较基线、样本量、收益、最大回撤、波动率、命中率、失败原因和发布资格。

只有通过独立样本区间的滚动回测，且满足已确认的准入阈值，模型版本才能进入可发布状态。任何未通过、样本不足或数据版本失效的运行都只能标记为不可发布。

### 4.4 提醒

提醒由三层数据组成：

1. 用户规则：当前用户针对已关注基金配置风险等级、评分变化或已授权事件提醒。
2. 信号快照：Java 从 Python 拉取已发布评分后，以不可变、幂等方式保存的服务边界快照。
3. 通知记录：规则命中后生成的站内消息，包含去重键、触发引用、未读或已读状态。

提醒只告知新的已发布评分或事件及其依据，不生成交易操作，不修改关注、持仓、定投或外部账户。

## 5. 主流程与异常流程

### 5.1 主流程

1. 已授权来源的同步运行成功，产生带来源和业务日期的数据水位。
2. Python 后台任务按基金类型和数据截至日创建特征快照。
3. 特征满足完整度和适用性规则时，且存在已发布模型版本，才创建评分；否则只落 DATA_INSUFFICIENT 或 NOT_APPLICABLE。
4. 管理员对候选模型运行滚动回测。只有回测准入后，模型才可被发布。
5. Java 以稳定游标拉取已发布评分变化，在单个本地事务中幂等写入 signal_snapshot、匹配本人提醒规则、写入 notification 并推进消费水位。
6. Vue 只通过 Java 查询评分、回测状态、提醒规则和本人通知；所有页面均显示数据截至时间和非交易提示。

### 5.2 强制降级

| 条件 | 必须行为 |
| --- | --- |
| 来源未授权、关闭、失败、陈旧或数据冲突 | 不创建 SCORED 评分；创建或返回数据不足状态，不触发评分提醒 |
| 特征缺失、观测数不足、基金类型不适用 | 保留不可评分原因；方向、概率、置信度为空 |
| 回测未完成、被拒绝或模型发布已暂停 | MODEL_REJECTED；不得投递评分变化提醒 |
| Java 无法拉取 Python 结果 | 保留上一份明确标注陈旧的只读结果；不补造新快照或通知 |
| 用户取消关注、关闭规则或账号失效 | 不再生成新通知；历史通知按保留策略受控可读 |

## 6. L3 七维方案与真实风险

1. 业务与功能边界：一期只做基金层面、站内、非交易的概率评分与风险解释。个人持仓结论和行动建议必须等待 M4 与独立评审。
2. 数据架构：fund_ai 是来源、特征、评分、回测的唯一写库方；fund_core 是用户规则、快照和通知的唯一写库方。服务间只经内部 API 交换。
3. 性能与并发：特征按基金和日期批处理；评分、回测、信号消费均使用稳定游标、唯一约束和幂等键，禁止页面触发长任务或逐基金 N+1。
4. 高可用与稳定性：来源失败不重试放大；任务应有限次退避、可恢复水位、按模型与日期隔离失败，读取端可标陈旧但不能伪造新评分。
5. 安全性：用户范围从 Java 当前认证上下文导出；Python 不接收用户标识；浏览器不持有服务令牌；不在日志、通知或 JSON 载荷中写入凭证、完整个人数据或交易指令。
6. 可观测性与运维：所有运行记录 TraceID、模型和特征版本、数据水位、计数、耗时、失败摘要；监控评分覆盖率、数据不足比例、回测准入、通知去重和消费延迟。
7. 可扩展性与工程化：模型、特征、目标周期和准入阈值均版本化、配置化；新增基金类别或来源必须独立登记并回测，不能修改已发布历史评分语义。

## 7. 实施阶段与验收门

| 阶段 | 交付内容 | 进入下一阶段的门槛 |
| --- | --- | --- |
| G0 数据治理 | 来源登记、数据水位、类别和目标周期确认 | 每个输入来源具备授权、刷新、保留和展示说明 |
| G1 特征 | 类型隔离特征、完整度和不可评分状态 | 特征可重算、可追溯，数据不足不会产生方向 |
| G2 基线评分 | 单类别、单周期的可解释基线评分 | 无效状态字段为空，结果可复现 |
| G3 回测 | 时间滚动切分、费用和基线比较、发布闸门 | 独立测试窗口满足已确认阈值 |
| G4 提醒 | 信号快照消费、规则匹配、站内通知、去重与已读 | 不跨用户、不重复、不含交易指令 |
| G5 受控发布 | 页面披露、监控、暂停和回滚演练 | 管理员审核模型版本与运行状态 |

## 8. 需要业务确认的三项决策

1. 首个试点基金类别、预测目标和周期：建议先选择一个具备足量已授权历史净值和明确比较基准的类别；不得默认对全部 43 只基金评分。
2. 回测准入门槛：需要确认独立测试区间、费用口径、长期持有/定投/基准的比较方式，以及收益、回撤、波动和样本量的最低标准。
3. 用户呈现与提醒策略：需要确认评分展示文案、提醒冷却时间、单日上限、历史保留期限，以及是否只允许已关注基金配置规则。

在这三项确认前，系统只能实施 G0 和 G1 的数据质量状态，不得启用方向、概率、提醒投递或页面行动文案。

## 9. v1.1｜2026-09-01 M3-04 受控基线实现默认值

本次仅授权 M3-04 的后台实现，使用以下可替换的保守默认值：

1. 试点固定为 `STOCK`，目标周期为 20 个交易日，只使用已授权并已落库的 Tushare 历史净值。
2. 回测采用扩展训练、验证、独立测试的滚动切分，显式记录 0.15% 费用假设、长期持有和等额分期投入对照。
3. 当前没有已授权且已登记的业绩比较基准序列，因此每次回测必须记录 `BENCHMARK_NOT_CONFIGURED` 并保持 `INELIGIBLE`；不得虚构基准或激活模型。
4. 回测合格时只创建 `ELIGIBLE` 候选发布；只有后续具备 `SYSTEM_ADMIN` 审计入口的人工激活动作才能转为 `ACTIVE`。评分任务没有定时计划，未激活时只落 `MODEL_REJECTED` 等非方向状态。

以上默认值用于完成可验证的工程闸门，不构成任何投资建议、收益承诺或自动交易授权；若后续确认基准、费用或准入阈值，须递增模型版本并重新回测。
