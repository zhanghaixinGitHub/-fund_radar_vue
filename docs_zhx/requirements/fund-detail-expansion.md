## 1. 目标与范围

基金市场向所有已登录用户展示基础资料；“我的关注”中的基金才可查看完整详情。市场范围保持为当前 `fund_ai.fund_share_class` 中 43 个 `ACTIVE`、`TUSHARE_PRO_FUND` 份额，不因本功能自动扩展为 Tushare 全量目录。

本期已完成上述结构化基金数据的代码接入：基金列表/基金公司、基金净值、基金经理、基金规模和基金分红。真实 Tushare 调用仍以前置的最小只读验权为准；在验权完成前不得把接口可用性或保存许可视为已确认。浏览器不得直接请求 Tushare 或 Python，详情打开不得触发外部同步。

## 2. 展示边界

| 区域 | 可见对象 | 内容 |
| --- | --- | --- |
| 基金市场列表与基础详情 | 所有已登录用户 | 名称、代码、类型、基金公司、托管人、成立/上市日期、业绩基准、费率、最新净值和日/周/月涨跌 |
| 我的关注完整详情 | 当前会话中已关注该基金的用户 | 基础详情，以及净值扩展字段、规模、基金经理任职记录、分红记录和历史走势 |

完整详情不得依赖前端路由隐藏。Java 必须先基于当前认证会话确认该基金属于本人关注列表，未关注时返回稳定的 `403/WATCHLIST_REQUIRED`；其他用户的关注关系不得出现在市场接口、Python 内部接口或共享缓存中。本期完整详情不进入共享 Redis，市场基础详情仍可按既有策略缓存。

## 3. 当前期数据字段

1. `fund_basic`：基金公司、托管人、成立/发行/上市/到期/退市及申赎日期、发行份额、管理/托管费、存续期、面值、起购金额、预期收益率、业绩基准、投资风格、产品类型和市场标记。
2. `fund_nav`：公告日期、单位净值、累计净值、累计分红、资产净值、合计资产净值、复权单位净值。
3. `fund_manager`：只保存基金经理姓名、公告日期、任职起止日期和学历；性别、出生年份、国籍与长篇简历不保存或展示。
4. `fund_share`：变动日期与基金份额（万份）。
5. `fund_div`：公告/实施公告/基准/登记/除息/派息日期、方案进度、每份派息、基准份额和收益分配金额。

每个数据区块必须返回来源和数据截至时间。来源尚未同步、接口当前无数据、来源失败后的陈旧快照三种状态必须区分，均不得用 `0`、空图表或“实时”字样替代。

## 4. 非范围与硬边界

- 不接入或调用 `fund_portfolio`、`fund_daily`、`fund_adj`、`fund_factor_pro` 等 5000 积分及以上数据。
- 不恢复 M2 新闻/公告正文采集；结构化分红记录不是资讯正文。
- 不接持仓导入、交易、申购赎回、自动交易、收益承诺、风险评分或方向性买卖建议。
- 基金公司地址、电话、联系人、统一社会信用代码等无展示必要的资料，以及基金经理非必要个人资料，不保存到读模型或前端。

## 5. 验收标准

市场页面持续支持原有筛选、分页、关注额度和净值涨跌展示；完整详情只能被本人关注关系解锁；重复同步不产生重复行；浏览器仅访问 Java；各资料区块能追溯来源、日期和同步状态；数据或权限缺失时安全、明确降级。

## 6. v1.1｜详情概览补全（2026-09-01）

本次补全仅基于已有落库读模型，不新增外部数据源、同步任务、交易功能或方向性结论。

| 优先级 | 区域 | 业务规则 |
| --- | --- | --- |
| P1 | 历史净值解读 | 对用户所选日期窗口展示区间涨跌、最高/最低单位净值及对应日期、实际数据起止日期；涨跌优先以两端累计净值计算，任一端缺失时回退单位净值。少于两条有效记录时明确“数据不足”，不补零。 |
| P1 | 经理与分红时间线 | 已关注用户可按已落库的任职/公告日期查看时间线；经理状态仅为“在任/已离任”，分红仅为来源给出的实施状态，不推断变更原因或未来分红。 |
| P2 | 基金份额规模趋势 | 仅已关注用户可读取明确日期窗口内的 `fund_share_snapshot` 历史；未同步、少于两条记录和接口失败分别展示，不将来源单位换算为资产规模。 |
| P2 | 同类型对比 | 仅比较当前基金市场中 `ACTIVE + TUSHARE_PRO_FUND` 的同基金类型份额，并要求与目标基金同一净值日期且均有近一月涨跌基准。结果必须显式标注受控样本范围，绝不称为全市场排名。 |

公共详情的净值解读和同类型对比仅需 `FUND_READ`；份额规模趋势继续要求 `FUND_READ`、`WATCHLIST_SELF_READ` 和当前会话本人关注关系。页面打开与切换范围均只读取本地历史，不触发 Tushare、同步或交易操作。
