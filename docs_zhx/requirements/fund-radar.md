# 全市场基金雷达 — 需求说明

> 版本：v0.1（总体方案）
> 日期：2026-08-24
> 变更等级：L3（金融信息、外部数据接入、跨 Java/Python 服务）
> 状态：已确认一期方向，待工程实施前确认数据供应商与部署环境

> 本文只说明“要做什么、边界是什么、如何验收”。实施顺序、完成标记和下次恢复位置统一维护在 `docs_zhx/implementation/fund-radar.md`。

## 1. 目标

建设一个面向个人使用的“全市场基金雷达”：对境内公募基金进行日频数据、公告、政策和资讯的统一分析，提供可解释的趋势概率、风险提示、基金筛选和关注列表。

系统帮助用户理解基金相关信息，不承诺收益，不构成确定性的买卖结论，不替用户在支付宝或其他平台执行交易。

## 2. 一期范围

### 2.1 包含

- 全量公募基金产品目录、状态、类型、基金管理人、业绩比较基准等基础信息。
- 按基金类别采集日净值、累计净值、公开公告、定期报告和基金相关公开资讯。
- 按股票、混合、债券、指数、QDII、FOF、货币及其他类别展示基金；不同类别采用不同分析口径。
- 基金列表、筛选、详情页、走势与风险图、资讯时间线、信号解释和个人关注列表。
- 对权威政策、基金公告、授权财经资讯进行去重、来源评级、实体关联和事件分类。
- 基于可复现实验的模型输出“偏强/中性/偏弱、概率、置信度、风险等级、依据、模型版本和数据截至时间”。
- 回测并与同类基准、长期持有和定投基线比较，展示收益、最大回撤、波动率和命中率。
- 提醒规则：关注基金的信号变化、回撤阈值、重大公告或高可信事件。
- 经用户明确确认后，可在本机单用户范围导入持仓快照并展示其原样字段；截图日期、份额或成本缺失时必须保留未知状态，不得推算。

### 2.2 明确不包含

- 不登录、不保存、不抓取支付宝个人账号、密码、验证码、支付凭证或 Cookie。
- 不通过网页自动化、模拟点击或其他非官方方式申购、赎回、买入或卖出基金。
- 不向第三方公开推荐具体基金、代客理财或处理他人资金。
- 不将社交媒体热度或单一新闻直接转化为自动交易指令。
- 一期不要求录入支付宝持仓、成本或交易流水；用户只需搜索并关注基金即可使用。若用户后续选择手工或已确认的截图字段导入，仅支持本机快照，不采集支付宝账户数据。

## 3. 用户与核心场景

| 角色 | 场景 | 预期结果 |
| --- | --- | --- |
| 个人用户 | 浏览全市场基金并按类别、风险、趋势筛选 | 找到可进一步研究的基金，不依赖个人账户数据 |
| 个人用户 | 查看单只基金走势、相关事件与信号理由 | 能核验分析依据、时间和来源 |
| 个人用户 | 关注基金并设置风险提醒 | 发生信号或事件变化时得到提示 |
| 个人用户 | 查看策略回测 | 知道模型是否在未参与训练的数据上优于基线，以及风险代价 |
| 个人用户 | 查看已确认的本机持仓快照 | 看到原始字段、数据日期状态和数据边界，不被误导为实时净值或交易建议 |
| 运营/开发人员 | 管理资讯源、检查采集任务和纠正实体关联 | 数据源可追踪，异常可恢复，模型结论可复现 |

## 4. 关键业务流程

### 4.1 全市场日频分析

1. Python AI 数据任务同步基金目录和公开/授权的日频数据。
2. 系统校验基金代码、份额类别、日期、净值和来源；重复或矛盾数据进入异常队列。
3. 按基金类别生成特征与风险指标；仅在数据完整度达标时产生当日信号。
4. Java 服务接收已签名的信号快照并保存审计记录。
5. 前端通过 Java 接口展示排行、详情、信号和数据截至时间。

### 4.2 资讯到基金关联

1. Python AI 服务从配置且允许接入的来源拉取标题、链接、发布时间、授权范围和必要摘要。
2. 对内容去重并进行来源评级、事件分类、实体提取和时效判断。
3. 先关联行业、指数、基金管理人或公告主体，再依据基金画像关联可能受影响的基金。
4. 前端展示“相关性”而非“因果性”，并始终提供原始来源链接、可信度和模型理由。

### 4.3 个人关注与提醒

1. 用户在前端搜索基金代码或名称并加入关注列表。
2. Java 校验基金有效状态并保存关注与提醒阈值。
3. 每次生成新信号或重大事件后，Java 计算提醒条件；满足条件时生成站内提醒。
4. 用户可查看提醒来源、模型版本和历史变化，但系统不生成可执行交易指令。

### 4.4 用户确认的本机持仓快照

1. 用户明确选择手工字段或截图中已确认的完整字段；系统不读取支付宝账号、Cookie、验证码或支付信息。
2. Java 在本机用户范围保存快照来源、内容哈希、导入时间、截图展示金额/收益/占比与数据日期状态；原图不入库。
3. 截图没有数据日期、份额、成本或交易流水时，分别标记为未知/缺失；不得生成总资产、成本收益率、实时净值或交易结论。
4. Vue 仅经 Java 只读接口展示快照与说明；多人部署前必须将本机用户标识替换为认证上下文与数据隔离。

## 5. 业务规则与异常边界

- 基金净值、公告与模型信号必须带 `as_of_date` 或发布时间；过期数据必须在页面显著标示。
- 同一基金存在不同份额类别时，产品主实体与份额类别分开建模；默认在列表中展示份额类别，不错误合并净值。
- 货币基金不输出“涨跌预测”；只展示收益、流动性和风险提示。
- QDII、ETF、封闭式基金等与普通开放式基金交易/估值规则不同，必须标识产品类别和适用范围，不混入同一排名口径。
- 资讯源超时、限流、授权到期或数据异常时，只降级该来源；既有已校验数据仍可查询，并标识最后成功同步时间。
- 模型数据完整度不足、样本量不足或回测不达标时，不生成“偏强/偏弱”信号，只展示“数据不足/模型不可用”。
- 任何模型结论都必须可定位到输入数据版本、特征版本、模型版本和生成任务编号。
- 用户快照的 `data_as_of_date` 未知时必须为 `NULL` 且页面显著标注未知；截图展示金额不是基金份额、单位净值或可用于回测的市场数据。

## 6. 数据与合规边界

- 优先使用基金管理人、托管人、证监会基金电子披露网站、政府公开信息等权威公开信息；商业行情、财经新闻与社交平台数据必须遵守授权协议、访问频率和保存范围。
- 未取得长期存储授权时，仅保存标题、链接、来源、发布时间、内容摘要、哈希和模型提取标签；不复制或展示完整受版权保护的新闻正文。
- 用户数据仅包括登录标识、关注基金、提醒规则和经用户确认的持仓快照；不采集支付宝认证要素。单用户本机样本只可由本机用户读取；多人部署前必须补充认证、授权、数据保留、删除与导出方案。
- 未来若从“个人工具”扩展为对外服务、公开荐基或交易执行，必须重新进行合规、牌照、适当性与平台授权评审；不得沿用本方案直接上线。

## 7. 一期验收标准

- 用户无需导入支付宝数据，即可按基金类型、名称或代码查看全市场基金及其最近有效数据。
- 每个信号都显示数据截至时间、模型版本、风险等级和至少一项可阅读的依据。
- 每条资讯可追溯来源链接、发布时间、可信度和关联对象。
- 数据源或模型异常不会产生伪造信号，不影响已缓存的历史查询。
- 前端不能直接访问 FastAPI AI 服务或任何资讯源凭证。
- 页面、接口、日志和数据库均不出现支付宝密码、验证码、Cookie 或支付信息。
- 已确认的快照数据必须可追溯导入来源和日期状态；重复导入不产生重复快照，未知字段不被自动补写。

2. 前端技术栈是否确定为 Vue 3 + TypeScript + Vite + ECharts。
3. 一期是否只面向个人单用户部署；若支持多人账号，需要补充租户隔离、注册登录、数据保留和对外合规方案。
