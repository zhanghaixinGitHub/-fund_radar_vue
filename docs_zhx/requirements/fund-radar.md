# 全市场基金雷达 — 需求说明

> 版本：v0.1（总体方案）
> 日期：2026-08-24
> 变更等级：L3（金融信息、外部数据接入、跨 Java/Python 服务）
> 状态：已确认一期方向，待工程实施前确认数据供应商与部署环境

> 本文只说明“要做什么、边界是什么、如何验收”。实施顺序、完成标记和下次恢复位置统一维护在 `docs_zhx/implementation/fund-radar.md`。

## 1. 目标

建设一个面向个人使用的“全市场基金雷达”：对境内公募基金进行日频数据、公告、政策和资讯的统一分析，提供可解释的趋势概率、风险提示、基金筛选和关注列表。

系统帮助用户理解基金相关信息，不承诺收益，不构成确定性的买卖结论，不替用户在支付宝或其他平台执行交易。

## 2. 一期范围

### 2.1 包含

- 全量公募基金产品目录、状态、类型、基金管理人、业绩比较基准等基础信息。
- 按基金类别采集日净值、累计净值、公开公告、定期报告和基金相关公开资讯。
- 按股票、混合、债券、指数、QDII、FOF、货币及其他类别展示基金；不同类别采用不同分析口径。
- 基金列表、筛选、详情页、走势与风险图、资讯时间线、信号解释和个人关注列表。
- 对权威政策、基金公告、授权财经资讯进行去重、来源评级、实体关联和事件分类。
- 基于可复现实验的模型输出“偏强/中性/偏弱、概率、置信度、风险等级、依据、模型版本和数据截至时间”。
- 回测并与同类基准、长期持有和定投基线比较，展示收益、最大回撤、波动率和命中率。
- 提醒规则：关注基金的信号变化、回撤阈值、重大公告或高可信事件。
- 经用户明确确认后，可在本机单用户范围导入持仓快照并展示其原样字段；截图日期、份额或成本缺失时必须保留未知状态，不得推算。

### 2.2 明确不包含

- 不登录、不保存、不抓取支付宝个人账号、密码、验证码、支付凭证或 Cookie。
- 不通过网页自动化、模拟点击或其他非官方方式申购、赎回、买入或卖出基金。
- 不向第三方公开推荐具体基金、代客理财或处理他人资金。
- 不将社交媒体热度或单一新闻直接转化为自动交易指令。
- 一期不要求录入支付宝持仓、成本或交易流水；用户只需搜索并关注基金即可使用。若用户后续选择手工或已确认的截图字段导入，仅支持本机快照，不采集支付宝账户数据。

## 3. 用户与核心场景

| 角色 | 场景 | 预期结果 |
| --- | --- | --- |
| 个人用户 | 浏览全市场基金并按类别、风险、趋势筛选 | 找到可进一步研究的基金，不依赖个人账户数据 |
| 个人用户 | 查看单只基金走势、相关事件与信号理由 | 能核验分析依据、时间和来源 |
| 个人用户 | 关注基金并设置风险提醒 | 发生信号或事件变化时得到提示 |
| 个人用户 | 查看策略回测 | 知道模型是否在未参与训练的数据上优于基线，以及风险代价 |
| 个人用户 | 查看已确认的本机持仓快照 | 看到原始字段、数据日期状态和数据边界，不被误导为实时净值或交易建议 |
| 运营/开发人员 | 管理资讯源、检查采集任务和纠正实体关联 | 数据源可追踪，异常可恢复，模型结论可复现 |

## 4. 关键业务流程

### 4.1 全市场日频分析

1. Python AI 数据任务同步基金目录和公开/授权的日频数据。
2. 系统校验基金代码、份额类别、日期、净值和来源；重复或矛盾数据进入异常队列。
3. 按基金类别生成特征与风险指标；仅在数据完整度达标时产生当日信号。
4. Java 服务接收已签名的信号快照并保存审计记录。
5. 前端通过 Java 接口展示排行、详情、信号和数据截至时间。

### 4.2 资讯到基金关联

1. Python AI 服务从配置且允许接入的来源拉取标题、链接、发布时间、授权范围和必要摘要。
2. 对内容去重并进行来源评级、事件分类、实体提取和时效判断。
3. 先关联行业、指数、基金管理人或公告主体，再依据基金画像关联可能受影响的基金。
4. 前端展示“相关性”而非“因果性”，并始终提供原始来源链接、可信度和模型理由。

### 4.3 个人关注与提醒

1. 用户在前端搜索基金代码或名称并加入关注列表。
2. Java 校验基金有效状态并保存关注与提醒阈值。
3. 每次生成新信号或重大事件后，Java 计算提醒条件；满足条件时生成站内提醒。
4. 用户可查看提醒来源、模型版本和历史变化，但系统不生成可执行交易指令。

### 4.4 用户确认的本机持仓快照

1. 用户明确选择手工字段或截图中已确认的完整字段；系统不读取支付宝账号、Cookie、验证码或支付信息。
2. Java 在本机用户范围保存快照来源、内容哈希、导入时间、截图展示金额/收益/占比与数据日期状态；原图不入库。
3. 截图没有数据日期、份额、成本或交易流水时，分别标记为未知/缺失；不得生成总资产、成本收益率、实时净值或交易结论。
4. Vue 仅经 Java 只读接口展示快照与说明；多人部署前必须将本机用户标识替换为认证上下文与数据隔离。

## 5. 业务规则与异常边界

- 基金净值、公告与模型信号必须带 `as_of_date` 或发布时间；过期数据必须在页面显著标示。
- 同一基金存在不同份额类别时，产品主实体与份额类别分开建模；默认在列表中展示份额类别，不错误合并净值。
- 货币基金不输出“涨跌预测”；只展示收益、流动性和风险提示。
- QDII、ETF、封闭式基金等与普通开放式基金交易/估值规则不同，必须标识产品类别和适用范围，不混入同一排名口径。
- 资讯源超时、限流、授权到期或数据异常时，只降级该来源；既有已校验数据仍可查询，并标识最后成功同步时间。
- 模型数据完整度不足、样本量不足或回测不达标时，不生成“偏强/偏弱”信号，只展示“数据不足/模型不可用”。
- 任何模型结论都必须可定位到输入数据版本、特征版本、模型版本和生成任务编号。
- 用户快照的 `data_as_of_date` 未知时必须为 `NULL` 且页面显著标注未知；截图展示金额不是基金份额、单位净值或可用于回测的市场数据。

## 6. 数据与合规边界

- 优先使用基金管理人、托管人、证监会基金电子披露网站、政府公开信息等权威公开信息；商业行情、财经新闻与社交平台数据必须遵守授权协议、访问频率和保存范围。
- 未取得长期存储授权时，仅保存标题、链接、来源、发布时间、内容摘要、哈希和模型提取标签；不复制或展示完整受版权保护的新闻正文。
- 用户数据仅包括登录标识、关注基金、提醒规则和经用户确认的持仓快照；不采集支付宝认证要素。单用户本机样本只可由本机用户读取；多人部署前必须补充认证、授权、数据保留、删除与导出方案。
- 未来若从“个人工具”扩展为对外服务、公开荐基或交易执行，必须重新进行合规、牌照、适当性与平台授权评审；不得沿用本方案直接上线。

## 7. 一期验收标准

- 用户无需导入支付宝数据，即可按基金类型、名称或代码查看全市场基金及其最近有效数据。
- 每个信号都显示数据截至时间、模型版本、风险等级和至少一项可阅读的依据。
- 每条资讯可追溯来源链接、发布时间、可信度和关联对象。
- 数据源或模型异常不会产生伪造信号，不影响已缓存的历史查询。
- 前端不能直接访问 FastAPI AI 服务或任何资讯源凭证。
- 页面、接口、日志和数据库均不出现支付宝密码、验证码、Cookie 或支付信息。
- 已确认的快照数据必须可追溯导入来源和日期状态；重复导入不产生重复快照，未知字段不被自动补写。

## 8. 实施前待确认项

1. 一期的市场数据和财经新闻采用哪些已授权供应商；官方披露数据可作为基础，但不能默认视为批量商业使用授权。
2. 前端技术栈是否确定为 Vue 3 + TypeScript + Vite + ECharts。
3. 一期是否只面向个人单用户部署；若支持多人账号，需要补充租户隔离、注册登录、数据保留和对外合规方案。

## 11. v0.4｜2026-08-27 重点基金完整数据闭环变更

本次判定：L2 中等改动 — 在全市场目录完整性未满足的前提下，将 M1 的实际交付范围收敛为用户指定的六只重点基金，并补齐其从成立以来至最近可得日期的历史净值、只读查询接口和详情走势图。

当前重点基金清单固定为 `010710.OF`、`160323.SZ`、`013275.OF`、`007832.OF`、`002112.OF`、`005312.OF`。系统只会同步这六个精确代码；不得把列表、筛选或净值覆盖表述为“全市场”，也不得因某次接口只返回部分代码而写入部分结果。

每只基金的目录查询必须精确命中一个预期代码；历史净值请求必须带起止日期，单次响应达到本机安全上限、存在非目标代码、缺少任一目标基金或返回空历史时，整次运行失败关闭且不写入本次结果。已校验的历史净值按份额代码、净值日期、来源幂等保存；同步运行记录仅保存统计和脱敏错误摘要，不保存 Token 或原始响应。

详情页提供近三月、近一年、近三年和成立以来四个范围，展示真实单位净值时间序列、数据截至日、来源及缓存陈旧状态。浏览器只访问 Java，Java 再访问受服务 Token 保护的 FastAPI；历史查询最多 5,000 天，读取失败可展示已有缓存并明确标记陈旧。该曲线仅用于信息展示，不生成评分、买卖建议或交易功能。

## 12. v0.5｜2026-08-27 重点基金工作日增量同步变更

本次判定：L2 中等改动 — 为已完成完整历史回填的六只重点基金增加可配置的工作日净值增量同步，不扩展到全市场、资讯、评分、买卖建议或交易。

每个基金的同步水位必须从 `TUSHARE_PRO_FUND` 来源的本地 `nav_daily` 读取，不能由其他来源记录推进。工作日默认在 `Asia/Shanghai` 20:00 由一个 Celery Beat 实例触发；每只基金只请求“该来源最后净值日的次日”到本轮日期的窗口。时间、开关和精确基金代码均只能从本机环境配置读取。

首次历史回填尚未完成、重点代码重复或返回窗口外/非目标基金净值时，本次运行失败关闭且不写入不可信记录。遇中国节假日或当晚未发布净值时，可安全完成为零变更；不得把零变更伪造成已获得当日净值。每次运行继续写入 `source_sync_run` 的 `FOCUSED_NAV_INCREMENTAL` 类型，保留日期、计数和脱敏错误摘要，绝不保存 Token 或原始响应。

## 14. v0.7｜2026-08-27 本地页面手动净值同步变更

本次判定：L2 中等改动 — 为本地运行场景增加详情页“同步六只重点基金净值”按钮，用于错过工作日 20:00 自动计划后的手动补数。

我按七维检查，仅以下 2 项存在真实风险：

1. 稳定性与并发：手动同步可能包含多日缺口且与定时任务重叠；手动和 Celery 任务必须共用 PostgreSQL 咨询锁，已有运行时返回冲突，不重复调用 Tushare，也不覆盖已有可信净值。
2. 服务边界与可用性：浏览器不得直连 FastAPI 或 Tushare；Vue 只能调用 Java `POST /api/v1/funds/sync/focused-nav-incremental`，Java 使用服务令牌调用 Python。人工请求允许较长等待但不影响普通读模型的 3 秒超时；页面必须禁用重复点击、显示结果或失败信息。

手动同步始终处理配置中的六只精确基金代码，沿用同源水位、窗口校验、幂等写入、`source_sync_run` 记录和失败关闭语义。它不要求本机启动 Beat 或 Worker，但仍要求 Python、Java、Vue、PostgreSQL 及已配置的 Tushare 凭据可用；不新增全市场目录、评分、买卖建议或交易能力。

## 15. v0.8｜2026-08-27 数据同步中心与可观察进度变更

本次判定：L2 中等改动 — 将手动同步入口从基金详情页迁移至独立“数据同步中心”，并将长时间同步改为“创建后台任务 + 查询进度”的交互模式，为后续多个同步任务提供统一入口。

我按七维检查，仅以下 3 项存在真实风险：

1. 稳定性与并发：本机手动任务与 Celery 定时任务仍可能重叠；同步中心只允许一个活动任务，实际数据同步继续以 PostgreSQL 咨询锁与 Celery 共用，锁竞争必须安全失败且不重复写库。
2. 可观测性：页面必须展示服务端返回的任务阶段、当前基金、完成步数和最终统计；失败必须有脱敏、可操作的说明，不能把“已创建任务”误报为“已同步完成”。
3. 本机运行边界：任务进度保存于当前 Python 进程内，Python 服务重启会使任务状态失效；页面应停止轮询并提示重新发起，不能伪造历史运行结果。

Vue 只能访问 Java 的 `/api/v1/sync-jobs`；Java 仅使用服务令牌访问 Python 的内部同步任务接口。创建任务应立即返回，轮询使用短读取超时，不能再让页面请求长时间占用连接。当前仅登记“重点基金净值增量同步”一项；范围、数据源、六只基金配置、历史基线、幂等写入和非交易/非买卖边界均保持不变。

## 16. v0.9｜2026-08-27 重点基金列表页码分页变更

本次判定：L2 中等改动 — 重点基金列表需要向用户展示当前筛选下的总条数、可选每页条数，并支持直接跳转页码。它不改变重点基金配置、净值同步、关注写入、持仓金额或任何交易边界。

列表默认每页 20 条，页面提供 10、20、50 三档；展示“共 X 条”和“第 P / N 页”，支持上一页、下一页及 1 至 N 的页码跳转。修改关键字或每页条数时必须回到第 1 页；空结果显示 0 条且不显示不可用的翻页控件。页码输入无效、超范围或小于 1 时，前端必须限制到有效范围，服务端仍独立校验最大页码，不能依赖浏览器校验。

我按七维检查，仅以下 2 项存在真实风险：

1. 查询性能与结果一致性：总条数必须与当前关键字使用相同筛选条件；服务端执行受限 `COUNT` 与单页查询，`pageSize` 最多 100，不允许浏览器为跳转而拉取完整目录。
2. 兼容性与缓存：已发布的 `cursor` 查询继续可用；新增 `page` 时不能与 `cursor` 同时使用。Java 缓存键必须包含关键字、页大小、游标和页码，陈旧缓存也不得返回到另一页。

验收时，总数、页数和本页条数必须与接口响应一致；搜索、切换每页条数、边界页与直接跳转均正确可用；列表仍保持 Vue → Java → FastAPI 的只读链路，不增加外部数据调用、数据表或数据写入。

## 17. v1.0｜2026-08-27 用户登录、前后台分区与数据归属变更

本次判定：L2 中等改动 — 从本机单用户页面升级为登录后的多账户数据隔离；不改变基金数据来源、同步范围、持仓导入边界或非交易原则。

基金市场、基金详情、关注、提醒和持仓均要求用户先以中国大陆 11 位手机号和密码登录。登录只校验已注册手机号，未注册手机号返回统一认证失败且不创建账户；新用户在独立注册页确认手机号和两次密码后创建默认 `FUND_USER` 并建立会话。当前不接短信，手机号只是未核验登录标识；密码为 6 至 20 位字符且只能由系统管理员人工重置。

`FUND_USER` 仅可读取基金与本人数据；`DATA_OPERATOR` 可进入同步和运行状态，但不能查看或管理用户；`SYSTEM_ADMIN` 拥有全部当前与后续权限，能够在受控后台查看指定用户已确认的持仓金额。历史本机账户的关注必须由管理员二次确认后迁移给一名已启用用户，提醒和持仓不会自动迁移。完整手机号、密码、Cookie、CSRF 值和首位管理员配置不得进入 Vue 状态、日志、文档或 Git。

用户端与后台管理端为两个独立路由区域：用户端顶栏只显示基金市场、我的关注、我的持仓；后台顶栏只显示工作台、数据同步、用户管理和运行状态。具备任一后台权限的用户通过右上角账户下拉框中的“后台管理”以新标签页打开 `/admin`，原前台页保持不变；后台账户菜单不提供“返回前台”。前端仅据服务端权限显示入口，直接访问后台仍由路由守卫与 Java 服务端授权共同拦截。
