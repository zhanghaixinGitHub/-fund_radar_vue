# 基金雷达待办：重大事件卖出提醒与统一打分公式

记录日期：2026-10-14

状态：**待办，未排期、未实施、未完成效果验证。**

本文件记录本次讨论的两项后续需求。适用于所有基金，不按002112、016008等基金代码设置资格限制；实际分析须匹配各基金自身投向、资料和交易规则。本次仅记录待办，不启用通知、不执行交易，也不将下文建议当作已生效规则。

关联规则：[综合预测统一规则 V1](../design/comprehensive-prediction-rules-v1.md)。现有综合资料审阅规则不等于已经建立经验证的统一打分公式；下述评分也不等同于基金长期质量评级，不能直接把长期评级当成短期卖出信号。

## 待办一：重大事件与卖出风险提醒

**用户需求：** 当某只基金出现重大不利事件，或下行风险明显升高时，在页面醒目提示，帮助用户及时判断是否需要减仓、卖出或重新评估持有理由。

- [ ] 建立覆盖所有基金的重大事件识别与关联流程，ETF联接基金穿透目标ETF及相关资产；仅当实际投向有关联时才纳入判断。
- [ ] 核验公告、政策、新闻等原始来源，记录公开时间、实际取得时间、事件阶段、影响对象和传导路径；区分调查、立案、计划、实际执行和已确认损失。
- [ ] 设计风险分级和触发条件，例如一般关注、风险升高、重大风险；具体等级、阈值和提示用语在验证后确定。
- [ ] 区分重大事件提示、综合下行风险提示与个人退出条件。单日下跌、连续下跌、持仓集中或公告数量不能单独推出“必须卖出”。
- [ ] 为提醒保存相反证据、关键未知、失效条件和复核时间；来源不足或过期时说明缺口，不能把未取得信息当成利空。
- [ ] 在关注列表、基金详情等合适位置提供明显但克制的标识，展示“发生了什么、为什么影响本基金、何时更新、建议如何复核”。提醒位置和等级保持一致，避免重复堆叠卡片。
- [ ] 支持提醒去重、重大进展更新、解除与历史查看；同一事件的多份公告不能重复增强风险等级或反复轰炸用户。
- [ ] 将止盈目标、可承受亏损、持有期限、仓位及交易费用作为可选的个人判断条件，与基金公共风险分开保存；未设置时不擅自推定。
- [ ] 明确卖出建议的适用条件、信息时效、赎回费用和交易限制。功能仅提供提醒和建议，不自动提交卖出或赎回。

**验收条件：**

- [ ] 不依赖特定基金代码；资料支持时，不同基金均可触发对应提醒。
- [ ] 每条重大风险提醒都能追溯到当时来源及基金投向关系，并能说明升级、维持或解除的原因。
- [ ] 未经概率校准和独立验证，不展示“下跌概率极高”“九成会跌”等概率或确定性结论，也不把内部风险分写成下跌概率。
- [ ] 有效提示与误报、漏报、提醒提前量、重复提醒次数都有明确统计口径；重要事件案例和普通市场波动案例均纳入验证。
- [ ] 页面只展示用户能理解的基金风险和必要依据；服务端继续限制本人关注、持仓及个人设置的访问范围。

## 待办二：建立并验证统一打分公式

**用户需求：** 综合判断应具有稳定、可复核的打分依据，避免每次临时选择因素、调整权重或凭新闻条数判断方向。

- [ ] 先确定评分目标：预测哪个周期的方向、评估多大范围的下行风险，以及如何核对结果；不能用一个未定义的总分同时代替方向、概率、长期质量和卖出建议。
- [ ] 建立统一因子字典，定义数据来源、业务含义、单位、方向、有效期限、标准化方法和缺失处理。候选维度包括实际投向、相关市场、行业、财务、公告、新闻、政策、估值、经理与资金变化；净值只作为综合输入的一部分。
- [ ] 制定统一计算框架。股票、债券、跨境、商品等资产及一日、五日、二十日、半年等周期允许采用经过验证的不同因子和权重，不能机械套用同一组比例。
- [ ] 研究并验证公式、权重、交互条件和触发阈值；先冻结候选方案，再验证。**本待办不预先指定未经验证的权重或分数线。**
- [ ] 合并同一事件的重复报道；净值、持仓和指数反映同一行情时处理相关性，避免重复计权。重大事件的独立触发条件也要可追溯，不能凭主观临时加分。
- [ ] 将下行风险评分、资料完整性与可信程度、个人操作建议分开。资料不足不能填零、当作利空，或任意重分配权重；缺口影响主判断时暂不评分。
- [ ] 按时间先后划分开发、验证和独立测试区间，进行滚动检验；仅使用当时已公开且符合截止规则的数据，不读取目标日结果后修改原判断。
- [ ] 与简单基线比较，评估方向表现、下行事件识别、误报漏报、提前量及交易成本影响；样本要覆盖不同基金、市场阶段和失败情形，不能只挑预测成功日期。
- [ ] 如需展示涨跌概率，另行完成概率校准、样本量和稳定性检验；风险分高不等于下跌概率高，格式校验通过也不等于有预测能力。
- [ ] 保存公式与因子版本、权重、阈值、输入快照、首次结果及失败记录；变更追加新版本，不覆盖历史，也不把事后回看混入事前预测表现。

**验收条件：**

- [ ] 相同输入、相同规则版本可复现相同得分，并能解释各主要因素的作用和相反证据。
- [ ] 公式、权重和阈值具有独立验证记录，适用基金类型、周期及失效条件明确；不以单只基金、少量日期或一次回测结果证明普遍有效。
- [ ] 样本总数、有效判断、拒判、失败和缺资料情形均如实记录；评分效果与资料可用率分开报告。
- [ ] 页面展示必要业务结论和依据，公式参数保留在开发与核验资料中；未通过验证时明确标为待验证，不宣称已有可靠胜率。

## 两项待办的衔接

重大事件提醒可以先建立来源核验、基金关联、去重和明确的事件提示，不必等评分研究全部完成。基于综合风险分触发减仓或卖出建议，则必须等待评分目标、公式和阈值取得相应验证证据。

后续实施时再确定排期、具体数据覆盖、提醒位置和验证门槛；完成一项验收后才能勾选对应任务。本次“文档已记录”不代表以上功能已完成。
