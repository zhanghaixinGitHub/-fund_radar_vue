# 我的持仓总览：实际资产、股票行业与主题分布

适用工程：`01-vue`、`02-java`、`03-python`。页面遵循[统一样式与交互规范](../../DESIGN.md)，功能登记见[功能保全清单](../design/frontend-redesign-functional-baseline-2026-11-13.md)。

## 1. 目标与结论

在“我的持仓－总览”增加“持仓构成”，同时提供以下三个视图：

1. **实际资产分布**：股票、债券、基金、现金及其他，以及资料待补充部分。
2. **股票行业分布**：按基金报告披露的行业分类，展示已披露股票主要投向哪些行业。
3. **主题分布**：按已核验的股票主题对应关系，展示芯片、通信、石油、食品、游戏等主题在已披露股票中的占比。

三种分布都是本需求的必需项。可以分批开发和验证，但不能只完成实际资产与行业分布，就把整个需求标记为完成。

这些图用于理解持仓结构，不用于推断基金经理实时调仓，也不直接生成买卖建议。基金类型（混合型、股票型、债券型等）分布不在本次新增范围内。

## 2. 统计对象、权限与运行边界

### 2.1 统计对象

- 统计对象与同一总览“持有金额”的账户范围保持一致，只读取当前会话绑定本人的模拟账户，不使用关注列表代替持仓。
- 正份额模拟持仓，以及现有总览明确纳入持有金额的已确认持仓，按原账本与汇总口径处理。待确认买入尚未计入持有金额的，不得提前计入图表。
- 已清仓且当前持有金额为零的基金不产生分类金额。真实零值保留为零，资料缺失保持未知，二者不能混用。
- 只有基金名称、没有可用持有金额的确认记录，不反推金额，不伪造图表占比；需要在资料说明中保留未统计原因。
- 图表刷新不得改变现有账户汇总、收益、订单、定投和结算口径。

### 2.2 权限与只读要求

- 本人页面沿用 `PORTFOLIO_SELF_READ`，用户编号只从当前会话取得，前端不得通过传参读取他人账户。
- 如管理员查看指定用户持仓时复用该能力，必须继续由服务端校验 `PORTFOLIO_USER_READ`，不能借用本人权限绕过。
- 本功能只读，不新增写权限，不在打开页面、切换视图或查看来源时触发采集、训练、预测、下单、结算或资料清理。
- 不因本功能改变现有每日任务、独立收益更新、定投下单与订单结算授权，也不新增自动任务。
- 日常前台不展示接口、模型、训练、解析或任务调度细节。

## 3. 页面入口与信息结构

### 3.1 位置和顺序

总览正文按以下顺序组织：

1. 原有“持有金额、持有收益、累计收益”三个汇总项。
2. 原有待确认交易提示；存在待确认交易时继续保持醒目。
3. 新增“持仓构成”区块。
4. 原有后台运行状态与最近完成时间。

不删除或移动八个持仓栏目，不在总览增加基金搜索框和查询按钮，不影响“添加基金”等原操作。

### 3.2 视图切换

“持仓构成”使用同一组文字页签：

- 实际资产
- 股票行业
- 主题分布

默认显示“实际资产”。选中项使用绿色文字和绿色下划线，不使用深绿实心块。页签单行显示，窄屏允许自身横向滚动，但不能挤破整个页面。

当前视图应可通过总览地址查询参数保存，刷新、详情返回和浏览器前进后退后保留；离开总览时不把该参数带到无关栏目。切换视图只改变图表，不清空现有持仓、交易或收益条件，并保留右侧工作区当前滚动位置，不能跳到页面顶部。

### 3.3 图表与来源明细

- 实际资产与股票行业、主题分布一致，使用每个资产类型一行的横向条形列表，配文字比例和估算金额，不再使用单条堆叠图。
- 股票行业使用横向条形列表，默认展示前五项，其余合并为“其他行业”；可以展开查看全部已披露行业。“行业待补充”单列，不能并入“其他行业”。
- 主题分布使用彼此独立的横向条形列表，不使用要求合计为100%的堆叠图，不设置貌似完整的“其他主题”来掩盖未分类部分。
- 鼠标悬浮、键盘焦点和触屏选择都能查看分类名称、比例、估算金额、统计范围和必要说明，不能只支持悬浮。
- 查看分类来源时使用右侧抽屉，列出贡献该分类的基金、采用的报告期、覆盖情况和来源说明。抽屉只读，支持关闭按钮、Esc和点击框外关闭；关闭后保留原页签和滚动位置。
- 所有图形必须有对应的文字数值，读屏无需辨认颜色也能获得同样信息。

## 4. 实际资产分布口径

### 4.1 分类

基金报告中的资产项归并为：

| 页面分类 | 报告资产项 |
| --- | --- |
| 股票 | 股票 |
| 债券 | 债券 |
| 基金 | 基金；包括直接披露的目标基金或其他基金投资 |
| 现金及其他 | 现金及结算资金、其他资产 |
| 待补充 | 当前持有金额已纳入总览，但缺少可核验资产配置的部分 |

“待补充”是账户资料覆盖状态，不是基金报告中的资产类别，不能算成现金或其他资产。

### 4.2 计算方法

对每只具有可用持有金额和资产配置报告的基金：

```text
某资产分类估算金额
= 各基金当前持有金额 × 该基金最近可核验报告中该分类占总资产比例，再求和
```

账户分类比例为各分类估算金额除以本次纳入统计的总持有金额。没有资料的基金持有金额进入“待补充”，因此页面能够同时看出分类结果和资料缺口。

这里的金额是按历史披露配置映射得到的**估算金额**，不是实时底层证券市值，也不是会计意义上的净资产穿透。基金报告“资产配置占总资产”和“行业、股票持仓占净资产”是不同分母，禁止直接相加或拼成同一张100%图表。

### 4.3 基金投资的处理

- 实际资产视图保留“基金”类别，不把ETF联接基金、FOF等直接持有的基金未经核验就全部算作股票。
- 后续即使行业或主题视图使用了已核验的底层基金资料，也不得让直接资产与底层资产重复计数。
- 无法核验底层基金的，保留原类别并说明未穿透范围。

## 5. 股票行业分布口径

### 5.1 数据来源与范围

- 优先使用同一基金、同一报告期的行业汇总表，保留报告原始行业名称、分类标准、报告期和公布日期。
- 行业分布仅描述股票，不包含债券、现金和未穿透基金，图名必须保留“股票”二字。
- 行业汇总完整性与前十大个股明细完整性分别判断。季度报告只有主要个股明细，不必然意味着行业汇总也只能覆盖前十大。
- 不同市场采用不同行业分类标准时，先保留原标准；没有经过核验的统一映射，不得把名称相近的行业直接合并。

### 5.2 计算方法

基金报告中的行业权重通常以基金净资产为分母：

```text
基金股票估算金额 = 基金当前持有金额 × 报告股票占基金净资产比例
基金某行业估算金额 = 基金当前持有金额 × 报告该行业占基金净资产比例
```

“股票行业分布”的100%指本次可确定股票估算金额的范围，不是整个账户持有金额。行业资料不足的股票部分显示为“行业待补充”；连股票占净资产比例也无法可靠取得的基金，不进入该100%分母，另行说明其账户金额和未覆盖原因。

页面至少同时说明：

- 行业图统计的是已披露股票部分，不是整个账户。
- 行业资料覆盖了多少账户持有金额，或覆盖了多少可统计股票金额。
- 各基金报告期是否一致；不一致时展示报告日期范围，并在来源抽屉保留逐基金日期。

不得把行业占净资产比例与资产占总资产比例混算，也不得从“制造业”等宽行业直接推算芯片、食品等更细比例。

### 5.3 底层基金

ETF联接基金、FOF等只有在目标基金身份、持有比例和同一口径底层行业资料均可核验时，才可纳入穿透计算。直接股票与底层股票分别计算后合并一次；未穿透或日期无法合理对齐的部分进入待补充，不按零处理。

## 6. 主题分布口径

### 6.1 主题与行业分开

主题是跨行业或更细的投资标签。芯片、游戏、人工智能等可能分别落入不同的报告行业，一家公司也可能同时属于多个主题。因此：

- 主题图允许一家公司计入多个主题，各主题比例独立计算。
- 各主题比例之和可以小于、等于或大于100%，页面不得强行归一化为100%。
- 行业图中的“通信”等名称与主题图中的同名标签必须保留各自定义和来源，不能仅凭名称相同就共用比例。
- 主题分布默认按估算金额降序排列，不使用饼图或堆叠图暗示它们互斥。

### 6.2 主题对应关系

每个主题至少需要保存：稳定标识、显示名称、定义、纳入与排除条件、股票对应关系、来源、分类日期或生效日期、核验状态。

不得根据基金名称、股票名称中的词语或近期涨跌直接猜测主题。主题来源无法核验、对应关系过期或股票身份不一致时，该部分保持待补充。

主题分类规则需要在实施前形成可复查的数据说明；本文不预先编造任何股票的主题归属。

### 6.3 计算与覆盖范围

主题计算基于有个股身份和权重的已披露股票：

```text
某主题估算金额
= 属于该主题的已披露股票，按基金当前持有金额和报告个股占净资产比例映射后求和
某主题比例
= 该主题估算金额 ÷ 已有个股披露且可统计的股票估算金额
```

已核验底层基金可以按实际持有比例纳入同一计算，但必须避免直接持仓与穿透持仓重复。只有前十大股票时，图例和说明必须写“已披露主要股票主题”，不能代表整只基金或整个账户。

页面分别保留：

- **个股披露覆盖率**：有个股明细支持的股票估算金额占可统计股票估算金额的比例。
- **主题对应覆盖率**：已有个股明细中，完成主题核验映射的金额比例。

没有出现在某主题中的已披露股票，只能说明“在当前已披露与已映射范围内未计入该主题”，不能证明基金实际完全没有该主题投资。

## 7. 日期、来源与缺失状态

- 所有视图都标明“按最近可核验报告估算，不代表实时持仓”。
- 持有金额采用的净值日期与持仓报告日期分别说明，不把报告期末写成当前日期。
- 不同基金报告期不一致时显示真实日期范围，不用最新一只基金的日期覆盖全部结果。
- 来源抽屉能够逐基金查看报告期、公布日期、来源链接或来源说明，以及主题分类日期。
- 缺少必要资料时显示“—”、待补充或具体原因，不以零替代。
- 资料冲突、金额对账失败或基金身份无法确认时，不发布该部分精确结果。

页面需分别处理：

| 状态 | 页面表现 |
| --- | --- |
| 加载中 | 明确正在读取，不绘制虚构条形图 |
| 空账户 | 说明暂无正份额持有金额，不显示全零分布 |
| 部分资料 | 展示已核结果与待补充比例，说明统计范围 |
| 完全无资料 | 显示暂时无法形成分布及原因，不显示100%未知资产结论 |
| 资料过期 | 保留真实报告日期和滞后提示 |
| 读取失败 | 提供重试；已有成功结果时不得把旧结果伪装成刚更新成功 |
| 无权限 | 不泄露任何本人或他人持仓及分类金额 |

## 8. 视觉与交互规范

- 使用公共颜色、文字、间距、边框、页签、抽屉和状态组件，不为本页面单独制作一套皮肤。
- 图表分类颜色需要新增公共图表变量；红涨绿跌的含义保持不变，不能只用红绿区分资产、行业或主题。
- 普通正文对比度至少4.5:1，大字至少3:1；每个分类同时显示名称和数值，不只依赖颜色。
- 不增加多层卡片包裹。“持仓构成”是一个克制的内容区块，三个视图共用同一位置，不同时铺开三张大卡片。
- 金额使用等宽数字，比例精度在同一视图保持一致；金额和百分比不混列。
- 桌面检查1440和1280宽度，同时检查平板、手机和矮窗口。手机采用图表在上、文字图例在下，允许列表自身滚动，不产生整个页面横向滚动。
- 左侧导航保持固定，右侧工作区独立滚动；切换页签、打开来源抽屉或返回页面不得引起左栏跳动。
- 普通文字链接不添加下划线；键盘焦点、悬停、按下、禁用和加载状态清楚可见。
- 抽屉管理焦点，Tab不进入背景，关闭后焦点回到触发元素；打开抽屉时不得误触发底层交易操作。

## 10. 验收条件

### 10.1 计算与数据

- 用合成数据分别验证单一基金、多只基金、不同报告期、部分缺资料、真实零值和空账户。
- 验证实际资产分类与待补充金额能够和本次纳入统计的持有金额对账；不把未知补成现金或其他。
- 验证行业占净资产与资产占总资产没有混加，行业图明确只统计股票范围。
- 验证同一股票属于多个主题时，各主题独立计算且不强制合计100%。
- 验证只有前十大股票时，页面只声明已披露主要股票主题。
- 验证ETF联接或FOF穿透不会重复计算；不能穿透时保留待补充。
- 验证待确认订单不提前计入、已清仓零金额不产生分类、不同净值日期不伪装成同一日期。
- 验证本人数据隔离和管理员权限，任何查询都不产生订单、结算、训练或资料清理写入。

### 10.2 页面与交互

- 使用本人真实登录页面检查三个页签、真实数据、来源抽屉、刷新和浏览器返回，不以组件截图代替正式验收。
- 检查加载、空账户、部分资料、完全无资料、过期、失败重试和无权限状态。
- 检查鼠标、键盘、触屏和读屏；所有悬浮信息都有键盘和触屏获取方式。
- 检查1440、1280、平板、手机和矮窗口，确认左栏固定、右侧独立滚动、页签不挤破、抽屉焦点正确。
- 确认原三个汇总项、待确认提示、八个栏目、添加基金和原有返回条件均未退化。

### 10.3 交付证据

- 按项目统一入口执行构建及相关回归检查，并记录真实结果。
- 在功能清单登记P16的实现位置、权限、只读属性和验证证据；未验证项保持“待验收”。
- 三种分布及来源说明全部验收后，本需求才可标记完成。任何资料覆盖不足都应作为真实限制保留，不能通过隐藏待补充部分制造完整假象。
