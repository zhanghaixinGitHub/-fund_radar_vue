## TC-PRED-01｜只在本人关注详情展示

前置条件：用户 A 已关注基金 F，用户 B 未关注 F；F 存在至少一条已发布多周期预测。

操作步骤：

1. 用户 A 从“我的关注”打开 `/watchlist/{fundCode}`。
2. 用户 B 请求相同关注详情与预测读取接口。
3. 用户 A 取消关注后刷新页面。

| 验收点 | 预期结果 |
| --- | --- |
| 用户 A | 能在关注详情看到预测区域和每个周期状态 |
| 用户 B | 返回 `403/WATCHLIST_REQUIRED`；Java 不向 Python 发起预测读取 |
| 取消关注后 | 不再读取完整预测，公共详情也不能绕过该限制 |
| 服务边界 | 浏览器只访问 Java，Python 请求无 `user_id` 或关注关系 |

## TC-PRED-02｜四个周期独立显示

前置条件：同一基金在同一数据截至日存在 5、10、20、40 个交易日的不同状态或已发布结果。

操作步骤：

1. 打开关注详情的“未来趋势预测”。
2. 比对四张卡的用户周期、精确交易日数、概率、状态和数据截至日。
3. 将其中一个周期的模型暂停或输入标为陈旧后刷新。

| 验收点 | 预期结果 |
| --- | --- |
| 周期完整性 | 显示约 7 天、15 天、1 个月、2 个月四张卡，不把 20 日结果复制成四张 |
| 已发布周期 | 只显示该周期自己的上涨/下跌概率、模型版本和数据截至日 |
| 不可用周期 | 只显示不可用原因，不影响其它已发布周期的只读结果 |
| 文字口径 | 自然语言周期和实际交易日数同时可见 |

## TC-PRED-03｜输入覆盖与数据缺口如实披露

前置条件：准备一条仅使用净值历史的已发布基线结果，以及一条使用净值、持仓板块、已授权事件和基准的综合结果。

操作步骤：

1. 分别打开两只基金的预测说明。
2. 检查输入分组、来源、数据截至日、披露/发布时间和缺口说明。
3. 对缺少持仓或没有可靠事件关联的基金，检查页面文案。

| 验收点 | 预期结果 |
| --- | --- |
| 净值基线 | 明确标识“未纳入持仓/板块、新闻公告”，不使用“综合预测”名称 |
| 综合预测 | 每类实际使用输入都有来源、日期和覆盖信息 |
| 缺失输入 | 明确说明未接入、陈旧或关联不足，不以空白或零值掩盖 |
| DeepSeek 解释 | 只能解释已发布结果，不能成为唯一概率依据 |

## TC-PRED-04｜披露截止时间与回测无未来信息

前置条件：准备含持仓披露日期、公告发布时间和未来标签的历史样本；其中包含一条评分日之后才公开的信息。

操作步骤：

1. 运行指定周期的特征构建与滚动回测。
2. 查看该评分日的输入覆盖和回测训练/验证/测试边界。
3. 将评分日之后公开的信息提前注入，验证任务拒绝或剔除。

| 验收点 | 预期结果 |
| --- | --- |
| 时间边界 | 每条输入的公开时间不晚于评分日 |
| 数据隔离 | 未来净值只用于对应标签，不进入同日特征 |
| 回测顺序 | 训练、验证、测试严格按时间推进 |
| 失败处理 | 时间字段缺失、冲突或未来泄漏时该周期不可发布 |

测试结果：

## TC-PRED-05｜回测与发布闸门

前置条件：同一基金类型的一个周期回测合格、另一个周期样本不足或未达到门槛。

操作步骤：

1. 管理员查看每个周期的回测指标和发布资格。
2. 尝试激活合格与不合格周期。
3. 用户刷新关注详情。

| 验收点 | 预期结果 |
| --- | --- |
| 合格周期 | 可被单独激活，用户可读其概率与回测摘要 |
| 不合格周期 | 不能激活，页面不显示概率 |
| 追溯 | 每张已发布卡可回查模型/特征版本、回测运行、样本和输入覆盖 |
| 暂停/回滚 | 停止生成新结果，历史保留只读且有明确状态 |

## TC-PRED-06｜数据不足、故障和非交易边界

前置条件：分别模拟来源未授权、输入陈旧、模型未发布、Python 不可用和已存在陈旧结果的情况。

操作步骤：

1. 从关注详情读取每种状态。
2. 检查网络请求、页面按钮、提醒内容和运行审计。

| 验收点 | 预期结果 |
| --- | --- |
| 无预测条件 | 显示“预测准备中”或具体缺口，不显示假概率或方向 |
| 服务故障 | 最多显示带缓存时间的陈旧已发布结果；无缓存则受控失败 |
| 页面与接口 | 不存在申购、赎回、买卖、自动定投、第三方账户授权或交易跳转 |
| 提醒 | 仅通知已发布的基金层面事实/预测变化，不生成个人操作或收益承诺 |
