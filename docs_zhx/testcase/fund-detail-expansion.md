## TC-01｜市场基础详情与关注后完整详情权限边界

前置条件：基金 `002112` 已有基础资料、至少一条净值和一条完整详情资料；用户 A 已关注该基金，用户 B 未关注。

操作步骤：

1. 用户 A、用户 B 分别请求 `GET /api/v1/funds/002112`。
2. 用户 A 请求 `GET /api/v1/watchlist/002112/detail`。
3. 用户 B 请求相同完整详情接口；用户 A 取消关注后再次请求。

| 验收点 | 预期结果 |
| --- | --- |
| 基础详情 | 两名已登录用户均可读，不出现任何用户关注状态 |
| 完整详情 | 仅用户 A 在有效关注期间获得完整资料 |
| 拒绝行为 | 用户 B 与取消关注后的用户 A 均收到 `403/WATCHLIST_REQUIRED` |
| 服务边界 | 浏览器只访问 Java，Python 内部接口不接受浏览器调用 |

测试结果：

- [x] 离线通过：Java 单测确认未关注时不会调用 Python，已关注时才返回完整详情；Python 内部接口只接受服务令牌且不返回用户态。
- [ ] 真实端到端待执行：用户 A/B、取消关注后的 403 响应待部署后验证。

## TC-02｜扩展基金资料同步幂等与缺失状态

前置条件：使用固定假 Tushare Provider 返回一只基金的基础资料、净值扩展、经理、规模和分红记录；其中一项可选字段为空。

操作步骤：

1. 执行一次扩展资料同步并记录新增/更新/跳过统计。
2. 使用相同输入重复执行。
3. 只修改一条经理、规模或分红记录后再次执行。
4. 打开完整详情，核对缺失的可选字段和各区块的数据日期/来源。

数据库验证：

```sql
SELECT fund_code, nav_date, source_id, unit_nav, accumulated_nav, accumulated_dividend,
       net_asset, total_net_asset, adjusted_nav
FROM fund_ai.nav_daily
WHERE fund_code = '002112'
ORDER BY nav_date DESC, source_id;
```

| 验收点 | 预期结果 |
| --- | --- |
| 重复同步 | 第二次不新增重复资料、规模或分红行 |
| 增量更新 | 仅内容哈希变化的记录更新 |
| 缺失字段 | 保持 `NULL`，页面显示明确缺失状态而不是零值 |
| 来源一致性 | 每个区块只显示同一记录的来源和数据日期 |

测试结果：

- [x] 离线通过：Tushare 客户端字段请求、跨基金/窗口拒绝、重复冲突拒绝和内容哈希规范化测试通过。
- [ ] 真实数据库待执行：迁移与实际基线同步后验证重复运行、更新与来源日期。

## TC-04｜历史净值区间解读

前置条件：目标基金在所选窗口至少有两条已同步单位净值；分别准备“端点累计净值完整”和“端点累计净值缺失”两组数据。

操作步骤：

1. 打开市场基础详情，依次切换近三月、近一年、近三年和成立以来。
2. 核对区间起止日期、最高/最低单位净值及日期、区间涨跌和计算依据。
3. 将窗口收窄到不足两条有效净值，或模拟历史接口失败。

| 验收点 | 预期结果 |
| --- | --- |
| 涨跌口径 | 两端累计净值均存在时使用累计净值，否则回退单位净值；不混用端点口径 |
| 极值与范围 | 最高/最低均是单位净值，显示对应日期；实际范围取已同步首尾点 |
| 数据不足 | 不显示 `0%`、虚假极值或空曲线，明确提示不足两条数据 |
| 外部副作用 | 切换日期范围只调用 Java 历史读接口，不创建同步任务、不访问 Tushare |

测试结果：

- [x] 离线通过：Vue lint、类型检查和生产构建通过；历史统计从当前窗口净值点派生。
